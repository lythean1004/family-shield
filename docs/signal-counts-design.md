# 원문 없는 일일 신호 집계 설계

2026-11-11 · 링크 후속 요청 작업 3. 이 문서를 먼저 작성한 뒤 시험·구현한다. 서버에는 접속하거나 반영하지 않는다.

## 현재 코드에서 남기는 것

- `skill/src/handler.js`: HTTP 시간·메서드·경로·상태·처리 시간, 고정 오류 문구. 판별별 신호·규칙·RDAP 지연 합계는 없다. 서버 실제 로그를 열지 않고 소스만 확인했다.
- `skill/src/results.js`: 동의에 따른 확인 기록 및 카카오 일회용 결과에 수준·신호·규칙·요약을 저장한다. 웹은 최대 24시간, 카카오 임시 결과는 10분. 가족/사용자와 연결되는 기록이라 일일 운영 통계 원본으로 재사용하지 않는다.
- 확인한 오류: `storedResult`가 R10까지만 허용하여 R11·R12를 버린다. DB는 규칙 문자열 배열이므로 마이그레이션 없이 필터를 R12까지 고치고 회귀 시험한다.
- RDAP 조회기는 결과를 24시간 메모리 캐시한다. `ok:true`에는 대상 제외·지원하지 않는 끝부분·등록일 없음도 포함되므로 네트워크 성공과 구분해야 한다.

## 최소 구현 범위

1. **KST 날짜별 메모리 합계**: 완료 판별 수, 오류 수, R1 빠른 경로 수, 알려진 신호 ID와 R1~R12의 발생 건수. 한 판별에서 같은 ID는 한 번만 센다. 빈 입력·인증 실패·결과 재조회는 세지 않는다. 재판별은 새 판별이다.
2. 평판·도메인 생성일 **조회 함수 호출 결과**는 각각 성공/실패/미호출 건수 및 지연 합계·최댓값·구간별 건수만 센다. 성공은 위협 없음/안전을 뜻하지 않는다. 평판 함수는 KISA 메모리 대조와 외부 조회를 합친 것이므로 네트워크 성공률로 해석하지 않는다.
3. RDAP는 별도 고정 숫자 카운터로 실제 요청 성공/실패, 캐시 사용, 미지원, 대상 없음, 등록일 확인/미확인을 센다. 404는 요청 성공이나 등록일 미확인이다. 최대 두 대상에서 일부 실패하면 함수는 실패, 개별 요청 숫자는 양쪽 모두 남는다. 주소·오류 원문을 담지 않는다.
4. 전체 판별 시간은 처리 시작~결과/오류까지 측정(대기열·응답 전송 제외). 조회 시간은 각 함수 실행 구간을 재어 AI와 병렬인 시간을 따로 본다. 요청별 시간은 보관하지 않고 건수·합계·최댓값·100/500/1500/3000ms 이하 및 초과 구간만 남긴다. 이 구간으로 정확한 p95를 주장하지 않는다.
5. 허용 ID·숫자만 새 객체에 복사한다. 원문·마스킹 문장·도메인·전화 HMAC·사용자/가족/세션·토큰·IP·AI 설명·자유 형식 오류·신호 조합별 행은 입력받아도 남기지 않는다. 상호 연결 가능한 요청 ID도 만들지 않는다.

## 보관·확인·실패 처리

- DB와 파일을 새로 만들지 않는다. 최근 7일 이내의 합계만 메모리에 유지하고 오래된 날은 제거한다. 프로세스별 집계라 재시작·강제 종료 시 아직 출력하지 않은 합계는 사라진다.
- 서버 진입점에서 1분 간격으로 날짜 변경을 확인한다. 지난 날짜 합계는 `signal_daily` JSON 한 줄로 기존 표준 출력에 한 번 보내며, 정상 종료 때 당일 분량도 출력한다. 당일 여러 번 재시작하면 그날의 여러 **분량**을 더한다. 로그에 식별자·개별 요청 시각을 추가하지 않는다. 기존 journald 보관 정책은 변경하지 않는다.
- 내부 `handler.signalMetrics.snapshot()`으로도 합계 복사본을 확인할 수 있으나 **HTTP 통계 경로는 만들지 않는다**. 테스트는 직접 호출한다. 배포 후 운영자는 기존 권한으로 서비스 로그의 `signal_daily` 행을 읽는다. 로그 보관 기간은 서버에서 확인하지 않았으므로 별도 운영 확인 사항이다.
- 집계 출력 실패는 판별 응답을 실패시키지 않는다. 새 날짜·종료 때 재시도할 수 있게 미출력 숫자를 유지하되 메모리 보관 상한을 따른다. 임의 필드·새 ID를 자동 추가하지 않아 키 수를 제한한다.
- 출력된 하루 빈도는 **발동 횟수**다. 놓침·오탐·피해 예방 성공률이나 실제 위험 여부를 증명하지 않는다. 사용자와 연결한 대조는 이 구현에 포함하지 않는다.

## 시험 계획

- 원문/도메인/식별자/오류 문자열 및 임의 신호를 넣어도 합계·로그에 남지 않음.
- 같은 ID 중복 제거, R11/R12 포함, 두 채널과 R1/오류/미호출 집계, 조회 예외에도 기존 판별 유지.
- KST 자정 경계·7일 보관·출력 중복 방지·출력 실패·정상 종료 분량.
- RDAP 실제 요청/캐시/미지원/대상 없음/404/부분 실패를 가짜 조회로 구분. 실제 외부 요청·DB 변경 없이 검증.

서버 적용은 운영자 승인 후 Claude Code 담당이다. 이번 구현에 마이그레이션은 필요하지 않다.

## 구현·검증 결과

- `skill/src/signal-metrics.js`와 두 채널 연결 구현. 서버 진입점에서 1분 간격의 지난 날짜 출력 및 SIGTERM/SIGINT 정상 종료 후 당일 분량 출력. 강제 종료 또는 30초 종료 상한 초과 시 미출력 숫자는 유실될 수 있다.
- 집계기는 기본으로 메모리만 사용하고, 운영 진입점에서만 표준 출력 함수를 넣는다. `handler.close()`는 출력 설정이 있으면 남은 숫자를 내보낸다. 날짜는 판별이 끝난 시각 기준이며 KST 자정을 넘긴 요청은 다음 날에 센다. R1 즉시 안내 시간은 0ms로 센다.
- RDAP `includeStats: true`는 스킬 서버에서만 켠다. 기존 코어 호출 반환 모양·판정은 유지한다. HTTP 404·등록일 없는 응답·지원 안 됨·오류·캐시에서 등록일을 못 얻으면 `date_unknown`이며, 별도 상태 건수로 이유를 구분한다.
- RDAP·집계·핸들러·결과 관련 **81개 시험 통과**. 여기에는 로컬 HTTP로 두 채널을 호출한 합계, 통계 경로 404, 종료 출력, 원문 배제 시험이 포함된다. PostgreSQL 통합 suite는 환경을 켜지 않아 실행하지 않았다. 기존 기록에서 이미 누락된 R11/R12는 복원하지 않는다.
- 서버 진입점 구문 검사 통과. Windows 로컬에서 테스트했으며 실제 Linux systemd 종료·journald 도착은 서버 반영 후 확인해야 한다. 외부 AI/RDAP 실호출 없이 가짜 응답으로 검사했다.
