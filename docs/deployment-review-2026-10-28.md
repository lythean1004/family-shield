# 2026-10-28 VM 반영 검토서

상태: 코드 구현·로컬 시험 완료, **사용자 서버 변경 확인 대기**. 실제 사용자 데이터는 사용하지 않는다(D26).

## 반영 내용과 순서

1. 현재 VM 커밋·서비스 상태 기록. GitHub main을 받고 고정 버전 의존성 설치 및 서버 단위 시험. 이 단계에는 재시작 없음.
2. 수정한 백업 서비스를 설치하고 한 번 실행. 기존 DB 백업 파일 생성·덤프 목록 검사. 만료 데이터 삭제가 실패하면 백업도 중단한다. 삭제 10분·백업 매일 03:30·7일 보관 일정은 유지.
3. DB 마이그레이션 11~15 적용(로그인, 만료 처리, 확인 요청, 쓰기 권한, 웹 푸시). 기존 적용 SQL은 변경하지 않음. 각 파일 단위 트랜잭션. DB 권한 시험 38개 실행.
4. `15-configure-push.sh`로 VAPID만 추가. 기존 AI·DB 값 보존, 기존 VAPID가 있으면 재사용. 원본 환경 파일을 `.before-push`로 보관, 권한 600 유지. AI 키는 12/11까지 그대로 둔다.
5. Nginx 설정 백업 후 저장소 설정 설치. Supabase CSP 주소 제거, `nginx -t` 성공 시에만 reload. DB·3000 포트·SSH·sudoers는 변경하지 않음.
6. 스킬 서비스 재시작·상태 및 HTTP 확인. 웹 테스트·PWA 빌드 후 기존 배포 스크립트로 교체(`web.old` 보관).
7. HTTPS에서 세션·원문 없는 결과 토큰·로그인 없는 API 차단 확인. 운영자 시험 코드 파일로 합성 계정 왕복 점검. 실제 휴대폰 웹 푸시는 사용자가 알림을 눌러 확인.
8. AI 평가를 Gemini 3초·3.5초 각각 200건×3회 실행. 키는 VM 밖으로 복사하지 않고 원문 없는 측정 결과만 회수. 운영 AI 시간 제한은 측정만으로 바꾸지 않음.

## 실행 명령

저장소를 받은 뒤 VM에서 순서대로 실행한다. 이 문서만으로 서버 변경 승인을 대신하지 않는다.

```bash
bash /srv/family-shield/repo/deploy/remote/14-db-timers.sh
bash /srv/family-shield/repo/deploy/remote/12-migrate.sh
bash /srv/family-shield/repo/deploy/remote/13-db-test.sh
bash /srv/family-shield/repo/deploy/remote/15-configure-push.sh
```

Nginx는 기존 설정 백업·설치·검사·reload, 스킬은 테스트 후 restart, 웹은 `deploy/deploy-web.ps1`. 상세는 `docs/operations.md`.

## 검증 범위와 제한

- 자동 시험 **324/324**, 로컬 PG16 권한 시험 **38/38**, PWA 빌드 통과. 통합 시험은 코드 만료·동시 사용, 가족 격리, 세션 취소, 동의·별도 기록 동의, 서명 위조, 응답 중복·철회·가족 제외, 토큰 재생성, 푸시 구독·시험 클릭 권한을 포함한다.
- D39에 따라 이번 시연의 알림은 수동 확인 요청만. 동의 ① 문구 v2 적용. ③ 동의자는 웹 판별 기록을 최대 24시간 보관하고, 미동의자는 가족 요청 시 D38 별도 동의를 받는다. 실제 HTTP 분석 → 맥락 변경 → 확인 요청에서 중복 기록 없이 연결되는 것을 검사했다.
- 새 백업 스크립트를 로컬 PG16에서 실행해 별도 DB에 복원 성공. 복원 DB에서 부트스트랩 포함 마이그레이션 기록 16개 확인. VM의 실제 서비스 실행 검증은 배포 단계에서 한다.
- 부모님·보호자 별도 브라우저에서 합성 요청 왕복, 390px 화면 확인. 실제 휴대폰 알림 수신을 뜻하지 않는다.
- 웹·서버 실행 코드·CSP의 Supabase 검색 0건. 운영 배포 확인 후 프로젝트 삭제는 사용자가 대시보드에서 직접 수행.
- 놓침률은 목표 5% 미달. 코드 전후 AI 미사용 평가는 89.9% → 74.7%, 오경보 0%. AI 사용 조건의 최신 성능은 아직 미측정.
- 전화 인증·실기기 SC1 리허설은 중간과제 이후. 근거 카드 원문 검수·법률 검토·NCP ACG는 별도 남은 일.

## 실패 시

시험 실패 시 다음 단계로 진행하지 않는다. 웹은 `web.old`, Nginx·환경 설정은 변경 직전 백업으로 되돌린다. 스키마는 추가 방식이므로 임의 down SQL을 실행하지 않는다. 데이터 복원은 백업을 별도 DB에 확인하고 사용자와 영향 범위를 확인한 뒤 수행한다. 서비스는 확인된 이전 커밋으로 복원하며 재시작 전에 시험한다.
