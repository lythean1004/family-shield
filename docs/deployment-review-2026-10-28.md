## 반영 내용과 순서

1. 현재 VM 커밋·서비스 상태 기록. GitHub main을 받고 고정 버전 의존성 설치 및 서버 단위 시험. 이 단계에는 재시작 없음.
2. 수정한 백업 서비스를 설치하고 한 번 실행. 기존 DB 백업 파일 생성·덤프 목록 검사. 만료 데이터 삭제가 실패하면 백업도 중단한다. 삭제 10분·백업 매일 03:30·7일 보관 일정은 유지.
3. DB 마이그레이션 11~15 적용(로그인, 만료 처리, 확인 요청, 쓰기 권한, 웹 푸시). 기존 적용 SQL은 변경하지 않음. 각 파일 단위 트랜잭션. DB 권한 시험 38개 실행.
4. `15-configure-push.sh`로 VAPID만 추가. 기존 AI·DB 값 보존, 기존 VAPID가 있으면 재사용. 원본 환경 파일을 `.before-push`로 보관, 권한 600 유지. AI 키는 12/11까지 그대로 둔다.
5. Nginx 설정 백업 후 저장소 설정 설치. Supabase CSP 주소 제거, `nginx -t` 성공 시에만 reload. DB·3000 포트·SSH·sudoers는 변경하지 않음.
6. 스킬 서비스 재시작·상태 및 HTTP 확인. 웹 테스트·PWA 빌드 후 기존 배포 스크립트로 교체(`web.old` 보관).
7. HTTPS에서 세션·원문 없는 결과 토큰·로그인 없는 API 차단 확인. 운영자 시험 코드 파일로 합성 계정 왕복 점검. 실제 휴대폰 웹 푸시는 사용자가 알림을 눌러 확인.
8. AI 평가를 Gemini 3초·3.5초 각각 200건×3회 실행. 키는 VM 밖으로 복사하지 않고 원문 없는 측정 결과만 회수. 운영 AI 시간 제한은 측정만으로 바꾸지 않음.
