# 제3자(문자 발신자) 정보 처리 검토서 — 초안 (전문가 확인용)

작성일: 2026-11-11 · 상태: **초안. 법적 판단 아님.** 개인정보 전문 변호사 또는 개인정보보호위원회 법령 해석 창구의 확인을 받기 위한 자료다(D43 운영 승인 서류 ②).
기준: 2026-11-11 운영 코드(서버 `055d90c`~`8e6ae39`). 사실은 코드에서 확인한 것만 적고, 판단이 필요한 곳은 **[확인 필요]**로 표시한다.

## 0. 이 문서가 다루는 것

부모님(이용자)이 받은 문자를 붙여 넣으면 그 안에 **문자를 보낸 사람(제3자)**의 정보가 들어 있다. 사기범일 수도 있고, 번호를 도용당한 사람, 진짜 가족·택배사·병원일 수도 있다. 이 사람들은 우리 서비스의 이용자가 아니고 동의하지 않았다.

멘토 1차 의견(요약): 제15조 1항 6호(정당한 이익)를 검토할 여지는 있으나 명백한 우선을 단정할 수 없다. 메모리 처리도 ‘처리’다. **국내 처리 근거와 국외 이전 근거는 따로** 필요하다. 건강정보 등 민감정보는 별도 대책이 필요하다.

이 문서는 ① 국내 처리, ② 국외 이전(해외 AI), ③ 민감정보를 나눠, 목적 → 필요성 → 덜 침해적인 대안 → 정보주체 불이익 → 보호조치 순으로 정리한다.

## 1. 처리하는 제3자 정보와 흐름 (코드 기준)

| 단계 | 제3자 정보 | 처리 방식 | 남는 것 |
|---|---|---|---|
| 입력 | 문자 원문(발신자 이름·번호·계좌·주소·사연 등이 섞일 수 있음) | 카카오 → 우리 서버 또는 웹 → 우리 서버. 최대 2,000자 | 원문은 저장·기록하지 않음(로그 포함) |
| 가리기 | 전화번호→`[번호]`, 계좌→`[계좌]`, 카드→`[카드]`, 주민번호→`[주민번호]`, 이메일→`[이메일]`, URL→`[링크]`, 등록된 가족 이름→`[가족이름]` | 서버 메모리 | 전화번호는 비밀키 HMAC 값만(가족 확인용) |
| 코드 신호 | 원문에서 요구 표현(송금·개인정보·앱 설치 등)과 링크 도메인 | 서버 메모리 | 신호 ID만 |
| AI | **가린 문장** | 중계 서버(aitestbed.kr) → Google Gemini / Anthropic Claude(국외), 3초(카카오)·8초(웹) | 중계·AI 쪽 보관은 **[확인 필요: 운영사 서면 답변 대기]** |
| 링크 확인 | 링크 도메인 | ⓐ KISA 목록: 서버 안 대조 ⓑ Google Safe Browsing: 도메인 해시 앞 4바이트(국외) ⓒ 등록일: 등록 도메인 이름을 등록 기관 RDAP에(국내·국외, 문자당 최대 2개) | ⓒ 결과는 서버 메모리 24시간 |
| 판정 | — | 규칙 코드 | 판정·신호 ID·번호 HMAC·끝 4자리(입력 시)만, 24시간 뒤 삭제(+삭제 주기 최대 10분, 백업 최대 7일) |
| 가족 확인 | 정해진 문장 틀 요약 + 사칭된 관계 + 끝 4자리(입력 시) | 부모님이 직접 요청할 때만 연결 가족에게 | 요청 기록 24시간 |

발신자의 실명·전체 번호·문장은 가족에게 가지 않는다. 판정 결과는 **‘안전’을 말하지 않는다.**

## 2. 국내 처리: 정당한 이익(제15조 1항 6호) 검토

### 2-1. 목적의 정당성
- 고령 부모님이 받은 문자가 사기(가족·기관 사칭, 악성 링크)인지 행동 전에 알려 주어 금전 피해를 줄이는 것.
- 결과는 판단 보조이며 송금 차단·신고 대행·차단 같은 자동 조치를 하지 않는다.
- 광고·판매·프로파일링 목적 없음. 발신자를 식별하거나 추적하지 않는다.

### 2-2. 필요성 (왜 제3자 정보를 보지 않고는 안 되는가)
- 사기 여부는 **문장 내용**(요구·재촉·사칭 표현)과 **링크·번호의 형태**로만 판단할 수 있다.
- 발신자 정보 자체(누구인지)는 판단에 필요하지 않아 가리거나 해시로 바꾼다. 남기는 것은 같은 번호인지 비교하기 위한 HMAC과, 부모님이 입력한 경우의 끝 4자리뿐이다.
- [확인 필요] 끝 4자리 보관이 꼭 필요한가: 가족 확인에서 “이 번호에서 왔는지”를 묻는 데 쓴다. 입력은 선택이다.

### 2-3. 덜 침해적인 대안과 채택 여부
| 대안 | 채택 | 이유 |
|---|---|---|
| 원문을 저장하지 않음 | 채택 | 메모리 처리 후 버림, 로그에도 없음 |
| 서버로 보내기 전에 기기에서 가리기 | 미채택(검토) | 카카오 입구는 기기 쪽 코드를 실행할 수 없음. 웹 입구는 가능하나 아직 서버에서 가림. **[검토 과제]** 웹에서는 기기에서 먼저 가리기 |
| AI 없이 규칙만 | 부분 채택 | AI 실패·시간 초과 때는 규칙만으로 판정. 규칙만으로는 놓침률이 높아(평가 200건, AI 없음 44.3%) AI를 완전히 뺄 수 없음 |
| 이름까지 모두 가리기 | 미채택 | 등록되지 않은 이름은 자동으로 구분하기 어렵다. **[검토 과제]** 사람 이름 추정 가림 |
| 링크 전체 주소 조회 | 미채택 | 도메인만, Safe Browsing은 해시 앞부분만. 링크 접속·단축 URL 펼치기 금지(D11) |

### 2-4. 정보주체(발신자)가 입을 수 있는 불이익
- 정상 발신자(가족·택배사·병원)의 문자가 ‘위험’으로 판정되어 부모님이 연락을 의심할 수 있다 → 결과는 단정하지 않고 공식 번호로 확인하라고 안내, 한계 문구 표시.
- 번호를 도용당한 사람의 번호가 사기 문자에 들어 있다 → 번호는 가리고 HMAC만, 24시간 뒤 삭제, 가족에게 전체 번호를 보내지 않음.
- 문장이 국외 AI에 간다 → 3장(국외 이전)에서 별도 검토.
- 발신자는 처리 사실을 알기 어렵다 → [확인 필요] 처리방침 공개로 충분한지(제20조 정보 출처 고지 대상 여부).

### 2-5. 보호조치 (코드에 있는 것)
- 원문 미저장·미기록, 가리기, 전화번호 HMAC(비밀키는 서버 권한 600 파일), 판정 기록 24시간 삭제, DB는 국내 서버 127.0.0.1만, 행 단위 접근 권한(RLS), 공개 데모는 고정 콘텐츠.
- 가족에게 가는 내용은 정해진 문장 틀(AI 문장 아님), 부모님이 직접 요청할 때만(D39).
- [보완 필요] 백업 7일 동안 24시간 지난 기록이 백업에 남는 점을 고지와 일치시키기(작업 ⑧).

### 2-6. 잠정 결론 (전문가 확인 전)
목적은 정당하고, 판단에 필요한 최소 내용만 다루며, 저장하지 않는 설계라 정당한 이익을 주장할 근거는 있다. 다만 **정상 발신자 권리와의 비교, 고지 방법, 끝 4자리 보관 필요성**은 전문가 판단이 필요하다.

## 3. 국외 이전 (가린 문장 → 해외 AI) 검토

- 국내 처리의 정당한 이익과 **별도로** 국외 이전 근거가 필요하다(멘토 의견, 제28조의8).
- 이용자(부모님) 정보에 대해서는 동의 또는 계약 이행상 위탁 근거를 검토할 수 있으나, **문자 속 제3자 정보는 부모님 동의나 계약으로 대신할 수 없다.**
- 필요한 사실: 이전받는 법인, 국가, 시기·방법, 항목, 보유 기간, 거부 방법 → **[확인 필요] 운영사 서면 답변(docs/operator-ai-relay-inquiry.md) 대기.**
- 줄이는 방법(검토 과제): ① 가리기 범위 확대(사람 이름 추정) ② 해외 AI로 보내는 것을 부모님이 끌 수 있게(끄면 규칙만으로 판정) ③ 국내 처리 모델 검토.
- [확인 필요] 가린 문장이 개인정보가 아닌 수준(제58조의2)에 이를 수 있는지, 이를 판단하는 기준.

## 4. 민감정보 (병원·건강 관련 문자)

- 병원 예약·검사 결과 안내 문자에는 건강정보(제23조 민감정보)가 들어 있을 수 있다. 정당한 이익만으로 해결되지 않는다(멘토 의견).
- 현재 코드는 건강정보를 따로 구분하지 않는다. **[작업 ⑦]** 처리 방침 결정 필요: 예) 진료·검사·질병 표현이 있으면 AI로 보내지 않고 규칙만 판정 + 안내.

## 5. 전문가에게 물을 질문

1. 2장의 사정으로 제15조 1항 6호 정당한 이익이 정보주체 권리보다 명백히 우선한다고 볼 수 있는가? 부족하다면 무엇을 더 해야 하는가?
2. 발신자에게 처리 사실을 알리는 방법으로 처리방침 공개가 충분한가(제20조)?
3. 가린 문장의 해외 AI 처리: 제3자 정보에 쓸 수 있는 국외 이전 근거가 있는가, 없다면 해외 AI 처리를 끄는 것 외에 방법이 있는가?
4. 끝 4자리·번호 HMAC 보관(24시간)의 필요성 설명이 충분한가?
5. 건강정보가 섞인 문자는 처리하지 않는 것(규칙만 판정 또는 거절)이 필요한가?
