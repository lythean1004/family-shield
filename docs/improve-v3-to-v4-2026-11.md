# 문자 v3 개발과 독립 v4 검증

2026-11-27 운영자가 v3를 개발 자료로 전환하고 별도 작성자가 새 v4를 만드는 방식을 승인했다. 위험 놓침률과 위험 오경보율의 목표는 각각 10% 미만이다. 기준 코드는 `c50377d`다. 같은 커밋이 v3를 처음 보았을 때의 [독립 평가 결과](improve-sub10-2026-11.md#고정-후보의-독립-평가-결과)는 그대로 보존한다.

## 개발과 채점 기준

- v3에서 기준판의 놓침 36/53건과 위험 오경보 0/67건을 재현했다. 가족·지인 13건, 기관 7건, 기타 수법 10건, 경계 사례 6건을 놓쳤다. 이후의 v3 측정값은 개발 성능이다.
- v3의 원문과 사례별 분석은 로컬에서만 사용한다. v2와 기존 회귀 세트 230건도 사례별로 대조한다. 새 위험 오경보 또는 판정 하락이 생긴 후보는 적용 전에 수정하거나 폐기한다.
- 별도 작성자는 개발 코드·기존 평가 문장·판정 결과를 열람하지 않고, 한국어 합성 v4 문장과 정답을 작성한다. 합성 자료에는 실제 연락처와 작동하는 의심 주소를 쓰지 않는다. 실제 가족이 받은 문자의 운영 성능은 별도 측정이 필요하다.
- 독립 v4의 분모와 판정 경로는 이전 독립 평가와 같다. 개발 v2·v3에서 두 비율이 모두 10% 미만이고 회귀 검사를 통과한 코드 커밋을 고정한 뒤, 로컬 [집계기](../eval/score-aggregate.mjs)로 v4를 한 번 채점한다. 사례나 예측 목록은 공개하지 않는다. 두 오류율의 분모는 각각 `gold.level_rule`이 위험인 건수와 그 밖의 건수다.

## 28라운드에서 남은 오차

코드 기준 v2 놓침은 3/46건(6.5%), v3 놓침은 6/53건(11.3%)이었다. 위험 오경보는 각각 0/74건, 0/67건이었다. 두 개발 자료에서는 사람 기대 등급과 규칙 기대 등급이 각 행에서 일치했다. v3의 남은 놓침 중 4건은 정답에 표기한 신호를 모두 추가해도 현재 규칙으로 위험에 이르지 않았다. 일반 배송지 입력이나 계좌 소유자 이름만 보고 위험으로 올리면 정상 안내와 구별하기 어렵다.

16라운드와 28라운드 사이에 v3 위험 30건, v2 위험 1건을 추가로 판정했다. 470건 전체에서 낮아진 판정, 새 위험 오경보, 정상 기대 등급이 확인필요에서 주의로 올라간 사례는 모두 0건이었다. 기존 200건의 놓침은 29/79, 보강 자료는 2/4, 기존 개발 자료는 2/9였다. 운영 서버와 외부 AI를 사용하지 않은 결과다.

16라운드에 썼던 통계적 신호 추정 방법과 임곗값 선택 절차도 다시 시험했다. v2에서 학습해 v3에 적용해도, 반대 방향으로 적용해도 놓침은 그대로였고 위험 오경보가 각각 1건 늘었다. 개발 자료 240건으로 학습한 뒤 기존 200건에 적용하면 놓침은 29/79에서 27/79가 되었지만 두 개발 판본 간 오경보 기준을 넘겨 적용하지 않았다. [신호 추정 방법](improve-sub10-2026-11.md#발신자와-요청-행동을-따로-추정한-실험)

## 독립 v4 평가 결과

**위험 놓침률 10% 미만 목표를 충족하지 못했다.** [29라운드 후보 8049896](https://github.com/lythean1004/family-shield/commit/8049896816b72458c1b0653c5acadd85e0fc8077)을 푸시한 뒤 원격과 로컬의 커밋, 작업 파일의 일치를 확인했다. 집계기가 작성자 지문과 같은 v4 파일을 한 번 읽어 전체 건수만 출력했다. 외부 AI와 도메인 조회를 사용하지 않았다.

## 개발 자료에서 신호와 정답을 다시 대조한 결과

29라운드 코드에서 v2와 v3를 대조했다. ‘달라고’, ‘요구를 받았다’, ‘문자를 받았다’ 등 미리 정한 전달·인용 표현에 해당하는 입력은 240건 중 0건이었다. ‘입니다·습니다·하십시오·바랍니다·해주세요·하세요’를 포함한 v3 위험 30건 중 4건을 놓쳤고, 그 밖의 위험 23건 중 1건을 놓쳤다. 이 분류는 일부 표현의 유무만 측정한다. 예전에 보관용으로 정한 제3자 사건 요약은 다시 측정하지 않았다. [문자 본문 평가의 범위](codex-request-message-eval.md)

실제 코드 신호에 정답에 표시된 신호를 모두 보태고, 각각의 코드·AI 출처를 유지해 판정했다. 이는 신호를 완벽히 보충할 수 있다고 가정한 진단이다. v2는 놓침이 3건에서 0건으로 줄고 오경보는 0건이었다. v3는 놓침이 5건에서 3건으로 줄었지만 위험 오경보가 0건에서 1건으로 늘었다. 최초 정답 주석만 규칙 엔진에 넣으면 v3의 34/120건에서 기록된 등급과 달랐다. 주석 누락이나 작성 시점의 판정 기준도 확인할 필요가 있다.

단어와 2~4글자 조각에서 발신자·요구 행동 신호를 추정하는 두 방법을 같은 조건으로 비교했다. 하나는 신호별 평균 벡터를 쓰는 방법이고, 다른 하나는 릿지 회귀(규제 계수 1)다. 각 학습 자료 안에서만 4분할로 임곗값을 골랐다. 두 방법 모두 v2로 학습해 v3를 판정했을 때 놓침은 5/53건 그대로였고 오경보는 1/67건이었다. 반대 방향도 놓침 3/46건 그대로에 오경보 1/74건이었다. 두 판본 모두로 학습한 릿지 회귀는 기존 평가 200건에서 놓침을 29/79건에서 27/79건으로 줄였으나 새 위험 오경보 2/121건이 생겼다. 새 위험 오경보를 0건으로 유지해야 한다는 채택 기준에 따라 두 방법 모두 보류했다.
