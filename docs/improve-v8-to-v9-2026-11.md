# 문자 v8 개발과 독립 v9 검증

v8의 [최초 독립 집계](improve-v7-to-v8-2026-11.md)에서 후보 `e12ee16`은 규칙 기준 위험 42건 중 31건을 놓쳤고 위험 오경보는 0/78건이었다. 작성자 기대 기준은 놓침 32/41·위험 오경보 2/79였다. 최초 집계와 고정된 두 정답을 보존하고 v8을 개발에 편입했다.

위험을 놓친 31건은 가족 7, 기관 11, 기타 12, 경계 1건이었다. 수신자가 자기 말로 보고한 입력에서는 18/27건, 문서 조각에서는 13/13건을 놓쳤다. 직접 수신 문구 형식의 위험 2건은 둘 다 검출됐지만, 두 건으로 실제 문자 성능을 추정할 수는 없다.

다음 후보는 기존 코드와 과거 평가 결과를 제공받지 않은 작성자 두 명이 별도로 만든 v9로 점검한다. 원점수를 보기 전 고정한 120건의 규칙 기준 분모는 위험 38·그 외 82건이다. 두 지표가 각각 10% 미만이려면 놓침이 3건 이하이고 오경보가 8건 이하여야 한다. 작성자 기대 분모는 34·86건이다. 파일의 SHA-256은 `dfd144602efc17b82f71a7d33c2a9da183291a10d585ab84f194e8f3a5834fee`다. 모든 검증은 로컬에서 수행한다.

## 제품 규칙을 기준으로 다시 읽은 v8

독립 검수자는 코드의 예측과 기존 정답을 가리고 본문과 실제 부모 입력을 먼저 읽었다. 이후 고정된 정답과 대조했을 때 규칙상 위험 42건 중 30건은 제품의 위험 조건이 명확했고, 5건은 적용 범위에 다른 해석이 가능했으며, 7건은 필요한 정보가 빠져 있었다. 작성자 기대 위험 41건으로는 각각 28건·5건·8건이었다.

규칙 정답 중 근거가 빠진 7건에는 취소나 회신에 쓸 번호를 공식 창구와 구별할 수 없는 4건, 입력할 금융 비밀의 종류 또는 실제 접수 양식의 목적지를 확인할 수 없는 3건이 있었다. 이 7건만으로 위험 분모의 16.7%다. 검수자 한 명의 재판독이므로 해석이 다른 건도 모두 원래 정답과 분모에 남겼다. 전체 개발 점수와 첫 독립 점수에도 같은 분모를 사용한다.

다음 검증의 편의를 위해 v10도 v9 첫 집계 전에 다른 작성자 두 명이 봉인했다. 파일 SHA-256은 `1bc599df40e006033b537c3636f90190b11a6a312c263ac980d8d4b38d929c6f`다. 동일한 그룹·형식 구성의 합성 120건에서 규칙 기준 위험 45·그 외 75건, 작성자 기대 기준 위험 44·그 외 76건이다.

73라운드 후보는 v8 규칙 정답에서 위험 놓침 12/42(28.6%)·위험 오경보 0/78, 작성자 기대에서는 13/41(31.7%)·2/79(2.5%)였다. 재판독과 교차하면 위험 놓침 12건은 근거 명확 3/30, 모호 2/5, 필수 근거 부족 7/7이다. 명확으로 본 3건에 대해서도 분야별 검수에서는 해석이 달랐다. 상품권을 언급했지만 후속 지시의 대상은 생략된 경우, 상담 인계용으로 가린 주소와 실제 첨부를 연결할 수 없는 경우, 주변 사람과 물리적으로 떨어지라는 요구에 연락이나 도움을 차단하는 조건이 없는 경우였다. 세 건을 위험으로 승격하지 않고 원점수에 포함했다.

당시 보지 않은 문체에 개선이 옮겨 가는지도 확인했다. 각 커밋의 코드와 근거 카드를 고정해 이미 개발용이 된 세 판본을 다시 계산했다.

AI를 끈 판정과 가짜 실패 응답을 준 판정은 1,070건 모두 같았고, 기존의 건강정보 입력 26건에서 외부 호출을 생략했다. 코어 1,669개, 스킬 97개, 웹 174개, 평가기 19개 시험을 통과했다. 로컬 Tranco 100만의 사칭 경고는 4건·KISA 일치는 0건, 한국 도메인 4,343개는 두 경고 모두 0건이었다.
