# 가족방패 결과보고서 (틀·초안)

> 상태: **틀과 확정된 내용만 채운 초안(2026-11-28).** `[12/10 채움]` 칸은 사용성 시험 집계 뒤 채운다. 전문가 검토 전이며 ‘검수 완료’라고 쓰지 않는다. 피해 감소 효과는 주장하지 않는다. 메모: [결과보고서에 넣을 것](final-report-notes.md).
> 사무국 양식이 오면 이 순서를 양식에 맞춰 옮긴다.

## 1. 과제 개요

- 과제: 가족방패 — 부모님이 받은 의심 메시지를 AI가 쉬운 말로 짚어 주고 지금 할 행동을 안내하며, 위험할 땐 가족에게 바로 알리는 사기 예방 웹서비스(2026 모두의 AI 실험실, 접수번호 AI-2026-000053)
- 대상: 의심 문자를 받은 부모님(어르신)과, 부모님이 동의해 연결한 가족
- 목표 단계: 프로토타입(부모님이 실제로 써 볼 수 있는 수준)
- 기간: 2026-10 ~ 2026-12-11(결과물 제출). 서비스 운영은 12월 말까지 예정(D60·D61)

## 3. 신청서 대비 바뀐 점과 이유

| 신청서 | 실제 | 이유 |
|---|---|---|
| 단축 URL을 펼쳐 링크 위험도 조회 | 펼치지 않음. 도메인만 평판 조회(KISA 목록·Google Safe Browsing 해시 앞부분), 단축 링크는 그 자체를 신호로 | 링크 접속은 사용자 대신 피싱 서버에 닿는 행동이라 금지(D11) |
| 이미지 인식 AI가 캡처 속 글을 읽음 | 이번 결과물은 **붙여넣기만**. 캡처는 기기 안 글자 인식 후 실패 시에만 동의받아 AI로(D24)라는 설계까지 | 이미지를 그대로 보내면 번호·계좌를 가릴 수 없음. 법률 검토 전 구현 금지 |
| 둘 중 하나라도 위험이면 위험 | 위험 단계는 **규칙 코드만** 정함. AI는 신호 찾기·설명 문장만 | 판정을 설명할 수 있고 같은 입력에 같은 결과(제품 원칙) |
| ‘특이점 없음’ 단계 | ‘확인 필요’ | ‘안전’으로 읽히는 판정을 내지 않음(D13) |
| 실제 받은 문자로 가족 실사용 | **합성 문자 시나리오**로 사용성 시험(D43) | 실제 문자 처리 전 운영 승인 서류 4가지 필요(멘토) |
| 참여 가족의 정상 문자로 오경보 검증 | 합성 정상 문자로 대체 | 위와 같음 |
| 웹앱 또는 챗봇 | 부모님은 카카오 채널, 설정·가족·음성은 웹(D27) | 부모님이 새 앱을 깔지 않도록 |

## 4. 작동 방식

근거 → 규칙 → 생성 → 검증 → 대체.
1. 근거: 공식 번호·주소·절차는 근거 카드(출처·확인일 포함)에서만.
2. 규칙: 코드가 신호를 찾고 위험 단계를 정한다(R1~R19).
3. 생성: AI(카카오 `gemini-3.1-flash-lite`, 웹 `claude-sonnet-5-5`, 실험실 중계)는 해외 AI 동의자만, 번호·계좌 등을 가린 문장으로 신호와 설명 문장만 만든다.
4. 검증: 정형 JSON, 허용 신호·근거 ID를 코드로 검사.
5. 대체: 실패·시간 초과·건강정보·비동의 시 고정 문장. AI가 만든 설명에는 “AI가 만든 문장”이라고 표시(인공지능기본법 제31조②, D65).

## 7. 개인정보와 안전

- 문자 원문은 DB·로그 어디에도 저장하지 않는다. 판별 기록은 신호·단계·규칙과 AI 사용 상태만, 24시간(카카오 경유 10분) 뒤 삭제.
- 해외 AI는 동의한 사용자만(웹 동의 v5 + 이해 확인, 카카오 D59). 국외 이전은 확인되지 않은 칸을 가장 넓게(미국 등·최대 2년·학습 가능) 적었다. 철회: 웹 [내 설정], 카카오 ‘AI 끄기’(비슷한 말도 인식, D68).
- 건강 관련 문자는 사기 신호가 없으면 AI로 보내지 않고, 있으면 건강 단어를 한 번 더 가린다.
- 결과 화면마다 의미와 한계 문구. ‘안전’ 판정 없음.
- 공개 데모는 고정 콘텐츠, AI 호출은 참여 코드와 횟수 제한 뒤.
- 운영 종료 때 계정·동의·확인 기록·백업 파기([종료 계획](shutdown-plan.md)).

## 8. 한계와 알려진 빈틈

- 놓침률 목표 미달(5장). 비동의 사용자는 규칙만이라 더 많이 놓친다.
- 규칙의 기관 목록에 공단 이름(건강보험·국민연금)이 없다(D62). 링크 세트의 선입금·주민번호 입력·‘폰 고장 새 번호’ 표현을 규칙이 낮게 본다.
- AI 제공사의 보관 기간·학습 이용·처리 국가를 서면으로 확인하지 못했다(사무국·중계 업체 미회신).
- 인공지능기본법·개인정보 처리 문구는 전문가 검토 전이다([대조표](ai-basic-act-31-check.md)).
- 캡처 입력(글자 인식)은 구현하지 않았다.
- 시험은 합성 문자로만 했다. 실제 문자에서의 성능·사용성은 확인하지 않았다.
