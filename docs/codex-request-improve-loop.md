# Codex 요청서: 놓침·오경보 반복 개선 (코드 신호, 라운드 방식)

작성일: 2026-11-27 · 작성: Claude Code · 요청자: 프로젝트 운영자
시작 커밋: `fb6cd58` 이후 최신 `main`

## 목적

AI가 시간 초과·실패해도 사기 문자를 잡도록 **코드 신호**를 늘린다. 한 번에 다 고치지 않고 **라운드를 반복**한다. 한 라운드는 놓친 사례 분석 → 일반 표현 1~2개 추가(시험 먼저) → 오경보 확인 → 커밋 순서다. 멈출 조건(4절)에 닿으면 끝낸다.

현재(규칙만, AI 없음, `eval/results/2026-11-27-messages-v2-noai.jsonl`): 위험 놓침 35/46(76.1%), 오경보 0/74.

## 0. 지킬 것

- `docs/codex-request-next-dev.md` 0절 그대로. 서버 접속·배포·재시작 금지(로컬과 GitHub까지만), `.env`·`private/`·`data/` 원본은 열지 않는다.
- 실제 피싱 주소·번호·계좌를 저장소에 남기지 않는다. 시험 문장은 지어낸 것만 쓰고, 번호는 `010-0000-XXXX`, 링크는 `.invalid`로 쓴다.
- 판정은 규칙 코드가 한다. ‘안전’ 판정을 만들지 않는다.
- 사실(기관·회사 이름, 공식 번호, 공식 주소)은 근거 카드(`content/evidence/`)에서만 가져온다.
- **열지 말 것:** `eval/messages-2026-11-v3*`, `eval/holdout-private/`. 최종 측정용 세트라 보면 측정이 의미를 잃는다. 있어도 열지 않는다.

## 1. 쓰는 자료

| 자료 | 용도 |
|---|---|
| `eval/messages-2026-11-v2.jsonl` (120) | **개발 세트.** 놓친 사례를 보고 고쳐도 된다 |
| `eval/test.jsonl` (200), `eval/supplement.jsonl`, `eval/dev.jsonl` | 회귀 확인. 판정이 **낮아지거나** 정상이 ‘위험’이 되면 안 된다 |

| 서버 AI 결과 `eval/results/2026-11-27-*-messages-2026-11-v2-*` (Claude Code가 올리면) | AI가 자주 놓치는 신호 참고 |

## 2. 라운드 하나의 순서

1. `node eval/run.mjs --no-ai --data eval/messages-2026-11-v2.jsonl --out eval/results/loop/r<N>-v2.jsonl`로 지금 상태를 잰다.
2. 놓친 위험 사례를 원인별로 묶는다(코드 표현 없음 / 규칙 조합 없음 / AI만 알 수 있음 / 정답 애매).
3. **가장 많은 묶음 하나**를 골라 일반 표현을 1~2개 만든다.
   - 표현은 **수법**을 나타내야 한다(예: 가족 호칭 + 폰 고장·임시폰·친구폰). 한 사례의 문장을 그대로 옮기지 않는다.
   - 공개 예방 자료(금감원·경찰청·KISA)에 같은 수법 설명이 있으면 출처를 주석에 적는다.
   - 같은 표현이 정상 문장에서 나올 수 있으면 제외 조건(경고문·과거 이야기·금지 어미)을 함께 넣는다. 기존 `NOT_PROHIBITION` 방식을 따른다.
4. **시험 먼저:** `packages/core/test/`에 잡아야 할 문장 3개 이상과 잡으면 안 되는 정상 문장 3개 이상을 쓴다. v2 문장을 그대로 복사하지 말고 다르게 쓴다. 실패를 확인한 뒤 구현한다.
5. 측정과 비교: v2, test, supplement, dev를 규칙만으로 다시 돌려 라운드 전과 비교한다.
   - **멈춤:** 정상이 ‘위험’으로 바뀐 사례가 하나라도 있거나, 위험 사례의 판정이 낮아지면 그 표현은 되돌린다.
   - 링크·회사 이름을 건드렸으면 Tranco도 돌린다.
6. `packages/core`, `skill`, `web` `npm test`와 `node --test eval/test/*.test.js`가 모두 통과하면 커밋한다. 메시지는 `feat(core): loop r<N> - <묶음 이름>`.
7. `docs/improve-loop-2026-11.md`에 라운드 한 줄을 추가한다: 라운드 번호, 묶음, 추가 표현(설명만, 정규식 전문은 코드에), v2 놓침/오경보 전후, 회귀 결과, 되돌린 것.

## 3. 규칙(판정 조합)을 바꿔야 할 때

코드 신호 추가는 라운드 안에서 해도 된다. **규칙 조합**(R1~R13 조건, 새 규칙)을 바꾸는 것은 하지 않는다. `docs/decisions.md`에 “제안 D5x” 행만 쓰고 그 묶음은 건너뛴다. 예: “가족 사칭 + 새 번호 + 개인정보 요구 → 위험”이 지금 규칙에 없으면 제안만 한다.

이미 알고 있는 우선 묶음(규칙만 평가, 놓친 35건 기준):
1. 가족 호칭 + 폰 고장·액정·임시폰·친구폰·번호 바꿈·새로 개통 → `SIG_FAMILY_IMPERSONATION` + `SIG_NEW_NUMBER`(코드). 16건. 지금 `SIG_NEW_NUMBER`는 끝 4자리 비교로만 켜진다. 문장으로 켜는 것이 지금 규칙(R3 등)과 맞는지 먼저 확인하고, 안 맞으면 3절대로 제안만 한다.
2. 근거 카드의 회사·기관 이름(택배·카드·은행·통신·쇼핑) + 공식이 아닌 링크·번호 → 사칭 신호. 9건. 운영자 결정(2026-11-27): 사칭 + 처음 보는 링크는 위험.
3. “아래 번호로·이 번호로·고객센터 0X-… 로 연락·신고” → `SIG_CALL_THIS_NUMBER`. 근거 카드의 공식 번호는 제외한다. 5건.
4. 신분증 사진·카드번호·유효기간·CVC·인증번호 알려 달라는 요구 → `SIG_PERSONAL_INFO`. 3건.
5. D50 보완: ‘안전계좌’와 ‘이체’ 사이에 계좌번호·괄호가 끼어도 잡는다(MV-B01). 1건. 운영자 결정으로 서버 AI 평가가 끝난 뒤 고친다. Claude Code가 평가 결과를 올렸다고 알리기 전에는 손대지 않는다.

## 4. 멈출 조건 (하나라도 닿으면 끝)

- v2 규칙만 놓침 **20% 이하**, 오경보 0건 유지
- 라운드 **8번**
- 두 라운드 연속으로 놓침이 2건 미만 줄었을 때(남은 것은 AI 몫)
- 남은 묶음이 모두 3절(규칙 변경 제안)에 해당할 때

## 5. 끝낼 때

1. `docs/improve-loop-2026-11.md`에 라운드 표, 최종 v2 수치, 회귀·Tranco 결과, 규칙 변경 제안 목록, 과적합 위험 메모(어느 표현이 v2 문체에 기대는지)를 쓴다.
2. 끝 문장: “v2는 개발 세트라 이 수치는 낙관적이다. 최종 수치는 v3(보지 않은 세트)로 Claude Code가 잰다.”
3. 마지막 줄: “서버 반영 승인 필요(배포 안 함)”.

## 6. 그 뒤 (Claude Code 몫, 참고)

- 개선이 끝나면 v3(독립 에이전트가 수법·문체를 달리해 따로 쓴 120건)로 규칙만 결과와 서버 AI 3회 결과를 잰다. 이 수치를 보고서에 쓴다.
- 운영자 승인 뒤 서버에 반영한다.
- 실제 문자에 가까운 표현이 더 필요하면 다음 반복은 v3를 개발 세트로 돌리고 v4를 새로 만든다(같은 방식을 반복).
