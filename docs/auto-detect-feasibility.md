# 문자·카카오톡 자동 판별 기술 확인

작성일: 2026-11-26 · 계기: 멘토링(2026-11-26) “문자를 받으면 바로 판단해 주면 좋겠다”, “카톡 채팅방 내용을 가져올 수 있나”
상태: 조사 결과 정리. 구현 결정 아님. 실제 문자 처리는 법률 검토와 운영 승인 서류(D43) 뒤에만 검토한다.

## 1. 결론 요약

| 방법 | 가능 여부 | 12/11 전 | 비고 |
|---|---|---|---|
| Android 앱이 받은 문자를 자동으로 읽기 | 조건부 가능 | 불가 | 기본 문자 앱으로 지정되거나 Google Play 예외 승인 필요. 별도 네이티브 앱 개발 |
| Android 알림 내용 읽기(알림 접근 권한) | 기술적으로 가능 | 불가 | 모든 앱 알림을 보는 강한 권한. 법률 검토 필수 |
| iPhone 앱이 문자를 자동으로 읽기 | 불가 | 불가 | 모르는 번호 문자만 ‘메시지 필터’로 분류 가능. 가족 알림 불가 |
| 카카오톡 채팅방 내용 가져오기(API) | 불가 | 불가 | 일반·단체 채팅방을 읽는 공식 API 없음 |
| 카카오톡 메시지 [전달] → 가족방패 채널 | **지금 가능** | 가능 | 사용자가 직접 보내는 방식. 안내만 추가 |
| Android 문자 [공유] → 가족방패 웹 앱 | 가능 | 가능(2~3시간) | 웹 앱의 공유 대상 기능. iPhone 미지원 |

**추천:** 자동 판별은 12/11 이후 로드맵에 둔다. 이번에는 사용자가 직접 보내는 방식([전달], [공유])을 쉽게 만드는 데 집중한다. 이 방식은 “가족방패는 먼저 링크를 보내지 않는다”, “원문 저장 안 함” 원칙과도 맞는다.

## 2. Android

- Google Play 정책상 문자(SMS)·통화 기록 권한은 **기본 문자 앱·전화 앱·어시스턴트로 지정된 앱**만 요청할 수 있다.
- 스팸 탐지·차단, 스미싱 보호는 허용 용도 목록에 있다. 하지만 기본 앱이 아니면 **사례별 심사로 예외**를 받아야 하고, 이용자 보호 실적이 요구된다.
- 알림 접근 권한(NotificationListenerService)으로 문자·카카오톡 알림 글자를 읽는 방법도 있다. 이 권한은 모든 앱의 알림을 본다. 받은 사람뿐 아니라 보낸 사람(제3자)의 정보도 처리하게 되어, 처리방침·동의·법률 검토가 먼저다.
- 어느 방법이든 지금의 웹 앱(PWA)으로는 할 수 없고 **Android 네이티브 앱**이 필요하다(개발·심사 기간 별도).

출처: [Google Play SMS·통화 기록 권한 정책](https://support.google.com/googleplay/android-developer/answer/10208820?hl=en), [권한 사용 예외 안내](https://support.google.com/googleplay/android-developer/answer/9047303)

## 3. iPhone

- iOS는 다른 앱이 문자 내용을 읽는 기능을 제공하지 않는다.
- 유일한 통로는 **메시지 필터 확장(IdentityLookup)** 이다. **모르는 번호에서 온 SMS·MMS만** 받으며, 결과는 ‘정크/거래/홍보’ 같은 분류만 할 수 있다.
- 서버 조회가 필요하면 시스템이 대신 서버에 물어 준다(확장 앱이 직접 인터넷에 접속하지 못함). 가족 알림, 결과 화면 열기 같은 동작은 할 수 없다.

출처: [Apple: SMS and MMS message filtering](https://developer.apple.com/documentation/identitylookup/sms-and-mms-message-filtering.md), [deferQueryRequestToNetwork](https://developer.apple.com/documentation/identitylookup/ilmessagefilterextensioncontext/deferqueryrequesttonetwork(completion:).md)

## 4. 카카오톡 채팅방

- 일반 채팅방·단체 채팅방·오픈채팅의 대화를 외부 서비스가 읽는 **공식 API는 확인되지 않았다**. 카카오톡 메시지 API는 로그인한 사용자가 친구에게 보내는 기능이다. 카카오 개발자 포럼의 답변 기준이며, 카카오 공식 문서로 “없다”고 확인한 것은 아니다.
- 챗봇(카카오톡 채널)은 **이용자가 채널 대화방에 보낸 말**만 받는다. 지금 가족방패가 쓰는 방식이다.
- **이미 되는 대안:** 카카오톡에서 의심 메시지를 길게 눌러 **[전달] → 가족방패 채널**을 고르면 챗봇이 판별한다. 시연 안내와 예시 화면에 이 방법을 넣는다.
- ‘대화 내보내기’로 채팅방 전체를 올리는 방식은 다른 사람의 대화까지 받게 되어 권하지 않는다.

출처: [카카오 데브톡: 단체방·오픈채팅 API 문의](https://devtalk.kakao.com/t/api/151008), [카카오 데브톡: 카카오톡 내용 API](https://devtalk.kakao.com/t/api/146860), [카카오톡 메시지 REST API 문서](https://developers.kakao.com/docs/latest/ko/kakaotalk-message/rest-api)

## 5. 12/11 이후 로드맵에 넣을 때 필요한 것

1. 실제 문자 처리 승인(D43의 운영 승인 서류 4가지, 법률 검토)
2. Android 네이티브 앱: 알림 접근 방식과 기본 문자 앱 방식 중 선택, Google Play 권한 심사 준비
3. 자동 판별 결과를 언제 알릴지(모든 문자? 링크·돈 요구가 있을 때만?) — 알림 피로와 오경보 영향 평가
4. iPhone: 메시지 필터로 ‘정크’ 분류만 하는 최소 기능의 실익 검토
