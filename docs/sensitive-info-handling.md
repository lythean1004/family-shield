# 민감정보(건강정보) 처리 방식 (작업 ⑦) — 운영자 결정 B + C 일부, 구현

작성일: 2026-11-11 · 근거: 멘토 1차 답변 Q1(병원 문자의 건강정보는 민감정보일 수 있음, 제23조, 정당한 이익만으로 해결되지 않음, 초기 운영에서 받지 않거나 제거할 방법을 정할 것)

## 1. 문제
- 부모님이 붙여 넣는 **진짜 병원·약국·검진 안내 문자**에는 부모님의 건강정보(진료과, 검사, 예약, 질환)가 들어 있을 수 있다.
- 지금은 이런 문자도 번호만 가린 채 해외 AI로 간다(해외 AI 분석을 허락한 경우).
- 반면 사기 문자의 “병원비가 급해”, “입원했어”, “건강검진 결과 확인” 같은 표현은 사기범이 지어낸 미끼라 실제 건강정보가 아니다.

## 2. 평가 세트로 본 규모 (2026-11-11)
건강 관련 표현(병원·입원·검진·접종·약국 등)이 든 문장: 평가용 200건 중 **9건**(위험 3, 확인 필요 6), 개발용 20건 중 2건.
- 위험 3건: 가족 사칭 병원비 요구, 입원 핑계 송금 요구, 건강검진 사칭 링크 — 모두 지어낸 미끼
- 확인 필요 6건: 정상 병원·예방접종·검진·약국 안내 — 진짜 건강정보가 들어갈 수 있는 유형

## 3. 선택지

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 건강 표현이 있으면 무조건 AI로 보내지 않음 | 건강 단어가 보이면 규칙만 판정 + “건강 관련 내용이 있어 해외 AI로 보내지 않았어요” | 가장 안전하고 단순 | 병원비 사칭 같은 사기에서도 AI를 못 써 놓칠 수 있음(평가 위험 3건 중 1건이 규칙만으로는 놓친 사례) |
| **B. 건강 표현 + 사기 요구 신호가 없을 때만 AI로 보내지 않음 (추천)** | 건강 단어가 있고 코드가 찾은 요구 신호(돈·개인정보·앱 설치·재촉·비밀·가족 사칭 등)가 **없으면** 규칙만. 요구 신호가 있으면 사기 미끼로 보고 지금처럼 처리 | 진짜 병원 안내(요구 신호 없음)는 해외로 안 감. 사기 문자는 AI 도움 유지 | 요구 신호가 있는 진짜 병원 문자(예: “진료비 수납 안내”)는 여전히 AI로 감 → 처방·질환 단어 가리기를 함께 함 |
| C. 건강 단어를 가리고 AI로 보냄 | 질환·진료과·검사명을 `[건강정보]`로 가림 | AI 판단 유지 | 가릴 단어 목록이 끝없음, 문맥으로 남을 수 있음 |
| D. 지금은 그대로, 전문가 확인 뒤 결정 | 합성 문자 시나리오(D43)라 실제 건강정보 없음 | 작업 없음 | 실제 문자 처리 전에 다시 결정해야 함 |

## 4. 추천: B + C 일부
1. 건강 표현이 있고 코드 요구 신호가 없으면 **해외 AI로 보내지 않고 규칙만 판정**, 결과에 이유 한 줄.
2. 요구 신호가 있어 AI로 보내는 경우에도 **질환·진료과·검사·처방 단어는 `[건강정보]`로 가림**(목록은 보수적으로 시작, 평가 세트로 영향 측정).
3. 링크 신호(SIG_LINK, 단축 URL)는 “요구 신호”로 치지 않는다. 진짜 병원 안내에도 링크가 흔하다. 링크 위험은 KISA·Google·사칭 감지·새 도메인 규칙이 따로 본다.
4. 판정 수준은 바꾸지 않는다(AI는 원래 판정을 정하지 않음). 영향은 설명 문장과 AI 신호 보탬뿐.

**측정 계획:** 평가 200건을 B 적용 전후로 돌려 놓침률·오경보율 변화를 확인(AI 3초 조건, 서버 키 사용). 예상: 위험 3건은 모두 요구 신호가 있어 영향 거의 없음, 정상 6건은 규칙만으로도 ‘확인 필요’.

**구현 범위(승인 후):** `packages/core/src/sensitive.js`(건강 표현 판별·가리기, 테스트 먼저), 파이프라인에서 AI 호출 전 분기, 결과 필드 `ai_skipped: "health"`, 카카오·웹 안내 문구, 처리방침 2장에 한 줄. 약 3시간.

## 5. 구현 결과 (2026-11-12)
- `packages/core/src/sensitive.js`(시험 먼저), 파이프라인 연결, 결과 `ai_skipped: "health"`, 카카오·웹 안내 “건강 관련 내용이 있어 해외 AI로 보내지 않았어요.”
- 구현 중 보완: ① 코드가 요구 신호를 못 찾는 가족 사칭(TEST-A005 “병원비 90만원 급해”)을 위해 **사기 미끼 표현**(금액, 병원비류, 송금·입금·계좌, 가족 호칭, 번호·기기 변경, 재촉)도 “AI 사용” 조건에 넣음 ② 기관 사칭(TEST-B065 “보건소 영장 발부”)을 위해 **법적 위협 표현**(영장·체포·압류·소송·미납 등) 추가 ③ `CCTV` 속 `CT`를 검사명으로 오인하던 문제(TEST-D2175)를 영문 검사명 앞뒤 영문자 금지로 수정.
- **평가 세트 결과(결정적 계산, AI 호출 없음):** AI를 건너뛰는 사례 6건 — 모두 정상 병원·접종·검진·약국 안내, 규칙만 판정이 정답과 6/6 일치. AI를 쓰되 건강 단어를 가리는 사례 11건(사기 9 + 정상 2). 가림이 AI 신호 추출에 주는 영향은 서버 키로 AI 평가를 돌려 확인할 수 있다(선택).
- 전체 시험 463건 통과.
