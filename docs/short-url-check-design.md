# 단축 URL 확인 방법 설계 (검토안)

작성일: 2026-11-26 · 계기: 멘토링(2026-11-26) “단축 URL은 어떻게 처리하나”, “의심 링크 판단의 정확성이 높아야 한다”
상태: **①+② 구현(2026-11-26, D48, 운영자 승인).** ③(펼치기 API)은 12/11 이후 따로 결정한다. 실제 목록 키는 20,425개(알려진 단축 서비스 22곳 + KISA에서 서비스로 본 42곳, 코드 1~2글자 제외).

## 1. 지금 방식

- 단축 서비스 22곳(bit.ly, han.gl, me2.do, url.kr, naver.me, buly.kr 등)을 알아보면 `SIG_SHORT_URL`(단축 링크 포함)을 붙인다.
- **펼치지 않는다**(D11). 펼치려고 접속하면 클릭 수가 올라가 “이 번호는 살아 있다”는 신호가 사기범에게 갈 수 있다.
- 판정: 단축 링크만 있으면 ‘주의’(R7). 기관 사칭이나 전화 받은 뒤 링크와 겹치면 ‘위험’(R6·R2). 공식 주소 예외(D47)에는 넣지 않는다.
- 한계: 단축 링크 속 주소를 모르니 KISA 목록·공식 주소 흉내·도메인 생성일 검사를 모두 못 한다. 링크만 있는 단축 URL은 언제나 ‘주의’다.

## 2. 측정 (로컬 KISA 목록, 2026-11-26)

| 항목 | 값 |
|---|---|
| KISA 피싱 목록 전체 행(2023·2024) | 159,219 |
| 그중 단축 서비스 주소 | 33,931 (21%) |
| 경로까지 있는 서로 다른 단축 주소 | 10,925 |
| 많이 쓰인 단축 서비스 | buly.kr, han.gl, t.ly, bit.ly, vo.la |

→ 피싱 문자 다섯 건 중 한 건꼴로 단축 URL을 쓴다. 목록은 2024년 말까지라, 오래된 주소가 그대로 다시 쓰일 때만 맞는다.

## 3. 방법 후보

| # | 방법 | 링크 접속 | 정확도 효과 | 개인정보·위험 | 작업량 |
|---|---|---|---|---|---|
| ① | **단축 주소 전체 대조**: KISA 목록의 단축 주소(서비스+경로)를 SHA-256 앞부분만 저장해, 문자 속 단축 주소와 그대로 맞춘다. 맞으면 `SIG_MALICIOUS_URL`(R10 위험) | 안 함 | 목록에 있던 주소만. 새 주소는 못 잡음 | 외부 전송 없음 | 2~3시간 |
| ② | **단축 링크 전용 안내**: 단축 링크가 있으면 “주소가 가려진 링크예요. 누르지 말고, 보낸 곳에 직접 확인하세요”를 고정 문장으로 붙인다. 링크만 보낸 경우 전용 답장 | 안 함 | 판정은 그대로, **어르신 이해도** 개선 | 없음 | 1~2시간 |
| ③ | **서비스 공식 펼치기 API**: 단축 서비스가 제공하는 조회 API(예: Bitly expand)로 원래 주소만 받아 ①~③단계 검사에 넣는다 | 단축 서비스에만 묻고 **원래 사이트에는 접속 안 함** | 속 주소를 알게 되어 목록·흉내·생성일 검사 가능 | 단축 코드가 단축 서비스 회사에 전달됨. 서비스마다 API·토큰·이용조건이 다르고, 국내 단축 서비스는 API가 없을 수 있음. **클릭 수에 잡히는지 서비스별 확인 필요** | 서비스별 1~2일 |
| ④ | 단축 주소에 직접 요청해 넘겨주는 주소만 읽기(HEAD 요청) | 단축 서비스 주소에 접속 | ③과 같음 | **클릭으로 잡힐 수 있어 D11 위반. 쓰지 않는다** | — |
| ⑤ | 단축 서비스의 미리보기 페이지(예: 주소 뒤에 + 붙이기) | 미리보기 페이지 접속 | 일부 서비스만 | 서비스 정책 확인 필요, 화면 긁기라 깨지기 쉬움 | — |

## 4. 추천

1. **지금(12/11 전): ①+②.** 링크에 접속하지 않는 원칙을 지키면서 정확도(목록 일치)와 어르신 이해도(전용 안내)를 같이 올린다.
2. **12/11 이후: ③을 결정 기록(D)으로 따로 검토.** 서비스별 API 이용조건, 클릭 집계 여부, 단축 코드 전달의 개인정보 영향을 확인한 뒤에만.
3. ④·⑤는 쓰지 않는다.

## 5. ①의 구현 메모

- 키 만들기: `buildKeys`가 지금은 단축 서비스 호스트를 목록에서 뺀다. 단축 주소는 `서비스호스트 + 경로`(대소문자 유지, 끝의 `/` 제거)를 정규화해 별도 키 파일(`content/phishing/short-*.txt`, 해시 앞 16자리만)로 만든다. 원본 CSV는 지금처럼 커밋하지 않는다.
- 대조: `extract`가 단축 링크를 찾으면 같은 정규화로 해시해 대조. 서버 메모리에서만, 외부 전송 없음.
- 오탐: 단축 서비스는 주소를 재사용하지 않는 것이 보통이지만 확인 필요. 정상 서비스의 단축 주소가 목록에 섞였는지 표본 20개를 사람이 확인(링크는 열지 않고 목록 문맥만).
- 평가: `eval/links-2026-11-26.jsonl`의 S 그룹과 KISA 표본으로 맞는 비율을 잰다(실제 피싱 주소는 저장소·문서에 원문으로 남기지 않는다).

## 6. ②의 문구 초안 (전문가 확인 전)

- 판정 답장에 추가: “주소가 가려진 링크(단축 링크)예요. 어디로 가는지 알 수 없으니 누르지 마세요. 보낸 곳에 직접 찾은 번호로 확인하세요.”
- 링크만 붙여 넣은 경우: “링크만 보내 주셨네요. 가족방패는 링크를 열어 보지 않고 주소 모양만 확인해요.” + 판정.
