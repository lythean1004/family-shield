# 공식 주소 판정 후속 보완 · 2026-11-27

작성: Codex · 기준 커밋: `14a6d9d` · 요청서: `docs/codex-request-link-review.md`

## 이번 범위와 결과

운영 채팅의 후속 요청에 따라 **공식 주소 안내를 허용하는 조건과 정상·혼합 링크 표시**에 집중했다. 요청서 전체 조사, 공식 카드 확대, KISA 자동 후보 재분류, D49 표현 사전 확대, 배포는 이번 완료 범위가 아니다.

- 후보를 토큰 전체로 보존하고, 네트워크 요청 없이 WHATWG `URL` 파서로 실제 URL 호스트를 확인한다. 이전 정규식이 일부만 인식했다는 이유로 공식 주소로 인정하지 않는다.
- 공백 사이 후보 안의 괄호·쉼표도 보존한다. 바깥의 짝지어진 감싸기와 ‘홈택스(주소)에서’ 같은 한글 안내 표기는 별도로 처리하며, 한 토큰에서 여러 링크가 인식되면 공식 예외를 보류한다.
- 후보의 전체 구문 확인이 안 됐거나 미지원 주소 모양이 남으면 메시지 전체의 공식 주소 예외를 보류한다. 입력이 2,000자 제한으로 잘렸을 때도 동일하다.
- 공식 예외에는 완전하게 해석한 HTTP/HTTPS 주소와 기본 포트만 허용한다. 사용자 정보, 변형 때문에 해석이 불확실한 구문, 인코딩된 전달 주소 등은 보류한다. 등록된 공식 카드 범위는 그대로다.
- **완결성 조건은 기존 위험 검사 입력을 삭제하는 필터로 쓰지 않는다.** `linksForRiskChecks`는 기존 `findLinks` 결과를 항상 포함하고, 완전하게 확인한 후보를 합친다. 기존 도메인 집합에 확인된 목적지를 더하며, 기존 도메인은 빼지 않는다. 목록 일치·주소 앞부분 속임수·기관/돈/개인정보 등의 위험 조건은 그대로다.
- R6·R7·R10·R11 및 D49 규칙 코드는 변경하지 않았다. 원문이나 파서 상태를 결과·DB·로그에 추가하지 않았다.

## 사례별 판정·안내

정상 기관 주소, 예약된 `.invalid` 주소, `example.com`·`example.org` 이메일을 사용했다. 새 시험에 취약점 재현 주소를 작성하지 않았다. 불완전한 후보는 파서 상태로 검증했다. 아래 10개 사례는 **동일한 고정 기대값**을 코어 파이프라인, 카카오 핸들러, 실제 웹 `ResultView` 렌더링에 적용했다.

‘안내’는 `OFFICIAL_LINK_TEXT` 전체 문단의 표시 여부다. 주의·위험 결과의 기존 신호 요약에서 공식 링크 포함 사실을 보여 주는 동작과는 구분한다.

|---|---|---|---|---|
| 정상 공식 링크 1개 | 확인 필요 | 표시 | 표시 | R8 |

## 검증 근거

1. 정상 자료와 추상 상태로 회귀 시험을 먼저 추가했다. 수정 전 공식 주소 시험에서 **3개 실패**(미완료 파서 상태·입력 미완료 상태·파이프라인 절단), 수정 후 통과했다. 마지막 후보 경계 점검에서도 정상 경로의 문장부호 보존 시험 1개를 먼저 실패시킨 뒤 수정했고, 기존 한글 안내 괄호 표기 시험까지 다시 통과했다.
2. `14a6d9d`의 신호 추출 본문과 새 코드에 같은 10개 사례를 넣어 비교했다. 공식 신호를 제외한 기존 위험 신호와 기존 도메인이 모두 새 결과에도 포함됐다. 공식 주소 의존 함수는 작업 사본의 함수를 사용하므로 이 비교는 **기존 위험 추출·도메인 유지 확인**에 한정하며, 전체 이전 버전의 판정 비교라고 주장하지 않는다.

## 한계와 후속

- URL 파싱은 글자 기준이다. 실제 링크를 열거나 단축 URL을 펼치지 않았으며, 서버가 나중에 보내는 주소·사이트 콘텐츠·발신자 신원까지 확인한 것은 아니다. ‘안전’ 판정은 추가하지 않았다.
- 미지원 주소 모양과 파일명을 구분할 수 없으면 공식 안내를 보류할 수 있다. 보수적으로 안내를 줄이는 동작이며 그 토큰 자체로 새 위험 규칙을 만들지 않는다.
- 실제 아이폰 자동 링크 인식·카카오 앱 수신 화면·음성 재생은 이번 로컬 시험의 대상이 아니다. 웹은 실제 컴포넌트의 정적 렌더링으로 확인했다.
- 공식 카드 확대와 KISA 자동 분류 후보의 정상 주소 오경보, D49 놓침·오경보 재평가는 후속 작업이다. 이번 정상·혼합 사례 통과를 전체 정확도나 놓침률 개선으로 해석하지 않는다.
- 서버 접속·배포·재시작과 Notion 쓰기는 하지 않았다. 운영 채팅이 이 문서와 커밋 근거로 상태를 갱신한다.
