# D41 설계안: 도메인 생성일 확인 (D40 ③)

작성일: 2026-11-11 · 상태: **승인(1안, decisions D41).** 시간 제한 2.5초(서버 실측 후 1.5초에서 보정), R12에서 재촉 제외로 확정

## 1. 목적
KISA 목록(~2024)과 Safe Browsing은 이미 알려진 피싱만 안다. 스미싱 도메인은 쓰기 직전에 새로 만드는 경우가 많으므로, **처음 보는 도메인이라도 “만든 지 며칠 안 됐다”는 사실을 신호로 쓴다.** 링크에 접속하지 않고 등록 정보만 묻는다(D11 유지).

## 2. 사전 조사 (2026-11-11)
- 조회 방식: RDAP(등록 정보 조회 표준). IANA 안내 파일(`https://data.iana.org/rdap/dns.json`, 2026-10-28 발행)에 1,203개 최상위 도메인의 조회 주소가 있다.
- 지원: `.kr`(KISA `rdap.nic.or.kr`), `.com`·`.net`, `.org`, `.xyz`, `.top`, `.shop`, `.pro`, `.one`, `.icu`, `.buzz`, `.yachts`, `.cfd`, `.mom`, `.bar`, `.site`, `.online`, `.life`, `.art`, `.pw`, `.ly`, `.to`, `.cc`, `.in` 등. 미지원: `.cn`, `.jp`, `.me`, `.io`, `.co`, `.la`, `.de`, `.su`, `.ru`.
- 속도(운영자 PC에서 측정): 0.05~0.9초. 서버(NCP)에서 다시 잰다.
- 응답의 `events`에 `registration`(등록일)이 있다. 없는 곳은 “알 수 없음”으로 둔다.
- **주의: 우리 도메인 `familyshield.kr`도 2026-10-27 등록이라 30일 기준에 걸린다.** 새 도메인이라는 사실만으로 위험을 주면 정상적인 새 사업자 링크도 위험이 된다.

## 3. 설계

### 3-1. 무엇을 묻나
- 문자 속 링크 도메인의 **등록 도메인**(예: `a.b.evil.shop` → `evil.shop`)만, 문자 1건당 최대 2개.
- 묻지 않는 것: 단축 URL, 공용 도메인, 공공기관 도메인(go.kr 등), 근거 카드 공식 도메인, KISA 목록·Safe Browsing에서 이미 위험으로 나온 도메인, 우리 도메인.
- 외부로 나가는 것: **등록 도메인 이름 하나**(경로·문자 원문·사용자 정보 없음).

### 3-2. 어디에 묻나
- IANA 안내 파일을 저장소에 넣어 두고(`content/rdap/dns.json`, 출처·발행일 기록, 월 1회 갱신) 그 주소로만 묻는다. 실행 중에 안내 파일을 내려받지 않는다.
- 안내 파일에 없는 끝부분은 묻지 않는다(“알 수 없음”).

### 3-3. 시간과 실패
- 시간 제한 0.8초(지금 Safe Browsing과 같음). AI·평판 조회와 **동시에** 돈다. 카카오 5초 제한에 영향 없음.
- 시간 초과·오류·등록일 없음은 신호를 켜지 않을 뿐 **판정을 낮추지 않는다.**
- 같은 등록 도메인은 서버 메모리에 24시간 캐시(파일·DB·로그에 남기지 않음). 같은 피싱 문자가 여러 부모님께 동시에 와도 한 번만 묻는다.

### 3-4. 신호와 규칙 (판정 수준은 측정 후 확정)
- 새 신호 `SIG_NEW_DOMAIN`: 등록일이 오늘로부터 **30일 이내**(설정값).
- **단독으로는 위험을 주지 않는다.** 링크가 있으면 이미 R7로 ‘주의’이므로 단독 효과는 요약 문구뿐이다.
- 제안 R12: `SIG_NEW_DOMAIN` + (돈 요구 / 개인정보 요구 / 앱 설치 / 재촉 중 하나) → ‘위험’. 지금 이 조합은 ‘주의’에 머문다.
- 요약 문구: “만든 지 얼마 안 된 링크 주소”.
- 기관 사칭+링크(R6), 공식 주소 흉내(R11), 목록 일치(R10)는 이미 ‘위험’이라 바뀌지 않는다.

### 3-5. 기록
- 서버 기록에는 조회 성공·실패 건수와 시간만 남긴다(도메인 이름 없음, CLAUDE.md 원문 미기록 원칙).

## 4. 결정 전에 할 측정 (승인 필요)
| 측정 | 방법 | 확인할 것 | 외부로 나가는 것 |
|---|---|---|---|
| A. 피싱 도메인은 정말 새것인가 | KISA 2024 목록에서 무작위 200개 등록 도메인의 등록일을 묻고 KISA 탐지일과의 차이를 센다(그 뒤 재등록된 것은 제외) | 탐지 시점에 30일 이내였던 비율 | 피싱 도메인 이름 200개를 각 등록 기관에 조회(접속 아님) |
| B. 정상 도메인은 얼마나 걸리나 | Tranco 무작위 1,000개 등록 도메인의 등록일 | 30일 이내 비율(오탐 기준선) | 정상 도메인 이름 1,000개 |
| C. 속도 | 서버(NCP)에서 A·B 일부를 다시 조회 | p50·p95, 시간 초과율 | 위와 같음 |

A·B 결과로 기준 일수(30일)와 R12 수준을 정한다. 조회는 초당 몇 건 이하로 천천히 한다(등록 기관 부담·차단 방지).

## 4-1. 측정 결과 (2026-11-11, `eval/domain-age-measure.mjs`, 도메인별 결과는 `data/rdap/`에만)
| 측정 | 결과 |
|---|---|
| **A. KISA 2024 피싱 도메인 200개** (RDAP 지원 끝부분 92.9%) | **189개(94.5%)가 이미 등록 말소**(404). 등록일 확인 10개 중 5개는 탐지 뒤 재등록, 남은 5개는 오래된 도메인(중앙값 2,271일, 정상 사이트 위 피싱으로 보임). → **탐지 당시 나이는 이 자료로 잴 수 없다.** 피싱 도메인 대부분이 2년 안에 버려지는 일회용이라는 점만 확인 |
| **B. Tranco 정상 인기 사이트 1,000개** | 등록일 확인 971개. **7일 이내 0.1%(1), 14일 이내 0.1%(1), 30일 이내 0.4%(4)**, 60일 2.5%, 90일 5.4%, 1년 18.4%. 중앙값 3,597일. 젊은 인기 도메인 다수는 불법 영화·도박 사이트로 보임 |
| **C. 속도** | 운영자 PC: p50 213ms·p95 1,180ms. **서버(NCP) 150개: p50 1,051ms·p95 1,404ms·최대 3,001ms**, 800ms 초과 62%, 1,500ms 초과 4.7%, 시간 초과 2%, 429(요청 제한) 1건. 원인: 서버에서 해외 RDAP 서버까지 연결·TLS에 약 0.7초(.kr KISA는 64ms) |

**해석**
- 30일 기준이면 정상 인기 도메인의 0.4%가 신호에 걸린다. 단독으로 판정을 올리지 않으므로 이 자체로 오경보는 늘지 않는다.
- 피싱 쪽 효과(놓침 감소)는 지금 자료로 측정할 수 없다(A 실패, 평가 세트 링크는 `.invalid`). 실제 운영에서 원문 없이 “신호가 켜진 횟수”만 세어 확인해야 한다.
- 서버에서는 설계안의 0.8초 제한으로는 60% 이상이 시간 초과다. **1.5초**로 두면 95%가 들어오고, AI(3초)와 동시에 돌아 카카오 응답 시간은 늘지 않는다.

## 5. 법률 검토 항목 추가
도메인 이름을 국내(KISA)·해외 등록 기관에 보내는 일이 새로 생긴다. 도메인 이름은 대부분 개인정보가 아니지만, 개인 이름으로 된 도메인일 수 있다. `docs/mentor-legal-questions.md`에 “문자 속 링크의 등록 도메인 이름을 등록 기관 RDAP에 조회하는 것”을 추가한다.

## 6. 작업량과 순서 (승인 후)
1. 측정 A·B·C(약 1시간, 조회 천천히) → 결과 보고
2. 기준 일수·R12 수준 확정(운영자 승인, decisions D41)
3. 테스트 먼저 → `packages/core/src/domain-age.js`, 파이프라인 연결, 요약 문구(약 3~4시간)
4. 서버 반영(운영자 승인) → 카카오 확인

## 7. 함께 하면 좋은 작은 수정
카카오 시험(2026-11-11)에서 R11 ‘위험’인데 AI 설명이 “건강검진 안내 문자입니다. 링크를 누르지 않도록 주의하세요.”로만 나와 위험한 이유가 보이지 않았다. **링크 규칙(R10·R11, 그리고 R12)으로 위험이 나오면 AI 설명이 있어도 코드 신호 문구(“공식 주소를 흉내 낸 링크” 등)를 항상 함께 보여 준다.**
