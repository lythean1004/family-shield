# VM 이전 계획 (D36)

작성일: 2026-10-28 · 결정: D36(docs/decisions.md) · 승인: VM 확정, `pg`·`web-push` 추가, 휴대폰 인증·시연은 중간과제 뒤

## 목표

저장되는 데이터를 모두 운영사 배정 NCP VM(한국, 101.79.8.126) 안에만 둔다. Supabase는 쓰지 않는다.

## 구조

```
브라우저(PWA) ── HTTPS ──> Nginx :443 ──> Node 서버 127.0.0.1:3000
                                            ├ /api/kakao-skill  (기존)
                                            ├ /api/auth/*       (새: 쿠키 세션)
                                            ├ /api/circle/*     (새: 초대 코드·동의)
                                            ├ /api/confirm/*    (새: 확인 요청 왕복)
                                            └ /api/push/*       (새: 웹 푸시 구독)
                                                 │ pg (127.0.0.1:5432, 외부 포트 없음)
                                                 ▼
                                            PostgreSQL 16
                                              - 기존 10개 + 새 5개(VM 반영·검증 완료)
                                              - auth.uid() = 요청마다 서버가 넣는 사용자 id
                                              - 기존 RLS 유지 + 새 API 권한 보완
systemd timer: 10분마다 purge_expired(), 매일 03:30 pg_dump 백업(7일)
```

권한 정책을 살리는 방법: 서버가 요청마다 트랜잭션을 열고 `SET LOCAL ROLE authenticated` + `set_config('request.jwt.claim.sub', <user id>, true)`를 넣는다. VM DB의 `auth.uid()`는 이 값을 읽는다. Supabase와 같은 방식이라 pgTAP 38개를 그대로 돌릴 수 있다.

## 2026-10-28 구현 상태

- 로그인·초대·동의(D37), 가족 확인 왕복·별도 기록 동의(D38), DB 1회용 토큰, 웹 푸시 API·시험 클릭 확인을 구현했다.
- PostgreSQL 16 로컬 통합 시험과 서로 다른 브라우저 세션의 요청 → 응답 → 부모님 반영을 확인했다. 실기기 시험은 별도다.
- 웹·서버 실행 코드와 CSP의 Supabase 참조는 0건. 기존 SQL 이력·권한 시험 경로만 보존한다.
- **사용자 승인 후 운영 VM 86ffd15 반영 완료(추가 판별 보완 6a71c5a 포함).** DB 권한 38/38, 최종 서버 core 201·skill 56, HTTPS 합성 가족 왕복, 백업 생성·덤프 검사, 아이폰 알림 클릭 확인(22:08:57 KST). 최신 놓침률 21.5%로 목표 5%는 미달. 자세한 결과는 `docs/deployment-review-2026-10-28.md`.
