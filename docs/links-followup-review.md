# 링크 점검 후속 조사·검증 (2026-11-11)

요청: `docs/codex-request-links-followup.md`. 로컬 구현·측정만 수행하며 서버 반영은 운영자 승인 후 Claude Code 담당이다. 원본 KISA·Tranco 자료는 `data/`에만 두며 이 문서에는 피싱 주소 원문을 싣지 않는다.

## 작업 1: 한진 이름 규칙

- 선택: (나) 이름 규칙을 좁힘. `hanjin`으로 시작하는 모든 조각 대신 **조각 전체가 hanjin 또는 hanjin+숫자**인 경우만 검사한다. 점·하이픈으로 나눈 조각에 적용하므로 `hanjin-delivery.invalid` 같은 합성 예시는 유지한다.
- 근거: KISA 2023·2024의 정규화한 서로 다른 호스트 29,033개에서 한진 접두어에 걸린 3개는 모두 이름+숫자 조합이었다. 수정 후에도 3/3 유지. CSV 159,334행은 반복 URL을 포함하므로 호스트 수와 구분한다.
- 정상 인기 사이트(Tranco 100만): R11 **5 → 4개**(0.0005% → 0.0004%), 한국 `.kr` 4,343개는 **0 → 0개**. 한진트래블 주소에 대한 감지가 사라졌다. R10은 양쪽 모두 0개이나 이 목록은 KISA 제외 목록에도 사용되어 독립적인 정확도 검증은 아니다.
- 시험 먼저: 정상 계열사 이름을 잡지 않는 회귀 시험을 추가해 기존 규칙에서 실패하는 것을 확인한 뒤 수정. 사칭·정상·다른 단어·공식 하위 주소를 포함한 lookalike 시험 14개 통과.
- 공식 출처 재확인: [한진 공식 누리집](https://www.hanjin.com/kor/Main.do)의 원클릭·계열사 연결, [한진칼 2025 ESG 보고서](https://www.hanjinkal.co.kr/common/file/2025%20HANJIN%20KALESG_Report_kr.pdf)의 관광 계열사 설명. 신규 여행 웹주소를 직접 명시한 근거는 확보하지 못했다. 이전 [대한항공 제휴사 안내](https://www.koreanair.com/contents/footer/terms-and-policies/privacy-policy/list-of-recipients-of-personal-information)는 업무 이메일 도메인만 확인한다. 따라서 미확인 주소를 공식 목록에 추가하는 대신 규칙 자체의 범위를 줄였다.
- 다른 접두어 점검: 우체국 16, CJ 12, 로젠 86, 롯데 5, 교통민원24 43, 건강보험 3개가 KISA 호스트에서 감지된다(각 카드 첫 매칭 기준). CJ의 해외 주소 후보는 공식 근거 미확인이 계속되어 보류. `nhis`는 다른 의료기관 약자와 겹칠 가능성이 있으므로 신호가 사칭 확정을 뜻하지 않는다. 근거 없는 추가 규칙 변경은 하지 않았다.
- 한계: 이 축소로 이름 뒤에 다른 영문 단어를 붙인 새로운 한진 사칭은 R11에서 놓칠 수 있다. 기존 KISA 목록 대조·다른 신호는 유지되며 실제 놓침률 개선을 증명한 것은 아니다. R11의 '위험' 수준은 변경하지 않았다.

## 작업 2: 새 카드 후보와 좁은 이름 조합

빈도는 CSV의 URL을 `toDomain` → `normalizeHost`로 정규화한 **서로 다른 호스트**에서 센다. 같은 호스트의 여러 경로·여러 날짜는 한 번이다. 아래는 점·하이픈으로 나누고 최상위 영역을 뺀 조각의 **앞부분 일치**이며, 단순 부분문자열 횟수와 다르다. 숫자는 그 기관의 실제 사칭 확정 건수가 아니다. KISA에는 정상 서비스의 악용 주소와 임의 문자열도 섞여 있다.

| 이름 조각 | 호스트 수 | 결정 |
|---|---:|---|
| customs / unipass / fss / fsc | 각 0 | 관세청·금감원 후보 보류: 이 자료에서 이름 근거 없음 |
| kb / nh / woori | 5 / 90 / 3 | 짧은 임의 문자열, 기존 nhis, 다른 서비스 이름 포함. 은행 사칭으로 단정할 근거 없음 |
| kbstar / kookmin / nonghyup / shinhan / hana / hanabank / ibk | 각 0 | 보류 |
| samsung / hyundai / lotte / card | 3 / 0 / 7 / 0 | 롯데는 기존 물류 이름 포함. 카드의 중간 문자열은 청첩장 등도 포함하여 일반 card 규칙 보류 |
| kt / skt / lg / uplus | 31 / 21 / 22 / 0 | 아래 문자 조합으로만 한정 |

`uplus`를 중간 문자열로 찾으면 3개가 나오지만 해당 기관의 공식 모바일 서비스인지 확인할 근거가 부족해 이번 이름 규칙에서는 제외했다. 현대카드 철자를 닮은 1개 조각도 있었으나 공식 첫 화면·모바일/인증 안내 원문 확인이 시간 초과로 실패하여 카드를 보류했다. [KB국민은행 공식 안내](https://www.kbstar.com/)의 은행·인증 하위 도메인은 확인했지만, 자료의 짧은 `kb` 조각을 은행 사칭으로 볼 근거가 충분하지 않다.

| 새 카드 | 감지 범위(라벨 전체) | KISA 감지 호스트 | Tranco 100만 추가 R11 | .kr 추가 R11 |
|---|---|---:|---:|---:|
| KT | kt-sms, kt-sms-vip, kt-text, ktsms, bg-ktsms | 9 | 0 | 0 |
| SK텔레콤 | skt-sms, skt-sms-vip, skt-text, skt+숫자-txt | 7 | 0 | 0 |
| LG유플러스 | lg-sms, lg-sms-vip | 4 | 0 | 0 |

- `label_regex`로 하이픈을 보존한 DNS 라벨 전체를 검사한다. 짧은 이름 단독·부고·일반 접두어/접미어는 제외. 합성 `.invalid` 주소로 먼저 실패 시험 후 구현했고 lookalike 15개 통과. 세 카드의 일치 조건은 서로 겹치지 않으며 동일한 100만 개 시험에서 카드별 신규 매칭이 모두 0개다.
- 공식 주소: KT `kt.com`, `olleh.com`; SK텔레콤 `sktelecom.com`, `tworld.co.kr`, `sktpass.com`; LG유플러스 `lguplus.com`, `uplus.co.kr`. 모바일·고객센터·인증의 하위 주소도 제외 대상에 포함된다. 출처·확인 한계는 각 카드 `check_note`에 기록했다.
- 주요 근거: [KT 모바일 로그인](https://m.kt.com/html/guide_pass.html), [KT 인증 약관](https://fido.kt.com/certService), [SK텔레콤 공식 고객센터 연결](https://www.sktelecom.com/), [SKT PASS 운영 주체·약관](https://www.sktpass.com/), [LG유플러스 서비스 인증 주소 안내](https://www.lguplus.com/biz/support/service-info/guide/744), [LG유플러스 PASS 안내](https://www.lguplus.com/mobile/plan/addon/addon-pass/LRZ0002347). KT 구주소는 공식 이용약관으로 확인했으나 현재 첫 화면은 열기 실패. LG 별도 인증 도메인은 직접 연결 근거가 없어 미추가.
- 전체 R11 **4 → 4개**, .kr **0 → 0개**, R10 **0 → 0개**. 카드마다 제안된 추가 기준을 만족했다. 인기 목록은 전체 정상 주소를 대표하지 않으므로 오탐이 없음을 보장하지 않는다. 문자 원문·시점별 위협 증거를 대조하지 않아 20개를 새 탐지 성공률로 해석할 수 없다(R10과도 중복 가능).
- 공식 도메인을 제외하도록 KISA 빌더 재실행: 159,334행, 키 **31,111개**, 단축 서비스 **42개** 유지. 산출물 변경 없음.
- 카드 10 → **13장**, 모두 `source_checked`, `terms_checked=false`. **새 카드 서버 반영 승인 필요**. R11 위험 수준 자체는 바꾸지 않았다.

## 작업 3: 원문 없는 운영 집계

- [설계와 검증](signal-counts-design.md)을 먼저 작성하고 실패 시험 후 구현했다. KST 날짜별로 알려진 신호·R1~R12·조회 성공/실패/미호출·지연 합계/최댓값/구간 건수만 메모리에 모은다. RDAP 실제 요청/캐시/미지원/등록일 미확인을 구분한다.
- 원문·주소·사용자 식별자·AI 설명·오류 문자열은 합계·출력에 포함하지 않는다. DB 변경 없이 최근 7일 상한을 두며, 지난 날짜 및 정상 종료 분량만 기존 로그로 출력한다. 새 통계 HTTP 경로는 없다.
- 결과 저장 필터의 R11/R12 누락을 고쳤다(기존 누락 기록 소급 복원은 안 됨). 관련 81개 시험 통과, DB 통합 suite는 미실행. 실제 서버 집계·종료 로그는 배포 후 확인 필요.
- 발동 횟수는 정확도나 피해 예방 성과가 아니다. 재시작·강제 종료 유실과 날짜별 여러 프로세스 분량 합산에 주의한다.

## 작업 4: 누락 24건의 정확한 분류와 링크 인식

이전 **24건을 재현했다**. 이는 `findLinks()` 전체가 아니라 `BARE_DOMAIN_RE`만 검사한 숫자다. CSV 159,334행 중 스킴으로 시작하지 않는 값 1,975개를 뽑는 이전 집계 방식 그대로 비교했다. CSV 따옴표를 정상 해석하면 그중 2개는 스킴 있는 URL이므로 실제 스킴 없는 값은 1,973개다.

| 이전 정규식 누락 유형 | 행 수 | 처리 |
|---|---:|---|
| 실제 도메인, 미지원 끝부분 | 14 | `.media` 4개, `.show`, `.gold`, `.vin`, `.services`, `.ski`, `.pub`, `.moe`, `.mobi`, `.baby`, `.rent` 각 1개. 11종 추가로 모두 인식 |
| 점이 없는 단어/상대 경로 형태 | 7 | 호스트가 없어 도메인으로 추정하지 않음. 일부 단어를 처음에는 끝부분으로 잠정 분류했지만 원본 형태 확인 후 바로잡음 |
| 스킴 앞 글자 오기 | 1 | 전체 함수는 내부 스킴 URL을 이미 찾음. 자료 원문을 자동 수정하지 않음 |
| CSV 따옴표 안의 스킴 URL | 2 | 전체 함수는 이미 찾음. 따옴표를 해석하면 스킴 없는 항목에서 제외됨 |

- 출처: [IANA 위임 TLD 목록](https://data.iana.org/TLD/tlds-alpha-by-domain.txt), **Version 2026111100, 2026-11-11 07:07:02 UTC**. 추가 11종 모두 확인했다. 7개 비주소 항목에 도메인이나 스킴을 임의로 붙이지 않았다. 이 누락 집합의 숫자 IP·한글 도메인은 각각 0개다(일반 지원 여부를 증명하는 수치는 아님).
- 실제 전체 함수의 미인식은 **21 → 7개**, 정규식만의 미일치는 **24 → 10개**. 남은 10개 중 3개는 전체 함수가 이미 인식하며 7개는 주소 형식이 아니다. 원본 자료의 주소형 14개는 해결했다.
- 별도로 주소 중간 `www`를 링크 시작으로 오인하여 호스트 앞부분을 잘라 내던 **1건**을 바로잡았다. 미지원 끝부분이더라도 `www`가 있는 기존 주소는 전체 호스트로 유지한다. CSV 따옴표·스킴 오기와 이 잘림을 별도로 세어 링크 일부만 찾은 것을 완전 인식으로 세지 않았다.
- 실패 시험을 먼저 작성했다. 새 끝부분·대소문자·경로·쿼리·괄호, 소수·버전·날짜·전화번호·이메일·파일 경로·단어 중간·`www` 포함 호스트의 회귀 시험을 통과했다. 새 끝부분이 파일명 중간에만 나오는 경우는 제외한다.
- 범위 제한: 기존 끝부분의 경계를 모두 엄격하게 바꾸면 목록에 없는 국가 도메인의 기존 인식까지 대량 변경된다. 이번에는 새 11종과 `www` 호스트 처리만 보완했다. 기존 정규식이 일부 미지원 끝부분 주소의 앞부분만 인식할 가능성은 별도 검토로 남긴다. 등록 도메인 전체를 일반적으로 검증하는 파서로 바꾼 것은 아니다.

재현 명령(네트워크 호출 없음, 원문 주소 출력 없음):

```powershell
node eval/links-followup.mjs data/kisa/kisa-2023.csv data/kisa/kisa-2024.csv --links-ref ec3bc1f
node eval/links-followup.mjs data/kisa/kisa-2023.csv data/kisa/kisa-2024.csv
node eval/lookalike-fp.mjs data/tranco/top-1m.csv 1000000
```

첫 두 명령의 `--links-ref`는 링크 인식 코드만 해당 커밋으로 비교하며 카드·이름 빈도는 현재 카드 기준이다. 마지막 기존 오탐 명령은 인기 사이트의 주소를 출력하므로 보고서에는 건수·카드별 합계만 옮겼다.

## 최종 비교·서버 인계

| 단계 | Tranco 100만 R11 | .kr 4,343개 R11 | R10 |
|---|---:|---:|---:|
| 시작 | 5 | 0 | 0 |
| 작업 1: 한진 축소 | 4 | 0 | 0 |
| 작업 2: 통신사 카드 3장 | 4 | 0 | 0 |
| 작업 4: 링크 인식 보완 | 4 | 0 | 0 |

작업 4는 호스트를 직접 넣는 기존 오탐 시험 외에 **스킴 없는 입력 → 링크 인식 → R11** 경로도 100만 개 전체에서 비교했다. R11 **4→4**, .kr **0→0**. 링크를 하나라도 인식한 행은 **831,866→833,709**(신규 1,846, 감소 3)였다. 감소 3개는 단어 내부 `www` 뒤만 잘라 인식하던 주소였고, 전에도 전체 호스트를 인식한 것은 아니었다(`.ir` 2, `.dev` 1, 기존 끝부분 미지원). 실제 호스트로 잘못 판단하던 부분 인식을 제거했으나 해당 전체 주소의 스킴 없는 인식은 별도 보완 대상으로 남는다. 이 숫자는 인기 사이트 주소 인식 범위이며 문자 판별 정확도가 아니다.

전체 지정 시험 **427개 통과**. PostgreSQL 통합 suite 3개는 `FS_DB_TEST` 미설정으로 실행하지 않았다(Node 합계의 skipped 0과 별개로 suite가 생략됨). 원본 KISA·Tranco와 측정 출력은 `data/`에만 두며 커밋하지 않는다.

승인 필요: **새 통신사 카드의 R11 적용 및 이번 변경의 서버 반영**. 위험/주의 수준과 R12 조건은 변경하지 않았다. 이번 요청에 따라 서버 접속·배포·재시작·설정 변경을 전혀 하지 않았다. 서버의 현재 커밋도 재확인하지 않았다. 배포 담당자는 승인 후 카드/코어/스킬을 같은 버전으로 반영하고, 정상 종료·다음 날짜의 `signal_daily` 로그를 확인해야 한다. 마이그레이션·비밀값 변경은 없다.
