# 화면 명세

작성일: 2026-10-26 · 기준: docs/prd.md v0.7(7장 기능, 8장 화면, 9장 판별) · 상태: 초안 1차(핵심 판별·응답 흐름), Q1~Q4 결정 반영

Figma 시안 없이 진행한다(PRD 13-1 "디자인"). **코드가 디자인 산출물**이고, 이 문서는 화면별로 무엇을 보여 주고 어떤 버튼을 두는지 정한다. 화면 ID는 PRD 8장을 그대로 쓴다. `[임시]`는 테스트 가족 사용성 확인 뒤 조정할 값이다.

## 1. 화면 공통 규칙 (PRD 8장 화면 기준을 구체화)

| # | 규칙 |
|---|---|
| U1 | 한 화면에 행동 하나. 버튼은 **최대 3개**, 가장 안전한 버튼을 **맨 위에 가장 크게** |
| U2 | 문장은 두 줄 이내. 부모님 화면 본문은 한 화면에 3문장 이하 |
| U3 | 판정은 색만으로 구분하지 않는다. **색 + SVG 아이콘 + 글자**(위험 / 주의 / 확인 필요, Q4 결정: SVG) |
| U4 | 모든 결과 화면 하단에 한계 문구(F4-8). 모든 화면 맨 아래에 “가족방패는 문자로 링크를 보내지 않아요.” |
| U5 | 모든 위험 화면에 112 안내: “전화 화면에 112라고 떠도 믿지 마세요. 끊고 직접 거세요.” |
| U6 | ‘안전’, ‘정상’이라는 말을 화면 어디에도 쓰지 않는다(원칙 1) |
| U7 | 전화 버튼은 근거 카드나 등록된 번호 카드의 번호만(`tel:`). 문자 속 번호는 전화 버튼으로 만들지 않는다(원칙 3·8) |
| U8 | 화면에 원문을 다시 보여 주지 않는다. 부모님 화면은 신호 문구(9-9 문장 틀)만, 보호자 화면도 같다(F5-8) |
| U9 | 로딩은 결과 화면 모양의 뼈대(스켈레톤), 실패는 “무엇이 안 됐고 무엇을 하면 되는지” 한 줄 + 다시 하기 |
| U10 | 터치 영역 최소 48px [임시], 버튼 사이 간격 12px 이상. 큰 버튼 높이 64px [임시] |

## 2. 디자인 토큰

`web/src/index.css`의 CSS 변수로 둔다. 컴포넌트는 값을 직접 쓰지 않고 토큰만 쓴다. 대비는 WCAG AA(본문 4.5:1, 큰 글씨 3:1) 이상을 목표로 하고 구현 때 수치로 확인한다.

### 2-1. 색

| 토큰 | 용도 | 값 [임시] |
|---|---|---|
| `--c-bg` | 화면 배경 | `#ffffff` |
| `--c-surface` | 카드 배경 | `#f5f6f8` |
| `--c-border` | 구분선·카드 테두리 | `#d0d4da` |
| `--c-text` | 본문 | `#111418` |
| `--c-text-sub` | 보조 문구(출처, 시각) | `#4a525c` |
| `--c-action` | 기본 행동 버튼 | `#1a56db` |
| `--c-action-text` | 행동 버튼 글자 | `#ffffff` |
| `--c-danger` / `--c-danger-bg` | 위험 | `#b42318` / `#fdecea` |
| `--c-caution` / `--c-caution-bg` | 주의 | `#9a4a00` / `#fff4e5` |
| `--c-check` / `--c-check-bg` | 확인 필요 | `#1f4f99` / `#eaf1fb` |
| `--c-focus` | 키보드 초점 테두리 | `#1a56db` |

- 다크 모드는 1차 범위에서 제외(어르신 휴대폰 기본값이 라이트인 경우가 많고, 판정 색 대비를 두 벌 검증해야 함). 추후 `prefers-color-scheme`로 추가.
- 주의(주황)는 흰 배경 대비가 약해지기 쉬워 글자색을 진한 갈색 계열로 둔다.

### 2-2. 글자

| 토큰 | 부모님 화면 (일반의 150%, D32) | 보호자 화면 | 용도 |
|---|---|---|---|
| `--fs-body` | 30px (20 × 1.5) | 17px | 본문 |
| `--fs-title` | 42px (28 × 1.5) | 22px | 화면 제목 |
| `--fs-verdict` | 54px (36 × 1.5) | 28px | 판정 단계 표시 |
| `--fs-small` | 24px (16 × 1.5) | 14px | 출처·시각·한계 문구 |

- 부모님 화면은 `<main class="mode-parent">`, 보호자 화면은 `mode-guardian`으로 토큰 값을 바꾼다. 휴대폰 글꼴 크기 설정을 따르도록 `rem` 기준.
- 줄 간격 1.6, 굵기는 400/700 두 가지만. 번호는 `font-variant-numeric: tabular-nums`.

### 2-3. 간격·모양

- 간격: 4px 단위 `--sp-1`(4) `--sp-2`(8) `--sp-3`(12) `--sp-4`(16) `--sp-6`(24) `--sp-8`(32)
- 모서리: 버튼·입력 12px, 카드 16px
- 그림자는 쓰지 않고 테두리 1px로 구분(저사양 기기, 고대비)
- 본문 최대 폭 32rem, 좌우 여백 16px

## 5. 화면별 명세

표기: **[버튼]**은 위에서부터 순서대로(맨 위가 가장 안전한 행동, U1). “문구”는 그대로 쓸 초안이다.

### K1. 챗봇 판별 답변 (카카오톡)

카카오 말풍선이라 웹 토큰이 적용되지 않는다. 글 1,000자·말풍선 3개·바로가기 버튼 제한 안에서 구성한다(현재 `skill/src/handler.js`).

| 순서 | 내용 |
|---|---|
| 1 | (R1일 때만) 끊기 안내가 맨 앞: “지금 통화 중이면 바로 끊으세요.” |
| 2 | `[위험]`/`[주의]`/`[확인 필요]` + 신호 문구(9-9) |
| 3 | 지금 할 일 한 줄(단계별 고정 문구) |
| 4 | 한계 문구(F4-8) |
| 바로가기 | [112 전화] (위험일 때) · [자세히 보기] (`WEB_BASE_URL` 설정 시, → P4) |

- 이미지가 오면 판별하지 않고 “사진 말고 글자를 복사해 붙여 주세요.”(frontend-structure 4-5-1)
- 확인할 것 → **결정(Q1, D34): 10분 만료 1회용 토큰**. 버튼 주소 `/check/result?t=<토큰>`(PRD 13-4)

### H0. 홈 `/`

- **제목:** 가족방패
- **문구:** “의심 문자를 받으면 카카오톡 ‘가족방패’ 채널에 붙여 넣으세요.” / “혼자 판단하지 말고 가족과 같이 확인해요.”
- **[버튼]** ① [공식 번호 보기] → N1 ② [이미 눌렀거나 보냈어요] → E1 ③ [예시 보기] → D1
- 하단: NoLinkFooter
- 로그인한 보호자면 상단에 “확인 요청 n건” 띠(→ C4, 2차)

### N1. 공식 번호 카드 `/contacts`

- **제목:** 공식 번호
- **문구:** “문자에 적힌 번호 말고, 여기 있는 번호로 직접 거세요.”
- **목록:** CallButton 카드. 112(경찰) 맨 위 고정(F2-4) → 근거 카드 기관(금융감독원 1332 등) → 우리 집 카드(로그인 시, 직접 입력은 ‘가족이 입력’ 표시, F2-2)
- 카드마다: 기관 이름, 번호(큰 글씨), “출처 ○○ · 확인일 2026-10-15”(작은 글씨)
- 오프라인: 서비스 워커 캐시로 그대로 표시 + OfflineBanner(F2-6)
- 하지 않는 것: 검색창, 번호 직접 입력(입력은 S4에서만)

### D1. 공개 데모 `/demo`

- **문구:** “실제 사기 문자를 바꿔 만든 예시예요. 실제 판별은 카카오톡 채널에서 해요.”
- **목록:** 예시 4개(SC1 딸 사칭 / SC2 기관 전화 뒤 링크 / SC3 이미 링크 누름 / SC4 신호 약함). 행동 버튼이 아니라 고르는 목록이라 U1의 3개 제한에서 예외
- 누르면 P4·E1과 **같은 컴포넌트**로 고정 결과를 보여 준다(AI 호출 없음, 12-5). 화면 맨 위에 “예시” 띠 고정
- 예시 문자 원문은 마스킹된 형태(`[링크]`, `[번호]`)로만 보여 준다

### P2. 전화 받았는지 `/check/call`

- **제목:** “이 문자 받기 전에 전화가 왔나요?”
- **[버튼]** ① [지금 통화 중이에요] (danger) → P2-a ② [전화 받았어요] → P4 ③ [전화 없었어요] → P4
- 고른 값은 `call_in_progress`/`called_before`로 규칙 엔진에 들어간다(R1·R2). 판정을 내리는 입력만 받고 되돌리기는 없다(판정은 올라가기만, 원칙 2)
- 챗봇에서는 같은 질문을 바로가기 버튼으로 묻는다(카카오 `params` 키 4개, 오픈빌더 연결 때 확인)

### P2-a. 통화 중 끊기 안내 `/check/hangup`

로그인 없이 바로 보여야 한다(가장 급한 화면).

- 배경 `--c-danger-bg`, VerdictBanner(danger) “[위험 아이콘] 위험”
- **문구(크게):** “지금 바로 전화를 끊으세요.” / “상대가 뭐라고 해도 괜찮아요. 끊는 게 먼저예요.”
- Warning112
- **[버튼]** ① [끊었어요] → P4 ② [112에 전화] (CallButton, “끊은 다음에 거세요” 보조 문구)
- 하지 않는 것: 끊기 전에 다른 입력 요구, 긴 설명

### P4. 판별 결과 `/check/result`

가장 중요한 화면. 위에서 아래로 **판정 → 이유 → 지금 할 일 → 행동 → 한계**.

| 영역 | 위험 | 주의 | 확인 필요 |
|---|---|---|---|
| VerdictBanner | 위험 SVG 아이콘 | 주의 SVG 아이콘 | 확인 필요 SVG 아이콘 |
| 한 줄 설명 | 사칭 유형별 고정 문구. 가족 사칭: “가족인 척하는 사기에서 자주 보이는 말이 있어요” | “사기에서 쓰는 말이 섞여 있어요. 확인하고 움직이세요” | “눈에 띄는 사기 신호는 없었어요. 그래도 공식 번호로 확인하면 확실해요” |
| 이유 | SignalList(9-9 문구) + AI 설명(검증 통과분, 최대 3문장) | 같음 | 생략 |
| 지금 할 일 | “링크를 누르지 말고, 돈을 보내지 마세요.” + Warning112 | “링크를 누르지 마세요.” | 없음 |
| [버튼] ① | 가족 사칭: [지은이에게 진짜인지 물어보기] → P6 / 기관 사칭: [공식 번호로 직접 확인] → N1 | [가족에게 물어보기] → P6 | [공식 번호 보기] → N1 |
| [버튼] ② | [112에 전화] | [공식 번호 보기] → N1 | [가족에게 물어보기] → P6 |
| [버튼] ③ | [이미 눌렀거나 보냈어요] → E1 | [이미 눌렀거나 보냈어요] → E1 | — |

- 하단: LimitNotice → 작은 글자 링크 “이 판정이 이상해요”(F4-13, P1) → NoLinkFooter
- AI 실패·시간 초과(F4-6): 이유 칸에 “자세한 설명을 만들지 못했어요. 판정은 그대로예요.” 판정은 코드 값 그대로
- [읽어주기] 버튼(F4-12, P1)은 VerdictBanner 오른쪽 작은 버튼(행동 버튼 3개에 세지 않음)
- 가족 확인 버튼은 동의 ②가 있을 때만(F5-9). 없으면 ①을 [공식 번호 보기]로 대체
- 모르는 가족 이름은 ‘가족’으로 표시(P3는 2차)

### P6. 가족 답 기다리기 `/check/wait`

- **제목:** “지은이에게 물어봤어요.”
- **먼저 보여 줄 것(가장 크게):** “답이 올 때까지 링크를 누르거나 돈을 보내지 마세요.”(frontend-structure 3장 기획 챌린지)
- 상태: “보낸 시각 오후 3:12 · 아직 답이 없어요” — 3초마다 확인(F5-6), 시계 대신 점 3개 애니메이션(움직임 줄이기 설정이면 멈춤)
- **[버튼]** ① [지은이 원래 번호로 전화] (등록된 번호만, U7) ② [다른 가족에게도 물어보기] (P1, F5-7)
- 일정 시간 [임시] 5분 응답 없음: “답이 늦어요. 원래 번호로 전화해 보세요.”로 문구 교체(F5-7)
- 답이 오면 자동으로 P8

### P8. 가족 답 반영 결과 `/check/answer`

| 가족 답 | 판정 | 문구(8장 핵심 문구) | [버튼] |
|---|---|---|---|
| 보낸 적 없어요 | 위험(R5) | “지은이가 보낸 문자가 **아니에요**. 지은이가 직접 확인해 줬어요.” + “문자에 답하지 말고 지우세요.” | ① [확인했어요] → H0 ② [이미 눌렀거나 보냈어요] → E1 |
| 제가 보냈어요 | **그대로**(F5-5) | “지은이가 **보냈다고 답했어요.** 그래도 위험한 부탁이 있어요. **목소리로 통화하기 전에는** 돈이나 결제를 하지 마세요.” | ① [지은이 원래 번호로 전화] ② [확인했어요] |
| 지금 엄마께 전화할게요 | 그대로 | “지은이가 곧 전화할 거예요. 전화를 받기 전까지 아무것도 하지 마세요.” | ① [확인했어요] |

- 하단: LimitNotice, NoLinkFooter
- “제가 보냈어요”에도 초록색·체크 표시를 쓰지 않는다(‘안전’으로 읽힘, U6)

### E1. 사후 대응 `/help`

로그인 없이 열린다(감염 의심 기기에서 로그인 요구는 위험·불가능할 수 있음).

- **제목:** “무엇을 했나요?”
- **고르기(4개, F6-1):** [링크를 눌렀어요] [앱을 깔았어요] [돈을 보냈어요] [정보를 알려 줬어요] — 고르는 목록이라 U1 예외
- 고른 뒤 StepList로 근거 카드 절차를 **한 번에 한 단계**(F6-2), needs_review 카드는 제외(F6-5)
- **링크·앱(F6-3):** 공식 번호 전화 버튼을 **숨기고** ① 비행기 모드 켜기 ② 다른 휴대폰이나 집 전화 쓰기 ③ 초기화나 앱 삭제는 가족·서비스센터와 ④ 경찰서 직접 방문. “이 휴대폰으로는 신고 전화를 걸지 마세요. 화면에 112라고 떠도 믿지 마세요.”
- **돈·정보:** 지급정지 요청(112 또는 은행 콜센터, 근거 카드 번호) → 다음 단계
- 보호자에게 최우선 알림(F6-4)은 로그인·동의가 있을 때만 서버로. 링크·앱이면 보호자 화면에 “엄마 휴대폰 말고 다른 방법으로 연락해 보세요”

### C2. 보호자: 요약과 응답 `/family/req/:id`

보호자 글자 토큰(`mode-guardian`). 정보는 F5-8 범위만.

- **상단:** “엄마(김○○)가 확인을 요청했어요 · 오후 3:12”
- **요약:** VerdictBanner(작게) + 문장 틀 요약(9-9, 예 “딸이라고 함 · 새 번호로 연락 · 상품권 결제 부탁”) + 끝 4자리(입력했을 때만)
- **질문:** “이 문자를 보냈나요?”
- **[버튼]** ① [보낸 적 없어요] (primary) ② [지금 엄마께 전화할게요] ③ [제가 보냈어요]
- “제가 보냈어요”는 맨 아래, 누르면 한 번 더 묻기: “보냈다고 답해도 엄마 화면의 판정은 바뀌지 않아요. 꼭 목소리로 통화해 주세요.” [보냈어요] [취소]
- 응답은 로그인한 요청 대상자만(F5-4). 다른 보호자는 읽기만
- 원문·AI 설명은 보여 주지 않는다(U8)

### C3. 보호자: 응답 후 안내 `/family/req/:id/done`

| 응답 | 문구 | [버튼] |
|---|---|---|
| 보낸 적 없어요 | “엄마 화면에 ‘보낸 적 없음’이 표시됐어요. 엄마께 전화해서 괜찮은지 확인해 주세요.” | ① [엄마께 전화] (등록 번호) |
| 전화할게요 | “지금 엄마께 전화해 주세요. 엄마 화면에는 ‘곧 전화가 온다’고 표시돼요.” | ① [엄마께 전화] |
| 제가 보냈어요 | “엄마께 목소리로 통화해서 직접 설명해 주세요.” | ① [엄마께 전화] |

- 엄마 기기가 감염 의심(E1에서 링크·앱)이면 [엄마께 전화] 대신 “엄마 휴대폰 말고 집 전화나 다른 방법으로 연락해 보세요”(F6-3)
