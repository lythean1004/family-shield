## 1. 반드시 지킬 규칙

- 비밀값·`.env`·서버 `skill.env`를 열지 않는다. 서버 접속·배포·재시작을 하지 않는다(반영은 Claude Code가 운영자 승인 후).
- `private/`, 저장소 루트의 PDF(추적 안 됨), `data/`는 커밋하지 않는다. `git add -A` 금지.
- **기관 공지·보도자료 안에 실제 피싱 주소가 적혀 있어도 그 주소를 열지 않는다.** 문서·카드에는 주소 원문 대신 “모양”(예: `기관명-sms`, `기관명+숫자`)과 출처 URL만 적는다.
- 공식 도메인은 **그 기관의 공식 누리집 안 근거**(하단 운영 주체·저작권, ‘공식 사이트 안내’, 고객센터·인증 안내) 또는 공공기관 자료로만 확인한다. 모델 지식으로 채우지 않는다. 앱 마켓의 개발사 웹사이트 표기는 보조 근거로만.
- 카드 상태 값은 `needs_review` / `source_checked`만. “검수 완료”라고 쓰지 않는다. `terms_checked`는 확인하지 못하면 `false`.
- 이름 규칙은 **테스트를 먼저** 쓴다(실패 확인 → 구현). 짧은 이름(`kb`, `nh`, `ibk`, `bc`, `sc` 등) 단독 규칙은 만들지 않는다.
- 판정 수준(R11 = 위험)은 바꾸지 않는다.
- 커밋 메시지 끝에 작성자 표시. 보고는 쉬운 한국어로, 숫자와 근거를 함께.

## 2. 지난번(요청서 2)과 달라진 점: 사칭 근거를 어디서 찾나

지난번에는 KISA 목록(2023~2024)에서만 이름을 찾아, 은행·카드·금감원·관세청은 근거가 없어 보류됐다. 이번에는 **사칭 근거를 공식 경고문에서 찾는다.**

| 근거 출처(우선순위) | 무엇을 보나 |
|---|---|
| ① 해당 기관 공식 누리집의 ‘사칭 주의’·‘보안 공지’·‘스미싱 주의’ 게시물 | 사칭에 쓰인 문자 내용·가짜 주소의 **모양**, 게시일 |
| ② 금융감독원·경찰청·KISA(보호나라)·과학기술정보통신부의 보도자료·소비자경보 | 기관명 사칭 수법, 가짜 주소 모양 |
| ③ KISA 목록(`data/kisa/*.csv`, 지난번 방식) | 실제 호스트에서 그 모양이 보이는지 건수만 |

①·②에서 가짜 주소의 모양을 확인하지 못하면 **이름 규칙 없이 공식 도메인만 있는 카드**로 만든다(아래 3-3). 이것도 의미가 있다: 공식 도메인은 KISA 목록과 도메인 생성일 조회에서 빠져 진짜 기관 링크가 잘못 걸리지 않는다.

## 3. 요청 작업

### 3-1. 대상 기관 (이 순서로, 기관당 최대 20분, 막히면 기록하고 다음으로)

| 묶음 | 기관 |
|---|---|
| A. 공공·수사 (사칭 빈도 높음) | 금융감독원, 대검찰청(검찰), 경찰청, 대법원(전자소송·법원), 관세청(유니패스), 국민연금공단, 한국도로공사(하이패스·통행료) |
| B. 은행 | KB국민은행, NH농협은행, 신한은행, 우리은행, 하나은행, IBK기업은행, 카카오뱅크, 토스뱅크 |
| C. 카드 | 신한카드, 삼성카드, 현대카드, KB국민카드, 롯데카드, 우리카드, 하나카드, BC카드 |
| D. 생활 서비스 | 쿠팡, 네이버페이, 카카오페이, 당근 |

### 3-2. 기관마다 할 일
1. **공식 도메인 확인**: 대표 도메인과, 문자로 링크가 오는 별도 도메인(모바일·인증·고객센터·청구서)을 근거와 함께 기록(`check_note`에 주소와 본 내용, 날짜).
2. **사칭 근거 찾기**: 2장의 ①→② 순서. 출처 URL·게시일·가짜 주소 모양을 기록. 찾지 못하면 “근거 없음”.
3. **KISA 건수**: 그 모양이 `data/kisa/*.csv` 호스트에서 몇 개인지(원문은 적지 않음).
4. **이름 규칙 제안**(근거가 있을 때만): 지난번 통신사 카드처럼 `label_regex`로 **라벨 전체**를 좁게 맞춘다. 예: `^기관명-(?:sms|text|notice)$`, `^기관명[0-9]+$`. 대표 단어(`bank`, `card`, `pay`) 단독·중간 문자열 일치는 금지.
5. **테스트 먼저**: `.invalid` 합성 주소로 ① 잡혀야 할 모양 ② 공식 도메인과 그 하위 주소 ③ 비슷하지만 정상인 이름(다른 회사·일반 단어)을 넣고, 기존 규칙에서 실패하는 것을 확인한 뒤 구현.

### 3-3. 카드 형식
기존 카드와 같은 필드(`id`, `name`, `official_domains`, `source_url`, `posted_at`, `checked_at`, `scope`, `terms_checked`, `status`, `check_note`) + 이름 규칙(`label_regex` 권장). 이름 규칙이 없으면 규칙 필드를 비우고 `scope`에 “공식 도메인 제외용(사칭 이름 근거 없음)”이라고 적는다. ID는 `EV-DOM-` + 영문 약칭.

### 3-4. 추가 기준 (카드마다)
- `node eval/lookalike-fp.mjs data/tranco/top-1m.csv 1000000` 결과에서 **그 카드로 늘어난 R11이 0개**, 한국 도메인(.kr) **0개**. 1개라도 늘면 규칙을 더 좁히거나 이름 규칙 없이 공식 도메인만 남긴다.
- 전체 시험 통과: `node --test packages/core/test/*.test.js skill/test/*.test.js eval/test/*.test.js web/src/__tests__/*.test.js`
- 공식 도메인을 더했으면 KISA 목록을 다시 만든다:
  `node content/phishing/build-kisa.mjs data/kisa/kisa-2023.csv data/kisa/kisa-2024.csv --allow data/tranco/top-1m.csv`

### 3-5. 하지 않는 것
- 근거 없이 공식 도메인을 추측해서 넣기, 피싱 주소 열기, 기존 13장의 이름 규칙 변경(문제가 보이면 보고만), 판정 수준 변경, 서버 반영.
