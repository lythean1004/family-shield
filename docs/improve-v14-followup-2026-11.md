# 독립 v14 채점 후 기존 신호와 판독 근거 검증

독립 v14 최초 성적은 위험 놓침 29/41(70.7%), 위험 오경보 0/79였다. 이 기록의 검증은 이미 개발에 사용한 이전 판본에서 진행했다. v14 사례와 정답은 추가로 열지 않았다. [v14 최초 채점 기록](improve-v13-to-v14-2026-11.md)

## 현재 신호로 두 목표를 달성할 수 있는지

제품 `5285bca`에서 외부 AI·주소 평판·도메인 생성일 조회를 끄고 각 문장을 다시 판정했다. 규칙 엔진이 받는 신호 집합, 발신 기관과 연결할 수 없는 행동 집합, 부모의 세 응답(현재 통화·이전 통화·가족의 발신 부인)이 같은 입력을 한 묶음으로 만들었다. 기본 계산에서는 응답하지 않은 경우와 명시적으로 ‘아니요’를 선택한 경우도 구분했다. 등록된 번호 끝자리와 수신 번호 끝자리는 원래 입력대로 추출기에 전달했다.

한 묶음에는 규칙이 같은 등급을 줄 수밖에 없다. 그 묶음을 위험으로 정하면 안에 있는 위험 사례를 모두 잡는 동시에 비위험 사례에도 모두 경보를 낸다. 시험 정답을 전부 알고 있다는 가정 아래, 위험 오경보가 10% 미만인 모든 묶음 선택 중 잡을 수 있는 위험 건수의 최댓값을 계산했다. 운영에 적용할 판정표를 만들지는 않았다.

v13의 두 목표를 충족하려면 규칙 기대 기준 놓침이 3건 이하여야 한다. 이미 추출된 신호와 세 응답을 아무리 잘 조합해도 최소 10건이다. 이 표본에서 목표를 충족하려면 적어도 7건을 더 가려낼 정보가 필요하다. 본문에 있는 주체·행동·목적지를 더 정확히 추출하는 방법과, 본문에 빠진 사실을 사용자가 명시적으로 확인하는 방법은 별도로 검증할 사안이다. 표의 하한은 고정 제품의 규칙 입력과 해당 개발 자료에만 적용된다. v14의 개별 실패 원인이나 새 추출기의 성능은 이 계산에서 알 수 없다.

다른 검수자가 실제 파이프라인이 넘긴 인수를 독립 계측해 600/600건의 3등급 판정과 적용 규칙이 재생 결과와 일치함을 확인했다. 원래 부모 입력과 번호 끝자리 전달도 전수 대조했다. 해당 자료에는 등록된 끝자리가 없어 별도 합성 대조 2건으로 일치·불일치 처리를 확인했다. 독립적인 부분집합 탐색과 동적 계획법 계산이 표의 결과에 일치했다. 부모 입력의 미응답을 실제 엔진처럼 ‘아니요’와 합쳐도 규칙 기대 기준의 최소 놓침은 v7~v9에서 20건, v13에서 10건이었다.

## 이전 작성자 6명의 놓침을 문장 근거로 재검토

v7~v9 개발 자료 360건에서 규칙 기준으로 놓친 23건을 모두 골랐다. 작성자마다 이미 잡은 위험 3건과 비위험 대조 5건을 더해 총 71건을 구성했다. 기존 오경보도 대조에 포함했다. 두 AI 검수자는 사례의 선택 이유·기존 등급·코드를 보지 않고 문장과 실제 부모 응답만 읽었다. 표시된 짧은 근거 298개가 본문 또는 입력값과 일치했다. AI 검수자 의견은 사용자 판정이나 정답 변경으로 사용하지 않았다.

놓친 23건 중 두 검수자가 같은 위험 규칙을 지지한 것은 11건, 한 명만 지지한 것은 2건, 두 명 모두 충분하다고 보지 않은 것은 10건이었다. 비위험 대조 30건에서 위험 근거가 충분하다고 본 검수자는 없었다. 같은 규칙을 지지한 사례도 제품에서 그 규칙을 발동할 근거가 실제로 남아 있는지 다시 확인했다.

- 세 작성자의 해외 결제·취소 연락 사례 3건은 실제 번호를 생략해 근거 카드의 공식 번호와 대조할 수 없었다. 관련 회귀 88개가 통과했다.
- 기관 사칭 의심 3건은 실제 목적지를 기록용 주소로 치환했거나 원번호를 생략했다. R147에서 허용한 별도 회신 경로라는 근거도 확인되지 않았다. 복구 비밀값 요구 1건과 부업 서류 묶음 1건도 원래 접수 주소가 남아 있지 않았다.
- 가족 관련 2건은 구매를 부탁한 사람과 구매해야 하는 사람, 또는 ‘막내’가 가족을 지칭하는지에 관해 해석이 갈렸다. 가족·통화·구매 관련 기존 회귀 191개가 통과했다. 물리적 분리 요구 1건도 타인의 도움을 차단하려는 요구인지 일시적인 거리두기인지 구분되지 않았다.
- 비위험 대조의 기존 위험 오경보 1건에는 부모의 ‘이전 통화 있음’ 선택과 링크가 있었지만, 서술에서는 다른 곳에 먼저 걸었던 통화였다. 최초 정답과 R2의 명시적 응답 처리는 그대로 기록했다.

## 문장 단위의 가족 자칭 신호 감독 실험

v2와 v7 두 작성자의 합성 240건에서 작성 단계의 `signals_code`와 `signals_ai`를 대조했다. v2의 코드 신호 열은 120건 모두 비어 있었다. v7 첫 작성자는 두 열이 60건 모두 같았고, 둘째 작성자의 AI 신호 열은 59건이 비어 있었다. 두 열을 합친 가족 신호 34건 중 발신자가 가족을 자처했다는 근거를 확인한 32건과 가족 단서가 없는 선별 음성 172건으로 로컬 문장 분류를 비교했다. 애매한 비표기 사례는 음성으로 간주하지 않았다.

작성자 한 명씩을 통째로 뺀 진단에서 정밀도는 2/5, 재현율은 2/32였다. 방법을 고정한 뒤 과거 v8·v9의 다른 작성자 240건에서 제안 17건이 나왔지만 같은 절의 실제 자칭과 요구를 확인해 제품 규칙에 추가할 수 있던 신호는 0건이었다. 두 판본에는 개별 신호 정답이 없어 관계 정밀도와 재현율을 산출할 수 없다. 이 방법은 제품에 반영하지 않았다.

로컬 실험의 재현 지문은 신호 묶음 집계 `04989a2f2f76adf1a9a7bdc578f75296eec1a2493df1fd36110b79c40f18798e`, 독립 검산 `94ecb6f5b2024e7af6f1ea6adc53e2ed4b2d10bae31700efca0700f0aeb79914`, 문장 분류 집계 `968a6596b16ab875335cedd5ad3c4095acb108155244069594cae8e2fefe7e2d`이다.

## R151 · 기록과 집계에서 누락된 위험 근거 복원

규칙 엔진은 R19까지 사용하지만 서명 결과와 일일 통계는 R13까지만 인정하고 있었다. v2와 개발에 편입된 v7~v13 합성 960건을 원래 부모 응답으로 처리해 코어 결과, 보관용 변환, 서명 후 읽기, DB 행 형식 변환, 메모리 일일 집계를 비교했다. 외부 통신과 운영 DB 접근 없이 진행했다.

수정 전에는 70건에서 적용 규칙이 하나 이상 누락됐고, 그중 위험 판정 41건은 서명 결과에 규칙이 하나도 남지 않았다. 누락된 적용 횟수는 R14 13회, R15 12회, R16 21회, R17 7회, R18 12회, R19 5회였다. 일일 통계에서도 같은 70회가 빠졌다. 두 경로가 코어의 규칙 번호 목록을 공유하도록 수정했다. 새로 만든 보관 결과와 집계에서 960/960건의 등급과 적용 규칙이 코어와 일치했다. 기존 기록에서 이미 지워진 근거는 원래 자료 없이 복구할 수 없다.

기존 제품에서 새 검증 2개가 실패했다. 수정 후 코어 2,847개, 스킬 115개, 웹 177개, 평가 도구 23개 등 3,162개가 통과했다. 개발·회귀 1,700건에서 등급 하락과 새 위험 오경보는 0건이었다. 개발 v2는 놓침 3/46·오경보 0/74, 개발 v13은 13/39·0/81로 동일했다.

### 가족 자칭·연락처 변경·요구를 같은 발신자에게 연결한 실험

별도 작성자가 합성 대조 18건의 기대값을 먼저 확정했다. 가족을 자처한 발신자가 바뀐 자기 연락처에서 실제 행동을 요구한 6건, 연락처만 바뀌었다고 알린 6건, 다른 가족이나 다른 사람의 사건을 포함한 일상 대조 6건이다. 연구 후보는 이 자료를 보지 않고 작성했다. 후보 작성자의 새 시험 6개가 통과했고, 첫 세 양성은 기준 제품에서 실패했다.

동결 후 다른 작성자의 18건에 적용하니 기존 제품과 후보 모두 위험 6건 중 2건을 잡았고 비위험 12건의 위험 오경보는 0건이었다. 연락처 변경만 알린 6건에는 양쪽 모두 `확인필요`를 냈다. 이전 개발 자료 960건에서도 추가 위험 감지와 적용 규칙 차이는 0건이었다. 이 후보는 제품에 넣지 않았다. 대조 자료 SHA-256은 `b7efe6fc7ad10f2c31d6cff3774cbef23fe14a846804bcf0fd9ccd6f9a580ba8`, 동결 후보 패치는 `abb05159af5ff385ae84f14f05751cdc9e6985dd739c9d17b6bb0a8fa63e9ef7`이다.
