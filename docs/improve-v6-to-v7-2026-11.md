# 문자 v6 개발과 독립 v7 검증

[독립 v6 첫 결과](improve-v5-to-v6-2026-11.md)는 고정 후보 `b12a6fd`의 규칙 기준 놓침 26/30, 위험 오경보 0/90이다. 작성자의 사람 기대 초안은 27/30, 1/90이었다. 이후 v6는 개발 자료이며 문장과 두 정답은 동결한다.

## 입력으로 알 수 있는 것

첫 놓침은 가족 4건, 기관 8건, 기타 12건, 경계 입력 2건이다. v6에 기록된 신호와 선택 입력을 규칙 엔진에 직접 대입하면 정답 등급과 120건 모두 일치한다. 실제 판정기가 받는 것은 사용자가 붙여 넣은 문장과 선택 입력이다.

서로 다른 세 문장은 주소를 지운 채 위험 목록 일치, 표시 주소와 실제 목적지 불일치, 최근 도메인 등록을 각각 서술했다. 해당 호스트나 신뢰할 수 있는 조회 결과는 판정기에 전달되지 않았다. 세 문장에 기술된 규칙(R10·R11·R12)의 위험 근거를 그대로 확인하려면 이 입력이 필요하다. 이 셋만 놓쳐도 고정된 v6의 원점수는 3/30(10.0%)이다. 다른 일부 서술에도 주소나 동작의 주체가 생략됐다. 어떤 행도 원래 분모에서 빼지 않는다.

별도 검수자가 최초 놓침 26건을 다시 읽어, 기존 위험 조건을 충족하는 행동이 명확한 사례 10건, 필수 입력 누락 7건, 요청 주체나 실제 행동이 불분명한 사례 9건으로 분류했다. 필수 입력 누락 7건에는 주소·목적지 확인이 필요한 6건과 해외 결제 취소 창구의 번호가 없는 1건이 포함된다. 이 분류는 원래 정답과 분모를 바꾸지 않는다.

서로 다른 다섯 커밋에서 개발판 600건을 다시 채점했다. `c50377d`에서 `b12a6fd`로 가는 동안 v3~v5 합계 놓침은 117/147에서 13/147로 줄었고 v6는 27/30에서 26/30으로 줄었다. 작성자와 함께 위험 유형과 난이도도 달라졌다. 이후 판본에서 처음 얻은 성적은 각 판본을 보완한 뒤의 성적과 따로 남긴다.

## 다음 독립 측정의 조건

기존 개발 v2~v5의 각 규칙 지표는 각각 10% 미만을 유지하고, 기존 830건에서 등급 하락과 새 위험 오경보가 생기는지 확인한다. v6에는 정답에 필요한 정보가 빠진 사례가 있으므로 관측 가능한 요청 유형을 보완하고, 원점수와 남은 이유를 함께 고정한 뒤 v7을 한 번 측정한다. URL이 위험하다는 서술을 실제 조회의 대용으로 사용하면 누구나 검증된 경고 표시를 만들어 낼 수 있다.

v7은 기존 자료나 판정기를 보지 않은 작성자 두 명이 각 60건을 작성한다. 각자 가족 8건·기관 9건·기타 8건·정상 25건·경계 10건을 맡는다. 두 작성자 모두 판정 시 제공되는 입력과 별도 조회가 필요한 조건을 안내받았다. 판정기는 외부 AI나 주소 조회를 호출하지 않는다. 수신자 보고 53건, 문서 조각 36건, 수신 문구 31건을 합쳐 규칙 정답과 사람 기대 초안을 각각 채점한다. 두 오류율 모두 10% 미만이라는 기준은 유지한다.

둘을 합쳐 고정한 SHA-256은 `befadfdcb0478ecaedfe742b673185b42e66786232a1e88100a48a74e371031b`이다. 개발자는 병합 과정에서 지문과 분모, ID·문장 중복 여부만 확인했다. 첫 작성자는 평가 전에 스스로 발견한 한 행의 정답 열 전기 오류를 정정했고, 그 전 파일도 보존했다. 검증본 두 개의 규칙 기준 분모는 각각 20/40과 22/38(위험/기타), 사람 기대 기준은 17/43과 20/40이다. 총 120건에서 규칙 기준 목표를 달성하려면 놓침은 최대 4건, 위험 오경보는 최대 7건이어야 한다.
