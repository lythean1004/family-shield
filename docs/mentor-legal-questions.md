# 멘토 문의: 법률·개인정보 검토 질의서

작성일: 2026-10-28 · 프로젝트: 가족방패 (2026 모두의 AI 실험실, 접수번호 AI-2026-000053)
목적: PRD D26 "개인정보 동의 항목·문구는 법률 검토를 받은 뒤 확정, 그 전에는 실제 사용자 데이터로 운영하지 않음"을 풀기 위한 질의. 중간과제(11/16) 전 1차 답변, 테스트 가족 실사용(5주차, 11/17~) 전 확정이 목표.

> 이 문서는 법적 판단을 하지 않는다. 사실(지금 서비스가 실제로 하는 일)과 질문만 적는다. 판단은 멘토·전문가의 몫이다.

## 0. 먼저 알려 드릴 사실 (질문의 전제)

**서비스:** 부모님이 의심 문자를 카카오톡 채널이나 웹에 붙여 넣으면, 위험 신호를 찾아 위험 / 주의 / 확인 필요로 알려 준다. 가족 사칭이면 사칭당한 가족 본인에게 "진짜 보냈는지" 확인을 요청한다.

**운영자:** 개인(1인). 사업자 등록 없음. 카카오는 일반 채널.

**대상:** 고령 부모님(정보주체)과 그 자녀(보호자). 만 14세 미만 가입 불가(D23).

**데이터 흐름 (2026-10-28 실제 코드 기준)**

| 단계 | 처리 내용 | 어디서 |
|---|---|---|
| ① 입력 | 부모님이 받은 문자 원문(제3자 = 발신자가 쓴 글, 번호·이름·계좌가 들어 있을 수 있음) | 카카오 서버 → 우리 서버, 또는 웹 → 우리 서버 |
| ② 가리기 | 전화번호·계좌·카드·주민번호·이메일·URL·등록된 가족 이름을 `[번호]` 등으로 바꿈. 전화번호는 HMAC(비밀키 해시)만 남김 | 우리 서버(NCP, 한국) 메모리 |
| ③ AI | **가린 문장만** AI로 보냄 | aitestbed.kr 중계 서버(운영사 제공) → Google Gemini / Anthropic Claude (국외) |
| ④ 링크 평판 | 링크의 **도메인 해시 앞 4바이트만** 조회 | Google Safe Browsing (국외) |
| ⑤ 판정 | 규칙 코드가 판정. 원문은 메모리에서 버림 | 우리 서버 |
| ⑥ 저장 | 원문 저장 안 함(로그 포함). 판정·신호·번호 해시·끝 4자리만 **24시간** 뒤 삭제 | 우리 서버 DB(**NCP VM 안, 2026-10-28 결정**) |
| ⑦ 가족 확인 | 자녀에게 정해진 문장 틀 요약 + 사칭된 관계 + (입력 시) 끝 4자리만 보냄 | 우리 서버 → 자녀 앱 |
| ⑧ 알림 | 웹 푸시(내용 없는 알림) | 우리 서버 → Google·Apple 푸시 서버 |

**결정 변경:** DB를 해외 서비스(Supabase)에서 운영사 배정 NCP 서버(한국)로 옮기기로 했다(2026-10-28). Supabase에는 실제 데이터가 한 건도 없다.

## 1. 1순위: 실사용 전에 반드시 답이 필요한 것

### Q1. 문자 원문에 든 "제3자(발신자) 정보"를 처리해도 되는가

부모님이 붙여 넣는 문자에는 발신자 번호·이름·계좌가 들어 있다(사기범이 쓴 번호지만, 진짜 가족·택배사 문자일 수도 있음).

- 정보주체(발신자)의 동의 없이 이 정보를 처리할 법적 근거가 있는가? (예: 개인정보보호법 제15조 제1항 각 호, 특히 정보주체 또는 제3자의 급박한 재산 이익, 정당한 이익)
- 근거가 있다면, 우리가 해야 할 조치는? (예: 처리 최소화, 즉시 삭제 고지)
- 원문을 **저장하지 않고 메모리에서만 처리 후 버리는 것**이 판단에 영향을 주는가?

### Q2. 가린 문장을 국외 AI로 보내는 것: 국외 이전에 해당하는가

- 번호·계좌 등을 가린 문장도 개인정보인가? (가린 뒤에도 "엄마 나 지은이야" 같은 이름·관계·상황이 남는다. 등록된 가족 이름은 가리지만, 모르는 이름은 못 가린다)
- 개인정보라면, 운영사가 제공하는 중계 서버(aitestbed.kr)를 거쳐 Google·Anthropic으로 가는 것은 **국외 이전(제28조의8)**인가, **처리위탁(제26조)**인가?
- 우리가 고지해야 할 항목은? (이전받는 자, 국가, 항목, 보유 기간: 이 중 **AI 제공사의 보관 기간을 우리는 모른다**. 중계 서버의 보관 정책도 아직 확인하지 못했다)
- 운영사(중계 서버 운영자)와 우리의 관계는 어떻게 보는가? 운영사에 무엇을 확인·요청해야 하는가?

### Q3. 카카오톡 채널을 거치는 것

- 부모님이 카카오 채널에 문자를 붙여 넣으면, 원문이 카카오 서버를 먼저 거친다. 이 부분은 **카카오와 부모님 사이의 관계**로 보는가, 우리가 고지해야 하는가?
- 우리 서버는 카카오에서 사용자 식별 키(`botUserKey`)를 받는다. 지금은 **호출 횟수 제한에만 메모리에서 쓰고 저장하지 않는다.** 나중에 계정 연결에 쓰면 무엇이 필요한가?
- 일반 채널(사업자 아님)로 시험 운영할 때, 운영자 표시·개인정보 처리방침 게시 의무는?

### Q4. 부모님 동의 설계: 항목을 몇 개로, 어떻게 나눌까

지금 설계(F1-3)는 부모님 휴대폰에서 화면마다 하나씩 동의 3개를 받는다.

| # | 동의 | 내용 |
|---|---|---|
| ① | 가족 알림 | 위험 판정 시 동의한 가족에게 알림 + "AI 제공사가 가려진 내용을 일정 기간 보관할 수 있음(국외)" 한 줄 |
| ② | 사칭 확인 | 가족 사칭이면 그 가족에게 요약을 보냄 (①에 동의했을 때만) |
| ③ | 확인 기록 | 판정 기록 24시간 보관 |

- 이 구분이 법이 요구하는 "구분 동의"(필수/선택, 제3자 제공, 국외 이전)에 맞는가? 국외 이전 동의를 ①에 한 줄로 넣는 것으로 충분한가, **별도 동의**여야 하는가?
- 자녀(보호자)에게 요약을 보내는 것은 **제3자 제공(제17조)**인가? 가족도 제3자인가?
- 문구 버전을 기록하고 동의를 쌓기만 한다(F1-4). 철회는 [내 설정]에서 언제든 가능. 이 구조로 충분한가? 동의 기록은 탈퇴 후 얼마나 보관해야 하는가?

### Q5. 고령 사용자 동의의 유효성

- 디지털에 서툰 어르신이 화면 동의를 했을 때, 동의가 유효하려면 무엇이 필요한가? (예: 글자 크기, 음성 읽어주기, 보호자 동석)
- **보호자(자녀)가 옆에서 설치를 도와주는 것**이 "대리 동의"로 보일 위험은? (원칙: 부모님 휴대폰에서 부모님이 직접. 대리 동의 불가, PRD 원칙 6)
- 판단 능력이 떨어진 경우(치매 등)에는 어떻게 해야 하는가? 서비스 범위 밖으로 둬도 되는가?

## 2. 2순위: 테스트·평가 데이터

### Q6. 평가용 실제 정상 문자(D2 묶음 35건) 수집

계획: 참여 가족에게 서면 동의를 받고, 이름·번호·계좌·주소·회사명을 바꾼 뒤 사람이 한 번 더 확인. 원본은 보관하지 않음. (현재는 합성 문자로 채워 둠)

- 이 절차가 **가명처리(제28조의2)**로 인정되는가, 아니면 처음부터 "동의 받은 수집"으로 다뤄야 하는가?
- 문자 속 **발신자**(택배사, 병원, 지인)의 정보도 들어 있다. 참여 가족 동의만으로 되는가?
- 비식별 기준은 무엇을 참고하면 되는가? (개인정보보호위원회 가명정보 처리 가이드라인 등)

### Q7. 오판 신고에 가린 문장 저장 (F4-13, D17)

부모님이 별도 동의하면 가린 문장을 90일 보관하고, 사람이 비식별을 확인한 뒤 판정 개선에 쓴다(신청서 내용).

- 프로젝트 원칙("원문을 저장하지 않는다")과 충돌하지 않으려면 어떤 조건이 필요한가?
- 별도 동의 문구에 꼭 들어가야 할 것은?
- 개선에 쓰는 것이 "수집 목적 외 이용"이 되지 않으려면?

### Q8. 어르신 사용성 테스트(부모님 세대 20~30명) 동의

- 사용성 테스트·설문 참여 동의서에 들어가야 할 항목은?
- 화면 녹화·관찰 기록을 남긴다면 추가로 필요한 것은?
- 개인 연구자로서 IRB(연구윤리 심의)가 필요한 수준인가?

## 3. 3순위: 표현·책임·저작권

### Q9. 판별 결과의 책임 범위

- 모든 결과에 "이 결과는 참고용입니다. 의심되면 반드시 직접 공식 번호로 확인하세요."를 붙인다. '안전' 판정은 아예 내지 않는다.
- AI가 위험한 문자를 놓쳐서 부모님이 피해를 입으면 운영자 책임은 어디까지인가? 이 한계 문구로 충분한가? 이용약관에 무엇을 넣어야 하는가?
- 반대로, 정상 문자를 "위험"이라고 해서 생긴 손해(예: 진짜 택배를 못 받음)는?

### Q10. 공공기관 예방 자료의 재사용 (근거 카드)

화면의 공식 번호와 절차는 금융위원회·KISA 등 공개 자료를 **다시 써서**, 출처와 확인일을 함께 보여 준다.

- 금융위원회 자료: 위원회 단독 저작물은 자유 이용, **수익 목적이면 사전 협의**, 공동 저작물은 변경 금지. 공모전 프로토타입은 수익 목적인가? 나중에 사업화하면?
- KISA 보호나라, 피해구제 안내 페이지: 이용조건을 아직 확인하지 못했다. 확인 전에는 화면에 쓰지 않는다(needs_review). 이 방식이 맞는가?
- 평가용 사기 문자는 공개 사례의 **수법만 참고하고 문장은 직접 쓴다.** 이 정도면 저작권 문제가 없는가?

### Q11. URL 평판 조회 (Google Safe Browsing)

- 도메인 해시 앞 4바이트만 보낸다(전체 주소·경로는 보내지 않음). 이것도 개인정보 국외 이전으로 고지해야 하는가?
- Safe Browsing 무료 이용은 **비상업 목적만** 허용된다. 공모전 프로토타입은 괜찮은가? 사업화하면 Web Risk(유료)로 바꿔야 하는가?

## 4. 4순위: 운영·종료

### Q12. 운영 종료(12/11) 후 데이터 처리

운영사 확인(2026-10-26): 12/11 이후 VM은 운영하지 않고, 데이터는 운영자가 직접 내려받아 보관한다.

- 종료 시 사용자 데이터는 **보관이 아니라 파기**해야 하는 것 아닌가? 내려받아도 되는 범위는? (평가 결과·통계는 식별 정보 없음)
- 종료 고지는 언제, 어떻게 해야 하는가?
- 동의 기록은 파기 대상인가, 일정 기간 보관 대상인가?

### Q13. 개인정보 처리방침과 고지

- 1인·비사업자·시험 운영 단계에서도 개인정보 처리방침을 공개해야 하는가? 어디에 게시해야 하는가? (웹 하단, 카카오 채널 프로필)
- 처리방침에 반드시 들어가야 할 항목 중, 우리 구조에서 놓치기 쉬운 것은?
- 개인정보 보호책임자는 운영자 본인으로 해도 되는가?
