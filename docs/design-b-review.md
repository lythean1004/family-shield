기본 화면에 ‘맑은 블루’를 적용했다. 홈에서는 공식 번호와 긴급 도움 버튼이 첫 화면에 함께 보인다. 홈 하단과 설정에서 고대비로 바꿀 수 있고, 처음 방문한 기기에서는 운영체제의 대비 설정을 따른다. 작업 결과는 로컬 브랜치 `main`에 기록했다.

## 모바일 화면 확인

일곱 화면을 기본과 고대비로 각각 캡처했다. 각 화면을 끝까지 검사한 결과 문서 너비는 모두 375px였다. 본문 요소의 가로 넘침, 조작 요소 간 겹침, 높이 48px 미만의 본문 조작 요소는 0건이었다. 표에는 화면별로 직접 확인한 내용을 적었다.

### 확인 중 고친 부분

초기 화면에서는 홈 긴급 버튼의 하단이 기본 875px, 고대비 889px에 있었다. 본문 30px와 제목 42px를 유지하고 카드 안쪽 여백을 조정했다. 예시 화면에서는 선택한 버튼이 화면에서 사라질 때 키보드 초점도 사라졌다. 목록을 열면 제목에, 예시를 고르면 새 예시 문자에 초점을 보내도록 `DemoScreen.jsx`를 함께 수정했다.

두 모드에서 키보드로 홈의 ‘예시 보기’와 ‘딸이라고 하는 문자’를 차례로 열었다. 모드별로 10개 지점에서 3px 초점선과 2px 바깥 여백을 확인했다. 본문 건너뛰기 링크와 결과의 첫 버튼도 고정 메뉴에 가려지지 않았다. 폭 320px에서도 홈과 펼친 메뉴에 가로 넘침이 없었고, Esc로 닫으면 메뉴 버튼으로 초점이 돌아왔다.

## 운영자가 확인할 점

합성 문자로 진행하는 다음 부모님 시연에서 “이미 돈을 보냈다면 어디를 누르시겠어요?”라고 묻고, 도움 없이 홈의 ‘이미 눌렀거나 보냈어요’를 찾는지 관찰할 것을 제안한다. 버튼의 대비와 첫 화면 노출은 확인했다. 색의 강조가 급한 상황에서 충분한지는 실제 참여자의 첫 선택으로 판단할 수 있다.

이번 검증은 로컬 Chrome의 모바일 크기에서 수행했다. 설정 화면은 로그인·푸시 설정 요청에 모의 응답을 사용했다. 실제 휴대폰의 Safari·TalkBack·VoiceOver 사용성과 운영 배포는 별도 확인 대상이다.

코드 주석 한 곳에 ‘카카오톱’ 표기가 있다(`web/src/screens/InputScreen.jsx` 4행). 사용자에게 표시되는 화면 문구에는 영향이 없다.
