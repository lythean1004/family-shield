## 1. 배경과 문제

장인어른의 피해는 **전화를 받은 뒤 문자로 넘어간 단계**에서 커졌다. 경찰청 통계에 따르면 60대 보이스피싱 피해는 2016년 1,261건에서 2025년 5,801건으로 늘었다([농민신문](https://www.nongmin.com/article/20260223500397)). 사기범은 악성 앱으로 빼낸 문자와 연락처를 통화에서 신뢰를 얻는 데 쓴다([안랩](https://www.ahnlab.com/ko/contents/content-center/30254)). 악성 앱은 발신번호를 112처럼 보이게 바꾸거나, 112와 1332로 거는 전화를 가로챌 수도 있다([금융위원회 10계명](https://www.fsc.go.kr/no010101/86250)).

**문제 정의:** 부모님은 의심 문자를 받은 그 순간 혼자 판단해야 한다. 가족이나 믿을 수 있는 공식 번호에 안전하게 바로 닿을 방법이 없다.

**출발점과 사전 준비(신청서):** 장인어른의 피해 이야기를 들은 자녀(초등학생)가 엔트리로 사기방지 메시지 앱을 만들었고, 이 아이디어를 AI 서비스로 완성한다. 신청 전에 공개된 사기 문자 10건을 AI에 넣어 10건 모두 올바르게 분류되는지 시험했고, 장인어른 댁을 포함한 테스트 가족 1곳의 참여 의사를 확인했다. 배우자는 테스트 가족 운영, 자녀는 퀴즈 콘텐츠 제작에 참여한다(팀원 수는 1명).

## 2. 포지셔닝

| 기존 서비스 | 하는 일 | 가족방패와 다른 점 |
|---|---|---|
| KISA 보호나라 | 카카오톡 채널에서 정상/주의/악성 판별 | 판별만 하고 가족과 연결하지 않음 |
| 카카오뱅크, 하나은행 | 판단 근거 설명, 앱 안에서 자동 분석 | 은행 앱 안에서만 쓸 수 있음 |
| 스미싱가드 | 캡처 이미지로 판별 | 판별만 함 |
| SKT 에이닷 가족 케어 | 통화 중 의심되면 보호자 최대 10명에게 알림 | 통화가 대상이고 알림이 한 방향 |

**정의:** 판별기가 아니라 **부모님이 혼자 판단하지 않게 해 주는 가족 확인 서비스**. 통화가 문자로 넘어오는 순간을 통신사와 관계없이 잡는다.

**핵심 차별점**
1. 사칭당한 가족 본인이 “보낸 적 없어요”라고 사실을 확인해 준다.
2. 자녀가 탭 한 번으로 답하면 부모님 화면에 바로 나타난다(양방향).
3. 우리 집 공식 번호 카드와 가족 암호처럼 미리 준비한 확인 수단을 쓴다.

**신청서와의 관계:** 이 PRD는 제출 신청서(docs/application.md)를 기준으로 한다. 신청서와 다르게 정한 것(채널, 단계 이름, 링크 처리 등)은 6장에 이유를 기록했다.

## 3. 목표와 비목표

**목표**
- G1. 입력 → 판정 → 행동 안내 → 가족 확인 → 사후 대응을 한 흐름으로 시연
- G2. 평가 세트 약 200건으로 사기를 놓치는 비율 5% 이하를 목표로 반복 측정하고, 오경보율과 함께 결과 공개
- G3. 테스트 가족 3곳(장인어른 댁 포함)에서 실사용한 뒤 부모님 세대 20~30명으로 넓혀 사용성 확인. 모집이 부족하면 실제 인원과 역할극 결과를 함께 보고
- G4. 12월까지 부모님이 실제로 써 볼 수 있는 프로토타입: 카카오톡 채널 챗봇 + 웹(목표 구현단계는 프로토타입)

**비목표**
- 통화 탐지, 자동 차단
- ‘안전’ 판정
- 피해 감소 효과 주장
- 네이티브 앱
- 카카오 알림톡, 챗봇이 먼저 보내는 메시지(Event API), 비즈니스 채널 전환(멘토링 후 검토)
- 링크에 직접 접속하거나 단축 URL을 펼치는 검사
- 판정을 낮추는 기능
- 원문 저장, 모델 학습
- 사기범과의 다턴 대화 시뮬레이션

## 5. 제품 원칙 (모든 요구사항보다 우선)

1. **‘안전’ 판정을 내지 않는다.** 결과는 위험, 주의, 확인 필요 세 단계뿐이다.
2. **판정은 코드로 된 규칙이 한다.** AI는 신호를 뽑고 설명을 쓰기만 한다. **판정은 올라가기만 하고 내려가지 않는다(예외 없음).**
3. **의심 번호로는 아무것도 보내지 않는다.** 확인은 등록된 가족 계정이나 원래 번호로만 한다.
4. **가족방패는 먼저 링크를 보내지 않는다.** 초대는 QR이나 숫자 코드, 문자·푸시 알림에도 링크 없음. 예외는 부모님이 카카오 채널이나 앱에서 직접 물었을 때의 **답변 안 버튼**뿐이다(D25).
5. **가족 암호는 목소리 통화에서만 쓴다.** 앱에 저장하지 않고, 문자로 보내지 않으며, 입력창에도 쓰지 않는다.
6. **부모님이 주인이다.** 동의는 부모님 휴대폰에서 직접 하고, 언제든 끌 수 있으며, 대리 동의 불가.
7. **원문을 남기지 않는다.** AI에 보내기 전에 마스킹하고, 저장하지 않으며, 로그에도 남기지 않는다. 자녀에게는 정해진 문장 틀로 만든 요약만 보낸다.
8. **근거가 있는 번호만 쓴다.** 공식 번호는 출처와 확인일이 있는 근거 카드에서만 가져온다.
9. **감염됐을 수 있는 휴대폰은 믿지 않는다.** 앱 설치가 의심되면 그 휴대폰으로 신고하거나 확인 전화를 걸게 하지 않는다. 화면에 112라고 떠도 믿지 않도록 안내한다.
10. **링크에 접속하지 않는다.** 링크는 평판 조회 API에 도메인만 묻고, 단축 URL은 펼치지 않는다. 캡처 이미지는 휴대폰 안에서 글자를 인식하고, 인식에 실패했을 때만 부모님이 그 자리에서 동의하면 AI로 보낸다(D24).

| D10 | 캡처 입력 | 신청서의 핵심 기능이라 P1로 포함. 이미지를 AI에 그대로 보내면 번호·계좌를 가릴 수 없으므로 **휴대폰 안에서 글자를 인식(OCR)한 뒤** 텍스트로 기존 흐름(마스킹 → AI)을 탄다. 이미지는 서버로 보내지 않음 |
| D11 | 링크 처리 | 신청서의 URL 평판 조회는 하되 **도메인만** 질의하고 링크에 접속하지 않음. 단축 URL은 펼치려면 접속해야 하고, 접속하면 번호가 살아 있다는 신호가 사기범에게 갈 수 있어 펼치지 않고 `SIG_SHORT_URL`로 처리 |
| D12 | 음성 안내 | 신청서의 음성 읽어주기를 P1로. 브라우저 내장 음성합성(Web Speech API)을 써서 외부로 보내지 않음 |
| D13 | 단계 이름 | 신청서의 ‘위험·주의·특이점 없음’ 대신 ‘위험·주의·확인 필요’. ‘특이점 없음’은 ‘안전’으로 읽힐 수 있음 |
| D14 | 평가 | 신청서대로 약 200건, 놓침률 5% 이하 목표. 공개 사례 수법 기반 합성 문자 + 참여 가족이 동의한 정상 문자(비식별) |
| D15 | 사용자 검증 | 신청서대로 가족 3곳 → 부모님 세대 20~30명. 어르신 테스트는 동의서 절차 후 |
| D16 | 목표 구현단계 | 부모님이 실제로 써 볼 수 있는 서비스를 지향하되 양식상 ‘프로토타입 단계’ 유지 |
| D17 | 오판 신고 | 신청서대로 신고 사례만 별도 동의를 받아 비식별화한 뒤 개선에 사용(F4-13) |
| D18 | 모델 | 신청서의 “지원받는 AI 개발 포인트로 쓸 수 있는 모델” 조건을 먼저 확인하고 D4 비교 진행 |
| D19 | 클라우드 요금제 | Supabase 무료, Vercel 무료(Hobby)로 시작(운영사 문의 결과: 클라우드는 우선 결제 없이). 세션 보안은 앱 코드로, 백업 대신 마이그레이션·근거 카드를 Git으로 관리. Vercel 상업 이용 해석은 OT에서 확인 |
| D20 | 관리자 화면 | 만들지 않음. 운영은 저장소 파일·평가 스크립트·Supabase 관리 화면(2단계 인증)으로(docs/frontend-structure.md) |
| D21 | 부모님 관리 단위 | 부모님 한 분당 그룹 하나. 보호자는 여러 그룹에 속할 수 있음 |
| D22 | 단톡방 동선 | 옵션으로 안내. 보호자 대신 확인(F4-3, P1) 경로 |
| D23 | 연령 | 만 14세 미만 가입 불가. 자녀 퀴즈는 보호자 계정으로 등록 |
| D24 | 캡처 이미지 | 기기 안 글자 인식 우선. 실패 시에만 부모님의 즉시 동의를 받아 멀티모달 AI로 전송(가림 불가 고지, 저장 안 함). 금지사항의 예외이므로 법률 검토 후 구현 |
| D25 | 링크 원칙 | “가족방패는 먼저 링크를 보내지 않는다.” 부모님이 채널·앱에서 직접 물었을 때의 답변 버튼만 허용 |
| D26 | 개인정보 동의 | 동의 항목·문구(카카오 경유, AI 제공사 국외 처리, 이미지 AI 전송, 가족 제공)는 **법률 검토를 받은 뒤 확정**. 검토 전에는 실제 사용자(테스트 가족) 데이터로 운영하지 않음 |
| D27 | 부모님 입구 | **카카오톡 채널 챗봇**(신청서 ①·구현 방법의 “카카오톡만으로”에 맞춤). 판별은 폴백 블록 → 스킬 서버. 설정·음성·캡처·가족용 화면·알림은 웹. 시험 기간은 일반 채널로 운영하고 참여자에게 운영자를 밝힘(경고 배너). 비즈니스 채널 전환·알림톡·Event API는 멘토링 후 |

## 7. 기능 요구사항

P0은 시연에 꼭 필요한 것, P1은 프로토타입 범위, P2는 후속 작업.

### F1. 설정과 동의

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1-1 | 보호자는 본인 번호를 직접 인증하고 가입 | P0 |
| F1-2 | 같이 있을 때 일회용 숫자 코드나 QR로 초대. [임시] 10분 뒤 만료, 시도 횟수 제한 | P0 |
| F1-3 | 부모님이 동의 3개를 화면마다 하나씩 받음: ① 가족 알림 ② 사칭 확인(①에 동의했을 때만) ③ 확인 기록. ① 화면에 “AI 제공사가 가려진 내용을 일정 기간 보관할 수 있음(국외)”을 한 줄로 안내 | P0 |
| F1-4 | 동의 기록은 계속 쌓기만 함(문구 버전 포함). [내 설정]에서 언제든 끌 수 있고, 끌 때 재인증 필요 | P0 |
| F1-5 | 보호자를 우선순위와 함께 추가. 추가되면 부모님에게 알리고, 부모님이 뺄 수 있음 | P1 |
| F1-6 | 부모님과 보호자 모두 시험 알림을 받아야 설정 완료. 아이폰은 홈 화면 추가 필수 | P0 |
| F1-7 | 번호를 바꾸면 재인증하고 가족 모두에게 알림 | P1 |
| F1-8 | 부모님 혼자서도 사용 가능(판별과 번호 카드). 가족 초대는 나중에 | P1 |
| F1-9 | 가입 시 만 14세 이상인지 확인(본인 확인 문구 + 체크). 만 14세 미만은 가입 불가(D23) | P0 |

### F2. 우리 집 공식 번호 카드

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F2-1 | 근거 카드에서 기관을 골라 등록. 출처와 확인일 표시 | P0 |
| F2-2 | 가족이 직접 입력할 수 있음. 직접 입력한 카드는 따로 표시 | P1 |
| F2-3 | 최근 판별한 문자 안에 있던 번호(HMAC으로 비교)는 등록을 막음 | P1 |
| F2-4 | 112는 기본 카드로 미리 넣어 둠 | P0 |
| F2-5 | 근거 카드에 있는 경우에만 “진짜라면 이렇게 와요”를 보여 줌 | P1 |
| F2-6 | 번호 카드는 서비스 워커 캐시에 저장해 로그인 없이, 오프라인에서도 볼 수 있음 | P0 |

### F3. 가족 암호와 가족 약속

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F3-1 | 암호 정하는 방법 안내: 질문과 답 형태, SNS에 나온 적 없는 것, **만나거나 통화할 때 말로** 정하기 | P0 |
| F3-2 | 서버에는 정했는지 여부만 저장. 힌트는 부모님 기기의 로컬 저장소에만(선택) | P0 |
| F3-3 | 가족 약속: ① 새 번호로 연락이 오면 부모님이 **원래 번호로 전화해서** 확인 ② 가족이라며 전화가 오면 **암호를 묻는다** ③ 돈 얘기는 목소리로 통화한 뒤에만 | P0 |
| F3-4 | 암호를 바꿔야 할 때 신고하면 가족 모두에게 알림 | P1 |
| F3-5 | 입력창에 “가족 암호는 여기에 쓰지 마세요” 표시 | P0 |

### F4. 메시지 판별

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F4-1 | 붙여넣기로 입력. 끝 4자리 입력 칸(선택). 입력 길이 상한 [임시] 2,000자 | P0 |
| F4-2 | 안드로이드에서 문자 앱의 공유 버튼으로 넣기(아이폰은 지원 안 됨) | P2 |
| F4-3 | 보호자가 대신 확인. 부모님 그룹에 기록하고 부모님에게 알림 | P1 |
| F4-4 | 전화 받았는지 묻기(아니요 / 예 / 지금 통화 중). ‘통화 중’이면 끊으라는 안내를 가장 먼저 | P0 |
| F4-5 | 처리 순서: 코드로 추출 → 마스킹 → AI → 검증 → 부모님 입력과 합치기 → 규칙 엔진(9장) | P0 |
| F4-6 | AI가 실패하거나 [임시] 8초를 넘기면 고정 안내를 보여 주고, 판정은 코드 값만으로 계속 진행 | P0 |
| F4-7 | 가족 사칭이면 등록된 가족 중 누구인지 부모님이 직접 고름 | P0 |
| F4-8 | 모든 결과 화면에 한계 문구 표시 | P0 |
| F4-9 | 사용자별 판별 호출 한도 [임시] 분당 5회, 하루 50회 | P0 |
| F4-10 | **캡처 입력:** 이미지를 올리면 휴대폰 안에서 글자를 인식해 텍스트로 바꾸고, 부모님이 인식된 글을 확인한 뒤 판별로 넘김. **인식에 실패하면** “사진을 AI로 보내 확인할까요? 사진 속 번호·이름은 가려지지 않아요” 동의를 받은 경우에만 이미지를 멀티모달 AI로 보내고, 이미지는 저장하지 않음(D24, 법률 검토 후 구현) | P1 |
| F4-11 | **URL 평판 조회:** 추출한 링크의 도메인만 평판 조회 API에 질의해 악성이면 `SIG_MALICIOUS_URL`. 링크에 접속하지 않고, 단축 URL은 펼치지 않고 `SIG_SHORT_URL`(D11). 조회 실패 시 판정을 낮추지 않음 | P1 |
| F4-12 | **음성 읽어주기:** 결과와 지금 할 일을 브라우저 내장 음성합성으로 읽어 줌. [읽어주기] 버튼(D12) | P1 |
| F4-13 | **오판 신고:** 결과 화면의 [이 판정이 이상해요]. 기본은 신호·판정·신고 사실만 기록. 부모님이 별도 동의했을 때만 마스킹된 문장을 저장하고, 사람이 비식별 여부를 검토한 뒤 개선에 사용(D17) | P1 |

### F5. 가족 확인

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F5-1 | 사칭 확인: 응답은 “보낸 적 없어요” / “제가 보냈어요” / “지금 엄마께 전화할게요” | P0 |
| F5-2 | 위험 알림: 기관 사칭이나 사후 대응 상황이면 보호자 모두에게 동시에 | P0 |
| F5-3 | “애들한테 물어보기”: 응답은 “누르지 마세요” / “제가 전화할게요” / “잠깐 기다려 주세요” | P1 |
| F5-4 | 응답은 로그인한 앱에서만 받음. 서버가 요청을 받은 본인인지 확인. 문자 답장은 판정에 쓰지 않음 | P0 |
| F5-5 | **“제가 보냈어요”라고 답해도 판정은 그대로.** 부모님 화면에 “목소리로 통화하기 전에는 돈이나 결제를 하지 마세요” | P0 |
| F5-6 | 부모님이 기다리는 화면(P6)은 3초마다 새로 확인 | P0 |
| F5-7 | 응답이 없으면 다음 보호자에게, 다음 보호자도 없으면 “원래 번호로 전화해 보세요” | P1 |
| F5-8 | 자녀 화면에는 받은 시각, 문장 틀로 만든 요약, 사칭된 관계, 끝 4자리(입력했을 때만)만 표시 | P0 |
| F5-9 | 동의가 없으면 확인 요청을 만들지 않음. 서버 함수와 RLS 두 곳에서 막음 | P0 |
| F5-10 | **가족용 화면:** 보호자가 최근 24시간의 확인 요청·알림과 응답 상태를 보고, 번호 카드와 가족 약속을 관리하는 화면(신청서의 ‘가족용 대시보드’) | P1 |

### F6. 사후 대응

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F6-1 | 버튼: 링크를 눌렀어요 / 앱을 깔았어요 / 돈을 보냈어요 / 정보를 알려 줬어요 | P0 |
| F6-2 | 근거 카드에 있는 절차만 한 단계씩 보여 주고, 어디까지 했는지 기록 | P0 |
| F6-3 | ‘앱을 깔았어요’나 ‘링크를 눌렀어요’면 공식 번호 버튼을 숨기고: ① 비행기 모드 ② **다른 휴대폰이나 집 전화** 사용 ③ 초기화나 앱 삭제 ④ **경찰서 직접 방문**. 자녀에게는 “엄마 휴대폰 말고 다른 방법으로 연락해 보세요”, 그 기기는 세션 종료 안내 | P0 |
| F6-4 | 최우선 위험 알림 | P0 |
| F6-5 | needs_review 상태인 근거 카드의 절차는 화면에 보여 주지 않음 | P0 |

### F7. 연습 모드: 오늘의 퀴즈 (신청서 배포 2단계)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F7-1 | 앱 안에서만 연습 문제를 보냄. 실제 문자는 보내지 않고 ‘연습’ 표시를 항상 띄움 | P2 |
| F7-2 | `is_practice` 표시로 실제 알림과 평가 지표에서 제외 | P2 |
| F7-3 | **재연습:** 연습 결과에서 놓친 신호를 짚어 주고, 같은 신호가 담긴 다른 상황 문제를 이어서 냄 | P2 |
| F7-4 | 연습 문제는 검수한 고정 문항만 사용(AI가 즉석 생성하지 않음). 자녀가 만든 퀴즈도 검수 후 등록 | P2 |
| F7-5 | 연습 전후 대응 퀴즈 점수를 비교(신청서 측정 항목) | P2 |

## 8. 화면

| 영역 | 화면 |
|---|---|
| 보호자 설정 | S1 시작과 인증, S2 그룹 만들기와 초대 코드, S3 보호자 추가, S4 번호 카드, S5 암호와 약속, S6 시험 알림 |
| 부모님 설정 | 코드 입력, 동의 ①②③, 동의 확인, 홈 화면 추가, 완료 |
| 부모님 판별 | P1 입력(붙여넣기 또는 캡처, 끝 4자리 포함), P1-a 인식된 글 확인(캡처일 때), P2 전화 받았는지, P2-a 통화 중일 때 끊기 안내, P3 사칭 대상 고르기, P4 결과, P6 기다리기, P7 원래 번호로 통화한 결과, P8 결과, 사후 대응 |
| 보호자 응답 | C1 알림, C2 요약과 응답(3종류), C3 응답 후 안내, C4 가족용 화면(최근 요청·알림, 번호 카드·약속 관리) |
| 공통 | 내 설정, 고정 안내, 오프라인 안내(112와 번호 카드) |

**화면 기준:** 한 화면에 행동 하나, 버튼은 최대 3개, 가장 안전한 버튼을 맨 위에 가장 크게. 문장은 두 줄 이내. 글자·버튼 크기는 Figma 시안 테스트 후 정함.

- P4 위험: “🔴 **위험** — 가족인 척하는 사기에서 자주 보이는 말이 있어요” → [지은이에게 진짜인지 물어보기]
- P8 (보낸 적 없음): “지은이가 보낸 문자가 **아니에요**. 지은이가 직접 확인해 줬어요.”
- P8 (보냈다고 함): “지은이가 **보냈다고 답했어요.** 그래도 위험한 부탁이 있어요. **목소리로 통화하기 전에는** 돈이나 결제를 하지 마세요.”
- 112 안내(모든 위험 화면): “전화 화면에 112라고 떠도 믿지 마세요. 끊고 직접 거세요.”
- 고정 표시(모든 화면 하단): “가족방패는 문자로 링크를 보내지 않아요.”

## 9. 판별 로직

### 9-1. 처리 순서

```
(캡처면 휴대폰 안에서 글자 인식 → 부모님 확인)
원문(메모리에만) → ① 코드로 추출(+ 링크 도메인 평판 조회) → ② 마스킹 → ③ AI(JSON) → ④ 검증
→ ⑤ 신호 합치기 + 부모님 입력 → ⑥ 규칙 엔진 → ⑦ 화면 문구 만들기 → 원문 버림
```

③이나 ④가 실패해도 ①과 부모님 입력만으로 ⑥ 규칙 엔진이 판정한다. 평판 조회가 실패해도 판정을 낮추지 않는다.

### 9-2. 마스킹

| 대상 | 처리 |
|---|---|
| 전화번호 | `[번호]`로 바꾸고, HMAC 값을 24시간 보관 |
| 계좌번호, 카드번호, 주민등록번호, 이메일 | `[계좌]`, `[카드]`, `[주민번호]`, `[이메일]` |
| URL | `[링크]` |
| 등록된 가족 이름 | `[가족이름]`. ‘엄마’, ‘딸’ 같은 관계 표현은 남김 |
| 그 밖의 사람 이름, 주소 | 남을 수 있음. 동의 화면에 이 사실을 알림 |

### 9-3. 신호 목록

코드와 AI는 같은 ID를 쓴다. 판별 기록에는 `signals_code`(코드가 뽑음)와 `signals_ai`(AI가 뽑음)를 따로 남기고, 판정에는 둘의 합집합(`signals_final`)을 쓴다.

| ID | 의미 | 누가 뽑나 |
|---|---|---|
| SIG_LINK | 링크 포함 | 코드 |
| SIG_SHORT_URL | 단축 URL 포함(펼치지 않음) | 코드 |
| SIG_MALICIOUS_URL | 링크 도메인이 평판 조회에서 악성으로 나옴 | 코드(평판 조회) |
| SIG_APP_INSTALL | 앱이나 원격 조종 프로그램 설치 요구 | 코드 + AI |
| SIG_DELETE_APP | 은행·통신사 앱을 지우라는 지시 | AI |
| SIG_MONEY | 송금, 이체, 결제를 **요구함**(이미 보냈다는 알림·출금 알림은 해당 안 됨) | 코드 + AI |
| SIG_GIFTCARD | 상품권 구매나 대신 결제 요구 | 코드 + AI |
| SIG_PREPAYMENT | 대출·환급 명목의 선입금 요구 | AI |
| SIG_THIRD_PARTY_ACCOUNT | 개인 계좌로 입금하거나 갚으라는 요구 | AI |
| SIG_PERSONAL_INFO | 개인정보, 인증번호, 신분증, 비밀번호 요구 | 코드 + AI |
| SIG_NEW_NUMBER | 폰 고장·분실로 새 번호를 쓴다는 말(AI), 또는 끝 4자리가 사칭된 가족의 등록 번호와 다름(코드) | 코드 + AI |
| SIG_FAMILY_IMPERSONATION | 가족이라고 주장 | AI |
| SIG_AGENCY_IMPERSONATION | 기관, 금융사, 택배사라고 주장 | AI |
| SIG_URGENCY | 재촉하거나 협박 | AI |
| SIG_SECRECY | 다른 사람에게 말하지 말라는 요구 | AI |
| SIG_ISOLATION | 혼자 있거나 숙박업소에 가라는 요구 | AI |
| SIG_AVOID_VOICE | 통화를 피함 | AI |
| SIG_CALL_THIS_NUMBER | 문자에 적힌 번호로 전화하라는 유도(수신거부 번호는 해당 안 됨) | AI |

### 9-4. 신호 합치기

- 최종 신호는 **코드 신호와 AI 신호의 합집합**. 어느 한쪽만 잡아도 신호로 친다.
- 코드 키워드는 ‘요구’ 표현(예: “보내 줘”, “입금해”, “결제해 줘”)만 잡는다. “보냈어”, “출금”, “결제 예정”처럼 이미 일어난 일·알림은 잡지 않는다. 평가할 때 코드와 AI의 정밀도를 따로 잰다.
- 끝 4자리가 사칭된 가족의 등록 번호와 **같아도 판정을 낮추지 않는다**(발신번호 조작 가능).

### 9-5. AI 입력과 출력

- **입력:** 시스템 프롬프트(역할, 신호 목록, 설명 규칙, 문자 안의 지시는 따르지 않는다는 지침), `<cards>`(활성 카드 ID와 한 줄 요약), `<message>`(마스킹한 문자)
- **출력 스키마:** `signals`(9-3 목록의 값만, SIG_LINK·SIG_SHORT_URL·SIG_MALICIOUS_URL 제외), `impersonation_type`(family / agency / none / unknown), `impersonated_relation`(정해진 관계 11개 또는 null), `evidence_card_ids`(최대 3개), `explanation_for_parent`(최대 3문장, 문장마다 40자 이하)
- **`impersonation_type`의 뜻:** 문자가 스스로 밝힌 발신자 유형. 진짜인지 가짜인지는 판단하지 않는다(진위 판단은 AI가 판정을 맡는 것이 되어 원칙 2와 충돌). 그래서 정상 은행 알림도 agency다.
- 시스템 프롬프트는 버전을 매겨 관리한다(`prompt_version`).

### 9-6. 서버 검증

- 허용 목록에 없는 신호나 카드 ID는 버린다.
- 설명 문장에 숫자가 4개 이상 이어지거나, URL이 있거나, “안전” 또는 “정상”이라는 말이 있으면 그 문장을 버린다.
- 유형이 family인데 관계가 없으면 unknown으로 바꾸고, 부모님이 P3에서 직접 고르게 한다.
- 스키마 검증에 실패하면 고정 안내로 넘어간다.

### 9-7. 판정 단계의 뜻과 규칙

**판정 단계의 뜻** (평가 세트 정답도 이 정의로 단다)

| 단계 | 뜻 |
|---|---|
| 위험 | 사기의 핵심 요구나 상황이 있다(돈·상품권·개인정보·앱 설치·고립 등 요구, 통화 중, 사칭된 가족의 부인 등) |
| 주의 | 사기 단서는 있지만 핵심 요구가 없거나 일상적인 요구다. 확인을 권한다 |
| 확인 필요 | 위 단서가 없다. 그래도 ‘안전’은 아니며 공식 경로 확인을 안내한다 |

**규칙**

| ID | 조건 | 판정 |
|---|---|---|
| R1 | 지금 통화 중 | 위험(끊기 안내를 가장 먼저) |
| R2 | 전화를 받은 뒤 + (링크 또는 앱 설치 요구) | 위험 |
| R3 | 가족 사칭 + 새 번호 + (돈 또는 상품권 요구) | 위험 |
| R4 | 가족 사칭 + 통화를 피함 | 위험 |
| R5 | 사칭된 가족이 앱에서 “보낸 적 없어요”라고 답함, 또는 P7에서 “안 보냈대요” | 위험 |
| R6 | 기관 사칭 + (링크, 앱 설치, 개인정보 요구, 문자 속 번호로 전화 유도 중 하나) | 위험 |
| R7 | 링크, 돈 요구, 개인정보 요구, 재촉, 비밀 요구 중 하나 / **또는 가족 사칭 + 새 번호** | 주의 |
| R8 | 위 조건에 하나도 해당하지 않음 | 확인 필요 |
| R9 | 고립 요구, 선입금 요구, 개인 계좌 입금 요구, 앱 삭제 지시 중 하나 | 위험 |
| R10 | 링크 도메인이 평판 조회에서 악성(`SIG_MALICIOUS_URL`) | 위험 |

판정은 올라가기만 한다. 판정에 쓰인 규칙은 `fired_rules`에 기록한다.

### 9-8. P7 (원래 번호로 통화한 결과)

원래 번호로 걸면 **진짜 가족**에게 연결되므로, 이 통화에서 확인할 것은 암호가 아니라 “그 문자를 보냈는지”다.
- **문구:** “지은이 **원래 번호**로 전화해서 보냈는지 물어보세요.”
- **버튼:** [안 보냈대요] → R5 위험 / [보냈대요] → 판정 유지 / [통화가 안 돼요] → 판정 유지, 다음 보호자에게 물어보기
- **암호를 쓰는 곳:** 가족이라며 **걸려 온** 전화. 통화 영역이라 서비스가 판정하지 않고 가족 약속과 안내 문구로만 다룬다.
- 부모님 휴대폰에 악성 앱이 깔렸을 수 있으면(F6-3) P7 대신 사후 대응으로 넘어간다.

### 9-9. 자녀에게 보내는 요약 문장 틀

AI가 쓴 설명은 쓰지 않는다. 신호 ID를 정해 둔 문구로 바꿔 “ · ”로 잇는다.

| 신호 | 문구 | 신호 | 문구 |
|---|---|---|---|
| SIG_NEW_NUMBER | 새 번호로 연락 | SIG_LINK | 링크 포함 |
| SIG_GIFTCARD | 상품권 결제 부탁 | SIG_APP_INSTALL | 앱 설치 요구 |
| SIG_MONEY | 송금 요구 | SIG_DELETE_APP | 앱 삭제 지시 |
| SIG_PERSONAL_INFO | 개인정보 요구 | SIG_PREPAYMENT | 선입금 요구 |
| SIG_AGENCY_IMPERSONATION | 기관이라고 함 | SIG_ISOLATION | 혼자 있으라고 함 |
| SIG_URGENCY | 급하게 재촉 | SIG_SECRECY | 비밀로 하라고 함 |
| SIG_AVOID_VOICE | 통화를 피함 | SIG_CALL_THIS_NUMBER | 특정 번호로 전화 유도 |
| SIG_THIRD_PARTY_ACCOUNT | 개인 계좌로 입금 요구 | SIG_FAMILY_IMPERSONATION | (관계로 표시: “딸이라고 함”) |
| SIG_SHORT_URL | 단축 링크 포함 | SIG_MALICIOUS_URL | 위험한 링크로 확인됨 |

### 9-10. 고정 안내와 한계 문구

**고정 안내(AI가 실패했을 때):** 지금은 자세히 살펴보지 못했어요. 링크를 누르지 말고, 답장이나 송금도 잠시 멈춰 주세요. [가족에게 물어보기] [공식 번호로 전화하기]

**한계 문구(모든 결과 화면):** 이 결과는 참고용이에요. 정상 문자를 위험하다고 하거나, 위험한 문자를 놓칠 수도 있어요. 돈이나 개인정보가 걸린 일은 꼭 공식 번호나 가족에게 직접 확인하세요.

## 10. 확인 요청 상태 흐름

```
created → push_sending → sent → viewed → responded → closed
            │ 구독 없음 또는 410 응답            ▲
            └→ sms_sent(링크 없는 문자) ────────┘
sent 상태로 [임시] 2분 동안 열지 않으면 → 문자도 함께 보냄
[임시] 5분 동안 응답이 없으면 → timed_out → 다음 보호자에게 새 요청 / 없으면 unresolved
부모님이 “그만 물어보기” → cancelled
응답이 calling이면 → 다음 보호자에게 넘기지 않음
purge_at이 되면 → 판별 건과 함께 삭제
```

| 요청 종류 | 필요한 동의 | 언제 만드나 |
|---|---|---|
| impersonation | 사칭 확인 | 가족 사칭이고 P3에서 가족을 골랐을 때 |
| alert | 가족 알림 | 판정이 위험이거나 사후 대응 버튼을 눌렀을 때 |
| ask_family | 가족 알림 | 부모님이 직접 “애들한테 물어보기”를 눌렀을 때 |

- **푸시 내용:** 요청 ID와 “확인 요청이 왔어요”라는 문구만. 요약은 넣지 않음.
- **예비 문자:** “[가족방패] 어머니가 의심 문자를 받으셨어요. 홈 화면의 가족방패를 열거나 어머니께 직접 전화하세요.” (링크 없음)
- **예비 문자 한도:** 그룹별 하루 [임시] 10건.

| AI 제공사 보관 | 제공사 정책에 따름 [확인 필요]. 동의 화면에 국외 보관 가능성을 알림 |

### 11-3. 접근 권한 (RLS)

- 모든 테이블 RLS를 켜고 기본 거부에서 시작한다.
- 보호자는 자기에게 온 확인 요청만 볼 수 있다.
- 부모님 판별 기록 전체는 부모님만 볼 수 있다.
- 대리 확인은 활성 상태인 보호자만 할 수 있다.
- 역할별(부모님 / 보호자 / 다른 그룹 사용자 / 비로그인) RLS 테스트를 자동화한다.

### 12-4. 실시간 갱신

Supabase Realtime은 연결이 유지되는 동안 권한 확인 결과를 캐시하므로([Supabase](https://supabase.com/docs/guides/realtime/authorization)) 보호자를 빼도 연결이 끊길 때까지 받을 수 있다. 그래서:
- 부모님 P6 화면은 3초마다 다시 확인(폴링)하고 매번 RLS를 거친다. 요청이 닫히면 멈춘다.
- 자녀는 푸시를 받고 앱을 열 때 내용을 가져온다.

### 12-5. 공개 데모

- 공개 데모는 고정 콘텐츠(미리 정한 예시 문자와 결과)로만 제공한다.
- AI를 호출하는 시연·테스트는 참여 코드와 횟수 제한 뒤에만 연다.

### 13-3. 카카오 챗봇 입구 구조 (D27)

```
부모님 카카오톡 ─ 채널 채팅방 ─ 카카오 오픈빌더(폴백 블록) ─ POST ─▶ 스킬 함수(Supabase Edge Function)
                                                                     │  헤더 토큰 검사
                                                                     ▼
                                                       판별 코어(웹과 공유): 마스킹·코드 신호·AI·검증·규칙
                                                                     │
                                       카카오 응답 JSON(단계·할 일·답변 버튼) ◀┘   원문은 메모리에서만 쓰고 버림
웹(PWA): 부모님 설정·동의, 결과 크게 보기·음성, 캡처 글자 인식, 번호 카드 / 보호자 전체 / 공개 데모(고정 콘텐츠)
```

- **5초 제한**(카카오 고정): 코드 신호·규칙 엔진으로 단계를 먼저 정하고, AI 설명은 약 3초 안에 오면 붙이고 아니면 검수된 고정 문장. 평판 조회도 시간 안에 못 오면 생략(판정은 낮추지 않음). 콜백(최대 1분)은 신청·승인이 필요해 MVP에서는 쓰지 않음.
- **사용자 구분**: 카카오가 주는 봇 전용 사용자 키를 해시해 익명 코드와 연결. 실명·번호는 받지 않음. 가족 연결은 채팅방에 보호자가 만든 숫자 초대 코드를 입력.
- **웹으로 넘어가는 답변 버튼**(D25 허용 범위): “크게 보고 듣기”, “캡처로 확인하기”, “동의하기” 등. 버튼 주소는 짧은 수명의 1회용 토큰.
- **가족 확인의 답 전달**: 챗봇은 먼저 말을 걸 수 없으므로(Event API는 건당 15원·조건 확인 필요), MVP는 부모님이 “답 왔는지 보기” 버튼을 누르는 방식. 보호자 쪽 알림은 웹 푸시·예비 문자.
- **사진 첨부**: 처리하지 않고 고정 안내(“사진 대신 글자를 복사해 붙여 주세요” 또는 “캡처로 확인하기” 버튼).
- **개발·시험**: 판별 코어와 스킬 함수는 로컬에서 테스트로 개발, 카카오 실제 연결 시험은 임시 터널(cloudflared) 사용. 4주차부터 클라우드 Edge Function 주소로 연결.

### 13-2. AI 모델 (D4)

| 후보 | 입력/출력 (100만 토큰당) | 확인 |
|---|---|---|
| Claude Haiku 5.5 (`claude-haiku-5-5`) | $0.10 / $0.50 (프롬프트 10만 토큰 이하) | Anthropic 모델표에서 확인(2026-10-15). 데이터 보관 정책 [확인 필요] |
| Gemini 3.1 Flash-Lite | $0.25 / $1.50 (OpenRouter 기준) | Google 공식 가격·모델 ID·데이터 정책 [확인 필요] |

- **먼저 확인:** 신청서대로 “지원받는 AI 개발 포인트”로 두 모델을 쓸 수 있는지 확인한다. 쓸 수 없는 모델은 후보에서 바꾼다(D18).

- **선정 순서:** 놓침률 → 스키마 통과율 → 일관성 → 응답 시간 → 비용. 놓침률 차이가 크지 않으면 더 싼 모델.
- **운영 원칙:** 모델 ID 고정, `model_id`·`prompt_version` 기록, 구조화 출력을 쓰고 서버에서도 검증. 프로토타입에서는 대체 모델을 두지 않음(AI 실패 시 F4-6 고정 안내).
- **Haiku 5.5 참고:** 생각 모드가 기본으로 켜져 있어 신호 추출은 effort를 `low`로 시작해 측정. 안전 필터 거절 시 자동 대체 모델이 없으므로 거절도 AI 실패로 처리.
- **비용 추정:** 건당 약 $0.0003~0.0008(토큰 수 추정). 비교 실험 전체 1달러 미만.
- Anthropic이 만든 모델(Claude)이 이 문서 작성을 도왔으므로, 순위는 미리 정하지 않고 측정으로 고른다.

- **D2 수집 원칙:** 참여 가족에게 서면 동의를 받고, 이름·번호·계좌·주소·회사명을 바꾼 뒤 사람이 한 번 더 확인한다. 원본은 보관하지 않는다.

- **분리:** 프롬프트를 고칠 때 쓰는 개발용 20건(작성 완료, 사전조사 문서)과 마지막 비교에만 쓰는 평가용 200건을 따로 둔다. 평가용은 개발용 문장을 말만 바꿔 쓰지 않는다.
- **작성 원칙:** 모두 합성 문자. 번호는 010-0000-XXXX, 링크는 .invalid 도메인. 수법은 출처를 참고하되 문장은 직접 쓴다. 오타와 말투 차이는 정상 문자에도 똑같이 넣는다.
- **형식:** JSONL. 필드는 case_id, split, group, technique, basis_card, message_text, fixture, parent_inputs, gold(signals_code, signals_ai, impersonation_type, impersonated_relation, level_human, level_rule), notes, difficulty.
- **정답 수정 기록 (v0.3):**
  - DEV-C02: level_human ‘주의’ → ‘확인 필요’. 링크·요구가 없어 9-7의 ‘주의’ 정의(사기 단서)에 해당하지 않음. 정상 택배 문자 오경보를 줄이기 위함.
  - DEV-C01: 정답 유지(주의), R7에 “가족 사칭 + 새 번호”를 추가해 규칙이 맞춤.
  - DEV-B02: level_rule을 ‘위험’(R6: 기관 사칭 + 문자 속 번호로 전화 유도)으로 확정.
  - 코드 신호 이름을 `SIG_*`로 통일: LINK→SIG_LINK, APP_INSTALL_KW→SIG_APP_INSTALL, MONEY_KW→SIG_MONEY, PERSONAL_INFO_KW→SIG_PERSONAL_INFO, LAST4_MISMATCH→SIG_NEW_NUMBER. PHONE_IN_TEXT는 삭제.
  - 정답을 고칠 때는 반드시 이유를 여기에 남긴다. 규칙에 맞추려고 정답을 바꾸지 않는다.

### 20-2. 사업화와 기관 도입 (신청서 Q5)

- 개인용 기본 기능은 계속 무료.
- 지자체·복지기관에는 교육·보급 패키지(20-1 교육 모드), 금융기관·통신사에는 고객 보호 서비스 제휴를 제안.
- 가족 리포트 같은 부가 기능은 선택형 유료화 검토.
- 비식별화한 신종 수법 통계는 동의받은 범위 안에서 예방 기관과 공유.
