## 평가 기준과 표본

`level_human`은 사례의 의미를 읽고 기대하는 단계이고, `level_rule`은 작성 시점에 부여한 신호로 문서화된 규칙이 낼 것으로 기대한 단계다. 메모와 두 정답은 운영자 확인 전 Codex 초안이다. 아래 예측은 모두 같은 AI 없는 파이프라인의 결과다. 원래 실행기는 `level_rule`로 집계한다. 사람 기대 기준은 ID로 고정 자료와 결과를 연결해 별도로 계산했다.

| 분류 | 건수 | 사람 기대 위험 / 주의 / 확인 필요 | 예측 위험 / 주의 / 확인 필요 |
|---|---:|---|---|
| 기관 사칭·기관 사칭 전화 뒤 문자 | 15 | 15 / 0 / 0 | 1 / 0 / 14 |
| 가족 사칭 | 12 | 12 / 0 / 0 | 1 / 0 / 11 |
| 택배·결제·환급 미끼 | 10 | 5 / 5 / 0 | 0 / 2 / 8 |
| 정상 가족·기관·병원·택배·은행 안내(D1) | 23 | 0 / 2 / 21 | 0 / 1 / 22 |

위험 자료는 행동을 유도하지 않는 사건 접수 요약, 정상 자료는 일상 안내·대화로 작성했다. 실제 연락처·계좌·외부 목적지를 넣지 않았다. 원래 문자를 읽을 때와 서술 시점·말투가 다르고, 집단별 문체 차이도 있다. 이전 작업에서 코드와 D46·D49를 알고 있었으며 이번 1번에서도 규칙을 검토했다. 작성 전 표현 사전을 다시 열어 문장을 고르지 않았지만 완전한 블라인드 자료로 볼 수 없다. 신호의 `signals_code`는 명시적 링크, `signals_ai`는 사람이 본 의미를 기입한 초안이라 일부 공용 신호는 실제 추출 출처와 다를 수 있다. 판정 평가는 단계만 비교했다.

기존 개발 20·평가 200·보강 10·링크 24건과 ID 중복 0건. 기존 검사기의 문자 3-gram 자카드 최대 유사도는 0.174(검사 기준 0.6)였다. 개발 20건과 새 자료 60건을 함께 스키마 검사해 오류 0건이었다.

## 놓친 위험 30건의 주된 이유

한 사례에 원인이 여럿일 수 있어 아래 표에서는 한 번씩만 셌다. 규칙을 이 자료에 맞춰 수정하지 않았다.

| 주된 이유 | 건수 | 근거와 후속 판단 |
|---|---:|---|
| 의미는 있으나 코드 표현이 잡히지 않음 | 26 | 위험에 두 정답이 일치한 사례 중 오답 전부. 코드 신호가 0개였다. 기관 11, 가족 10, 미끼 5건이다. 제3자가 간접적으로 요약한 문장에 직접 요구가 드러나지 않는다. |
| 규칙 조합 없음 | 3 | HO-B-05·B-12·A-08. 사칭 피해와 돈 요구는 기재됐지만 개인 수취인·선입금·압박 등 추가 조건이 불분명하다. 사람 기대는 위험, 규칙 기대는 주의다. |
| 정답 문맥이 애매함 | 1 | HO-B-02. 상담 맥락은 사칭이지만 원래 어떤 요구가 있었는지 모른다. 기관 신호만 추출됐다. 사람 기대 위험과 규칙 기대 확인 필요 중 어떤 기준을 쓸지 운영자 확인 대상이다. |

운영자는 60건의 `notes`와 특히 두 정답이 다른 4건을 검토할 수 있다. 수정 시 현재 판본과 결과를 보존하고 새 판본에서 변경 이유를 기록한다. 실제 문자 판별에 대한 별도 검증은 본문 형식·출처가 다른 독립 자료에서 진행해야 한다.
