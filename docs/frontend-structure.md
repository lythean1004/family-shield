작성일: 2026-10-21 · 기준: docs/prd.md v0.4 · 상태: 구조 결정(D20~D23) 반영, 카카오 챗봇 입구는 검토 중

## 2. 구조: 앱은 하나, 화면은 역할별

```
가족방패 (하나의 PWA, 하나의 주소)
├─ 공개 영역 (로그인 없음)
│   ├─ 소개·설치 안내 (홈 화면 추가 방법, 단톡방 동선 소개)
│   ├─ 공개 데모: 미리 정한 예시 문자와 결과만 (AI 호출 없음)
│   └─ 우리 집 공식 번호 카드·112 (오프라인 캐시)
├─ 부모님 화면 (큰 글씨, 한 화면에 행동 하나)
│   └─ 판별 P1~P8, ‘이미 당했어요’, 번호 카드, 내 설정(동의 끄기)
└─ 보호자 화면 (정보 밀도 높게)
    └─ 확인 요청 응답 C1~C3, 가족용 화면 C4(여러 그룹 전환), 설정 S1~S6

운영자: 앱 밖 (저장소 + 평가 스크립트 + Supabase 관리 화면)
```

- **주소를 하나로 두는 이유:** 아이폰은 홈 화면 앱마다 알림 권한과 로그인 정보를 따로 둔다. 사이트를 나누면 설치·알림 허용·로그인을 두 번 해야 한다. 한 사람이 두 역할을 가질 수도 있다.
- **역할은 사람이 아니라 그룹 안의 관계에 붙는다**(`circle_members.role`). 로그인 뒤 내 그룹의 역할로 첫 화면이 갈리고, 두 역할이 다 있으면 전환 버튼을 둔다.
- **화면 분리는 편의일 뿐 보안이 아니다.** 권한은 RLS가 지키고, 역할별(부모님 / 보호자 / 다른 그룹 / 비로그인) RLS 테스트를 둔다.
- **부모님 화면은 가볍게:** 글자 인식(OCR) 같은 무거운 기능은 필요할 때만 불러온다.
- **기술:** Vite + React + React Router + PWA 플러그인. 서버 렌더링이 필요 없어 Next.js는 쓰지 않는다(호스팅을 옮기기도 쉬움).

## 3. 챌린지와 대응

### 기획
| 빈 곳 | 대응 |
|---|---|
| 의심 문자를 받은 순간 부모님이 앱을 열까(신청서는 ‘설치 없이 카카오톡’) | 시안 테스트에서 가장 먼저 확인. 단톡방 동선(D22), **카카오 채널 챗봇 입구 검토 중**(4장) |
| 보호자가 밤·회의 중이라 응답이 늦음 | 기다리는 화면(P6)에 “기다리는 동안 하지 말 것”을 먼저 표시하는지 시안에서 확인 |
| ‘확인 필요’가 자주 떠서 경고 피로 | 평가에서 ‘확인 필요’ 비율을 함께 보고, 위험과 확실히 다른 무게로 표시 |

### 기술
| 빈 곳 | 대응 |
|---|---|
| 아이폰 홈 화면 앱은 사파리와 로그인 정보를 따로 두는 것으로 알려짐(**미검증**) | 설정 순서를 “홈 화면 추가 → 앱에서 로그인 → 알림 허용”으로 고정, 실기기 시험 항목 |
| 어르신에게 인증번호 입력·잦은 재로그인은 이탈 요인 | **보호자 동반 첫 설치**를 절차로 명시, 그 뒤 긴 세션, 위험 작업만 재인증 |
| 알림 대상은 사람이 아니라 기기 | 시험 알림을 받은 기기만 ‘활성’, 보호자가 자기 기기 목록을 볼 수 있게 |

### 운영
| 빈 곳 | 대응 |
|---|---|
| 탈퇴·삭제 요청 흐름 없음 | 실사용 테스트 전에 정의: 동의 끄기·탈퇴 시 그룹·기록·푸시 구독 삭제 순서 |
| 장애를 알 방법이 없음 | 원문 없이 숫자 지표만: 서버 함수 오류, 푸시 실패율, AI 대체 비율 경고 |
| 비용 폭증·남용 | 긴급 차단 스위치(AI 호출 끄기 → 코드 신호만으로 판정, 예비 문자 끄기) |
| 어르신 지원 창구 | 테스트 기간: 보호자 1차 지원 → 개발자. 테스트 안내문에 명시 |
| 근거 카드 90일 재확인 | 확인일이 지나 화면에서 빠진 카드를 운영자가 알 수 있게 목록화 |

## 4. 검토 중: 카카오 채널 챗봇 입구 (2026-10-21 조사)

사용자 구상: 부모님이 카카오톡 채널 대화방에 의심 문자를 넣으면 챗봇이 답하고, 버튼으로 다른 서비스 화면(가족 확인, 번호 카드, ‘이미 당했어요’)으로 이어진다. 신청서의 원래 구상(“카카오톡 채널 챗봇(또는 웹앱)”)과 같다. 서브에이전트가 카카오 공식 문서를 조사했다.

### 4-1. 확인한 사실

| 항목 | 내용 | 확신도 |
|---|---|---|
| 비용 | 일반 챗봇(오픈빌더)은 무료(2022년 공지 기준) | 중간 |
| 사용 자격 | 카카오비즈니스 가입 후 챗봇 관리자센터 가입. **비즈니스 인증 채널이 꼭 필요한지는 공식 문서에 없음**(카카오 직원 답변: 고객센터에 확인) | 낮음 |
| 동작 방식 | 사용자가 보낸 글(`utterance`)과 봇별 사용자 키(`botUserKey`)를 우리 서버(스킬)로 보내고, 우리는 JSON으로 답한다. 말풍선 최대 3개, 글 1,000자, 버튼(웹링크·전화·메시지 등) | 높음 |
| **응답 제한 5초** | 고정, 바꿀 수 없음. 서버는 공개 주소여야 함 | 높음 |
| AI 챗봇 콜백 | `useCallback:true`로 먼저 “확인 중” 문구를 보내고 1분(문서에 따라 5분) 안에 최종 답. **승인 절차·기간 불명확**(2026-06 포럼에 메뉴가 안 보인다는 미해결 글) | 낮음 |
| 아무 말이나 받기 | 폴백 블록에 스킬을 연결하는 방식(공식 문서 없음, 2차 자료) | 중간 |
| 이미지 | ‘이미지 보안전송’ 플러그인: 사용자 동의 후 최대 10장, 주소 10분 유효. 정해진 흐름(“사진 보내기” 버튼)이 필요 | 중상 |
| 사용자 연결 | 카카오싱크·`appUserId`는 **사업자 비즈 앱 + 비즈니스 채널** 필요. 개인 개발자 비즈 앱은 채널 연결 불가 | 높음 |
| 먼저 보내기 | Event API(비즈 인증 채널·앱, 건당 15원), 알림톡(비즈니스 채널 + 공식 딜러사 + 템플릿 심사, 전화번호 수집 필요) → **보호자 알림은 웹 푸시 유지가 맞음** | 높음 |
| 카카오 로그인 | 개인도 앱 생성 가능, 회원번호만 받으면 심사 불필요. 이름·전화번호는 비즈 앱 심사 | 중간 |
| 타인 사업자 인증 | 신청자가 사업자 본인·직원·대행사인지에 따라 서류(대행사는 위임장·계약서) 요구, 관계없는 사용은 ‘사칭’ 신고 대상. **개인 자격으로 비즈니스 심사를 신청하는 길도 있음** | 중간 |

### 4-2. 원칙과 부딪치는 점

1. **이미지:** 챗봇으로 사진을 받으면 이미지가 카카오와 우리 서버로 간다 → “캡처 이미지를 서버·AI로 보내지 않는다” 금지사항과 충돌.
2. **원문 경로:** 붙여넣은 글은 마스킹 전에 카카오를 거쳐 우리 서버에 온다. 카카오 쪽 대화 보관 정책은 확인 못 함.
3. **링크:** 챗봇 답의 웹링크 버튼은 “가족방패는 링크를 보내지 않는다” 원칙과 부딪친다.
4. **범위:** project.md는 카카오 챗봇을 ‘후속’, ‘결정 전 구현 금지’로 두었다(D9).

### 4-3. 구성안

| 안 | 흐름 | 5초 제한 | 사업자 | 비고 |
|---|---|---|---|---|
| **A. 얇은 챗봇 (규칙 우선)** | 붙여넣기 → 폴백 → Edge Function: 마스킹 → 코드 신호 + (3.5초 안에 끝나면) AI 신호 → 규칙 판정 → 카드로 답 + 버튼(가족에게 물어보기 / 번호 카드 / 이미 당했어요) | AI가 늦으면 코드 신호만으로 답(PRD의 대체 흐름 그대로) | 불필요(일반 채널 사용 가능 여부만 확인) | 가장 현실적. 사진은 “사진으로 확인하기” 버튼 → 웹에서 기기 안 글자 인식 |
| B. 콜백 + AI | A와 같되 바로 “확인 중” → 1분 안에 AI 반영 답 | 해결 | 콜백 승인 필요(불확실) | A를 먼저 만들고 승인되면 올림 |
| C. 웹 중심 + 카톡 안내 | 기존 PWA 유지, 채널은 “확인하러 가기” 버튼만 | 해당 없음 | 불필요 | 원칙을 모두 지킴. 신청서의 ‘설치 없이 카카오톡’은 약해짐 |

**계정 연결(A·B 공통, 사업자 없이):** 봇이 `botUserKey`에 묶인 1회용 토큰을 버튼에 넣고, 부모님이 웹에서 보호자가 준 초대 코드로 가족 그룹에 합류한다. 보호자는 PWA + 웹 푸시.

**Croche:** 앱에 AI 대화 에이전트를 붙이는 SDK로, 대화 기록을 저장하고 Studio 로그로 내용을 볼 수 있으며 Node.js 백엔드가 필요하다. 카카오 연동 기능은 없다. 원문이 오가는 판별에는 쓰지 않고, 개인정보가 없는 대화(오늘의 퀴즈, 교육 모드) 후보로만 둔다.

### 4-4. 카카오톡 자동응답 경로 전수 조사 (서브에이전트 3명, 2026-10-21)

**결론:** 우리 서버가 답을 만들어 카카오톡으로 돌려주는 현실적인 공식 경로는 **오픈빌더 챗봇 하나**다. 비공식 자동화는 모두 쓰지 않는다. 카카오톡 안 AI(카카오툴즈·카나나)에 들어가는 길은 2027년 목표로 둔다.

| 경로 | 사업자 없이 | 우리 서버 호출 | 판단 |
|---|---|---|---|
| **오픈빌더 챗봇(스킬)** | 일반 채널 가능 여부 **불명**(공식 문서 없음, 카카오 직원도 고객센터 문의 안내). **개인 비즈니스 채널**로 가능성 있음 | 가능(5초 제한) | **주 경로** |
| 개인 비즈니스 채널 | 카카오 「개인 비즈니스 채널 자격증 목록 v26.10」에 **정보처리기사·정보처리산업기사·정보관리기술사·정보기기운용기능사** 등이 있어, 관리자 본인이 자격증이 있으면 사업자 없이 심사 신청 가능(심사 1~3영업일, 2차 자료) | – | 지인 사업자보다 먼저 확인 |
| 채널 기본 자동 메시지(채팅 안내·채팅 불가 시간) | 가능 | 불가(고정 문장) | **최소안:** 웹앱 주소를 안내하는 입구 |
| 카나나 상담매니저 | 불가(비즈 인증 채널) | 불가, 카카오 AI가 답을 정함 | 원칙(AI가 판정하지 않음)과 충돌 → 쓰지 않음 |
| 상담톡(공식 딜러) | 불가(비즈 채널 + 딜러 계약 + 위탁 계약) | 딜러마다 다름, 건당 80~100원(채널톡) | 쓰지 않음 |
| 오픈채팅 봇 | 공식 API 없음 | – | 불가 |
| **비공식 자동화**(알림 읽기 앱, PC 매크로, 역설계 클라이언트, 오픈채팅 봇) | – | – | **사용 금지.** 카카오 약관(안내한 방법 외 접근 금지, 역설계 금지, 계정 타인 이용 금지, 운영정책 3-②)에 걸리고, 계정 정지 시 서비스 전체가 멈추며, 원문이 개인 폰·계정에 남음. 역설계 클라이언트로 오픈채팅 개인정보가 유출된 보도 사례(2023) 있음 |
| 사람이 운영하는 개인 계정으로 전달받기 | – | – | 소수 테스트 가족의 사용성 실험으로만(동의서, 원문 즉시 삭제). 공개 경로로는 쓰지 않음 |
| **PlayMCP**(카카오 MCP 플랫폼) | 등록은 누구나 | 가능(AI가 언제 부를지 정함) | 카카오톡 안 ‘카카오툴즈’ 노출은 기업 제휴 또는 공모전 통과작뿐(2026 공모전 마감). 원문이 카카오·외부 AI를 먼저 거쳐 **마스킹 원칙을 지킬 수 없음** → 데모 한정, 2027 공모전 목표 |

**카카오 고객센터에 물어볼 것**
1. 비즈니스 인증이 없는 일반 채널을 챗봇 운영 채널로 연결·배포할 수 있는지, 스킬 서버 호출이 되는지
2. 개인 비즈니스 채널(자격증)에서도 오픈빌더 챗봇·스킬·콜백을 쓸 수 있는지, 공익 사기 예방 서비스가 업종 요건에 맞는지
3. 콜백 사용 신청·승인 조건과 기간, 콜백 주소 유효 시간(1분/5분)
4. 사기 의심 문자 원문을 붙여 넣는 서비스나 답장에 링크 문자열을 다시 보여 주는 것에 운영정책상 제한이 있는지
5. 개인 비즈니스 채널 심사 기간과 반려 시 재신청 절차
6. (멘토·카카오) PlayMCP에서 사기 판별 도구가 허용되는지, 카카오툴즈 호출 시 전달되는 정보 범위, 2027 공모전 계획

**결정 게이트(제안):** 2주차 끝(11/2)까지 일반 채널 스킬 사용 또는 개인 비즈니스 채널 승인 중 하나가 확인되면 A안(얇은 챗봇)을 MVP에 넣는다. 안 되면 C안(웹 중심 + 채널 안내 메시지)으로 가고 멘토와 방향을 확인한다. 지인 사업자는 위임 계약과 개인정보 책임 정리가 된 경우의 마지막 수단.

### 4-5-1. 심층 조사 결과 (2026-10-21, 서브에이전트 2명 + 직접 확인)

**카카오: 일반 채널로 챗봇·스킬 서버 사용 가능성 높음(약 70%), 공식 확답은 없음**
- 공식 튜토리얼의 챗봇–채널 연결 조건은 ① 봇 마스터가 채널 매니저 이상 ② 다른 봇에 연결되지 않음 ③ 채팅방 메뉴·자동응답 끄기뿐이고 비즈니스 인증은 없다. 비즈니스 인증은 디벨로퍼스 앱 연결(개인정보 수신), ‘개발자용 채널 만들기’ 버튼 같은 선택 기능에만 나온다.
- 배포 문서의 “운영·개발 채널이 같은 비즈앱에 연결되어 있는지”는 **배포 실패 시 점검 항목**이다. 카카오 문서 사이트의 질문 기능(AI 요약)도 “필수 선행조건이라고 명시하지 않는다”고 답했다(공식 확인 아님).
- 2026-10 개인 블로그 2곳은 일반 채널로 된다고 하지만 화면 증거는 없다. 데브톡 답변(2026-07)은 고객센터 문의를 안내.
- **중요:** 공식 「채널 만들기」 문서에 따르면 **일반 채널에는 ‘사업자 정보가 확인되지 않은 채널’ 주의 문구가 사용자에게 표시**된다. 사기 예방 서비스가 이 경고를 달고 있으면 신뢰가 떨어지고, “확인되지 않은 채널을 조심하라”는 우리 안내와도 어긋난다.
- 2026-10-20 기사: 사업자등록이 없는 개인도 경력·자격 증빙으로 비즈니스 채널 전환 심사 가능(대상·서류는 기사에 없음).

**네이버 톡톡: 카카오보다 불리**
- **네이버 로그인 필수**(로그인 안 한 모바일 브라우저로 대화 링크를 열면 로그인 화면으로 이동, 직접 확인). 네이버 앱은 필수 아님.
- 계정 유형 4가지(개인/국내사업자/해외사업자/기관·단체), 개인은 공식 문서상 **테스트용**으로 안내. 공개 운영 금지 문구는 없으나 허용도 불명. 개인 계정에서 챗봇 API 사용은 가능성 높음.
- 사용자 사진 수신은 실제로 가능(GitHub 이슈 #71·#189)하지만, 우리 원칙상 이 경로로는 사진을 받지 않는다. 대화는 네이버 이용기록에 포함되며 보관 기간 불명.
- 요청 빈도 제한(3초 30건), 사용자가 24시간 말이 없으면 먼저 보내기를 막는 정책 ‘고려 중’(2025-04 답변).

**직접 시험 결과 (2026-10-21, 사용자 확인)**
- 사업자등록 없이 만든 **일반 채널 + 오픈빌더 챗봇: 채널 연결·배포·카카오톡 대화 모두 작동.** ‘일반 채널로 챗봇 운영 가능’이 확인됐다(가이드: docs/kakao-bot-test-guide.md 파트 A).
- 남은 확인: 스킬 서버 연결(파트 B), 폴백 블록에 스킬 연결 가능 여부, 응답 시간, ‘사업자 정보 미확인’ 경고 화면.
- 시험용 스킬 서버: spikes/kakao-skill-echo/(글자 수만 답하고 원문은 저장·기록 안 함, 헤더 토큰 검사).

**정리한 입구 전략**
1. **시험(지금):** 무료 일반 채널 + 봇을 직접 만들어 운영 채널 연결·배포·스킬 호출을 시험한다(사용자 작업, 1~2시간). 개발·내부 테스트는 일반 채널로 충분하다.
2. **실사용·공개(테스트 가족부터):** ‘사업자 정보 미확인’ 경고를 없애기 위해 **비즈니스 채널로 전환**한다. 방법은 개인 경력·자격 심사(대상 확인 필요) → 안 되면 지인 사업자 위임(위임 계약, 개인정보 책임 정리).
3. 네이버 톡톡은 로그인 필수·테스트 계정 문제로 **보조 후보에서도 우선순위를 낮춘다**. 병행 경로는 ‘공유 → 가족방패’(안드로이드)와 아이폰 단축어.

### 4-6. 결정이 필요한 것
1. 챗봇 입구를 MVP에 넣을지(D9 변경)
2. 사진은 챗봇에서 받지 않고 웹의 기기 안 글자 인식으로 보낼지(금지사항 유지)
3. 링크 원칙을 “사용자가 채널에서 직접 물었을 때의 답변 버튼만 허용”으로 좁힐지
4. 비즈니스 인증 경로: 일반 채널 → 개인 자격 심사 → (마지막) 지인 사업자 + 위임 계약
