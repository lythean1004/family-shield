# 문자 v9 개발과 독립 v10 검증

후보 `f6a1d01`의 [v9 최초 독립 성적](improve-v8-to-v9-2026-11.md)은 규칙 기준 위험 놓침 25/38(65.8%), 위험 오경보 1/82(1.2%)였다. 작성자 기대는 24/34(70.6%)와 4/86(4.7%)였다. 첫 채점 뒤 v9를 개발로 전환했다. 최초 규칙 놓침은 가족 4·기관 11·기타 9·경계 1건이고, 형식별로는 수신 보고 16/26, 문서 조각 9/12건이었다. 직접 수신 문구 31건에는 규칙상 위험 정답이 없었다.

위험 오경보 1건은 이전 전화와 문자가 서로 무관하다고 본문에 쓰여 있지만 부모 입력의 ‘전화 받았어요’가 선택돼 있고, 문자에 완전한 시험 주소가 들어 있었다. 현재 P2 화면은 문자 전에 전화가 왔는지를 묻고, R2는 ‘전화 받은 뒤 + 링크’를 위험으로 정한다. 부모 입력과 문자의 링크를 그대로 규칙에 전달하고 이 사례는 전체 오경보 분모·분자에 남긴다. [제품 규칙표](prd.md)

후속 검증용 v10은 v9 채점 전에 독립 작성자 두 명이 60건씩 봉인했다. 합성 120건의 규칙 기준 분모는 위험 45와 그 외 75건, 작성자 기대 기준은 위험 44와 그 외 76건이다. 두 지표가 각각 10% 미만이려면 규칙 기준 위험 놓침이 최대 4건, 위험 오경보가 최대 7건이어야 한다. 파일의 SHA-256은 `1bc599df40e006033b537c3636f90190b11a6a312c263ac980d8d4b38d929c6f`다.

## 독립 판독과 이전 후보 비교

별도 검수자가 예측과 작성자 정답을 가린 상태에서 v9 본문과 부모 선택 120건을 다시 읽었다. 규칙 위험 38건 중 위험 조건이 명확하다고 본 것은 29건, 해석이 갈린 것은 7건, 필수 근거가 부족한 것은 2건이었다. 작성자 기대 위험 34건에서는 각각 26건, 6건, 2건이었다. 근거가 부족하다고 본 두 건은 취소 연락처의 실제 번호 또는 요구하는 금융 비밀의 종류를 본문에서 확인하기 어려운 경우였다. 재판독 결과를 적용해 정답이나 분모를 바꾼 건수는 0건이다.

서로 다른 네 고정 후보 `ab7fe36`, `e12ee16`, `f6cb27f`, `f6a1d01`을 뒤늦게 같은 v9로 대조했다. 네 후보 모두 놓침 25/38, 오경보 1/82였다. 앞선 판본에서 잡게 된 표현들이 이 판본의 독립 성적을 개선했다는 근거는 없다.

기존 연락 상대에게 조언을 구하지 못하게 하는 조건을 넓힌 별도 후보는 v6 사람 정답에서 놓침 1건을 줄였으나 규칙 정답에서는 새 위험 오경보가 1건 생겨 제외했다. 원래 계약 상대와 다른 수취인을 연결하는 또 다른 후보는 기존 평가 1,070건에서 등급 변화가 없고 별개 발신자 합성 반례도 통과하지 못해 제외했다. 두 후보 모두 개발에 쓰지 않은 v7·v8 240건에서 추가로 잡은 위험은 0건이었다.

가족 발신과 계정 인증 요구를 연결하는 별도 후보도 앞선 개발 자료 1건을 회복했지만 v7·v8 240건에서는 추가 탐지가 없어 제외했다. 이 격리 시험에서 npm이 공개 패키지 레지스트리의 npm 버전 정보를 한 번 조회했다. 평가에는 Node를 직접 실행해 동일한 코어 시험을 다시 확인했다. 레지스트리에 요청한 내용은 공개 패키지 메타데이터였다.

## 독립 채점 직전

83라운드에서 v9의 규칙 정답 위험 놓침은 7/38(18.4%), 위험 오경보는 1/82(1.2%)였다. 작성자 기대 기준으로는 6/34(17.6%)와 4/86(4.7%)였다. 첫 독립 성적은 25/38과 1/82로 보존한다. 공개 평가 200건도 놓침 19/79에서 18/79로 바뀌었고 위험 오경보는 0/121이었다. v2~v8, 기존 dev·supplement, 별도 문체 30건의 등급은 이전 후보와 모두 같았다.

최초 눈가림 재판독과 교차하면 남은 규칙 놓침 7건 중 근거를 명확하다고 봤던 경우가 1/29, 해석이 갈렸던 경우가 5/7, 필수 정보가 부족했던 경우가 1/2였다. 명확하다고 봤던 전기 점검 사례는 평소 쓰던 창구를 떠나 문자 지정 번호로 접수하라는 요구까지는 확인된다. 추가 검수에서 점검 부서가 공공기관이나 카드에 등록된 기관인지 확인할 수 없었다. 수업 접수 중 방문해 보호자 연락처를 적는 경우, 가족이 생년월일이 필요하다고만 한 경우도 위험으로 올리지 않았다. 반대로 ‘계정 복구 문구’의 입력은 제품 문서에서 예로 든 지갑이라는 표현이 빠져 첫 검수에서 근거 부족으로 분류됐다. 구현은 기존 코드와 운영자 승인에 나온 ‘복구 문구’를 기준으로, 실제 미확인 양식에 필수 입력 항목으로 적힌 경우 R16을 적용한다.

나머지 판본의 절대 수치와 최초 결과는 [이전 판본의 개발·독립 기록](improve-v8-to-v9-2026-11.md)과 [최초 독립 성적표](improve-loop-2026-11.md)에 있다. v9의 한 건을 근거가 부족하다고 재판독해도 최초 집계의 분모나 정답은 달라지지 않는다. 이 자료는 합성 사례이며 여러 개발 판본과 독립 판본을 순차적으로 썼으므로 성적은 실제 이용자의 위험 발견 확률을 직접 추정하지 않는다.

v10의 결과를 보기 전에 다음 판본 v11의 원래 정답도 봉인했다. 두 작성자의 합성 120건에서 규칙 기준 위험 38·그 외 82건, 작성자 기대 기준 위험 39·그 외 81건이다. 원본 SHA-256은 `dec90199b5f67cf68af46271b6da3bcb368a5d259944e0af0183aa5c46d05fd1`이다. 독립 검수자의 첫 재판독은 작성자와 117/120건에서 규칙 정답과 작성자 기대가 모두 일치했다. 조정 제안에서 원본과 다른 것은 작성자 기대의 비위험 단계 1건뿐이고, 규칙·작성자 기대의 위험 정답 집합은 각각 원본과 전부 같았다. 검수안은 원본과 별도로 보존했다.

코어 1,853개, 스킬 97개, 웹 174개, 평가기 19개 시험이 통과했다. 로컬 입력 1,190건에서 AI 없음과 가짜 실패 응답의 판정이 일치했고 기존 건강정보 28건은 외부 AI 호출을 생략하는 경로를 유지했다. Tranco 100만에서 사칭 경고 4건과 KISA 일치 0건, 그중 한국 도메인 4,343개에서 두 경고 모두 0건이었다.
