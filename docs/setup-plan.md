## 0. 착수 전에 고쳐야 할 PRD 항목

개발을 시작하기 전에 아래 6가지를 PRD에서 먼저 정리해야 합니다. 그대로 두면 코드나 평가가 엇갈립니다.

| # | 문제 | 제안 |
|---|---|---|
| 1 | 모델 후보 확인. Claude Haiku 5.5(`claude-haiku-5-5`)는 Anthropic 모델표에서 확인됨: 입력 $0.10 / 출력 $0.50 (100만 토큰당, 프롬프트 10만 토큰 이하). GPT-5.4 nano, Gemini 3.1 Flash-Lite의 이름·가격은 대화 중 검색 결과라 공식 페이지 재확인 필요 | PRD 13-2에 확인일을 적고, Gemini 쪽 가격은 OpenRouter가 아닌 Google 공식 가격 페이지 기준으로 다시 확인 |
| 2 | 규칙표와 평가셋 정답이 어긋남. DEV-C01(요구 없는 새 번호 가족 문자)과 DEV-C02(링크 없는 택배 주소 확인)는 정답이 ‘주의’인데 R7 조건(링크·돈·개인정보·재촉·비밀)에 해당하지 않아 규칙상 ‘확인 필요’가 나옴 | R7에 “가족 사칭 + 새 번호”와 “기관 사칭 + 정보 확인 요청”을 넣을지, 정답을 ‘확인 필요’로 고칠지 결정 |
| 3 | 코드 신호 이름이 두 벌(평가셋: `LINK`, `MONEY_KW`… / PRD: `SIG_LINK`…) | 신호 ID를 한 벌로 통일하고, 코드 신호와 AI 신호를 구분하는 접두어만 둠 |
| 4 | `impersonation_type` 정의 미확정 | “문자가 스스로 밝힌 발신자 유형(진위 판단 안 함)”으로 확정하고 시스템 프롬프트도 같은 뜻으로 고침 |
| 5 | “24시간 뒤 삭제” 약속과 Supabase 백업 충돌 가능 | 요금제별 백업 보존 기간을 확인하고, 화면 문구를 “24시간 뒤 서비스에서 삭제(백업은 최대 N일)”처럼 정확히 씀 |
| 6 | 일정 가정 불일치: PRD는 12주·120시간, 수행계획서·CLAUDE.md는 주당 10시간·총 80시간. 프로젝트 마감은 2026-12-18(사용자 확인) | 10/16~12/18 약 9주 × 주 10시간 ≈ 90시간. PRD 120시간과 차이가 있으므로 주당 시간을 늘리거나 P1 일부를 뒤로 미룸 |

## 4. 보안에서 고려할 부분 (매우 중요)

이 서비스는 **사기 피해 직전의 부모님**과 **가족 관계·전화번호**를 다룹니다. 공격자에게도 가치가 큰 서비스라는 전제로 설계합니다. 우선순위 순서입니다.

### 4-1. 메시지 원문과 개인정보 (최우선)

1. **원문은 메모리에서만.** 원문은 Edge Function 요청 본문으로만 받고, DB 컬럼·URL 쿼리·로그(`console.log`)·오류 리포트 어디에도 남기지 않음. 오류 처리 코드가 요청 본문을 통째로 찍지 않는지 리뷰 항목으로 둠.
2. **마스킹 테스트를 먼저.** 번호·계좌·카드·주민번호·이메일·URL·등록 가족 이름 가림을 테스트로 고정. 놓친 형식은 평가셋에 추가.
3. **AI 제공사 보관과 국외 이전.** 마스킹 후에도 이름·주소가 남을 수 있고, 제공사가 30~55일 보관할 수 있음. 해외 제공사로 보내는 것은 **개인정보 국외 이전 고지·동의** 대상일 수 있음 → 동의 화면 문구와 함께 멘토(법률)에게 확인.
4. **번호 HMAC은 가명정보.** HMAC 비밀키는 Secrets에만, 24시간 뒤 판별 건과 함께 삭제. “개인정보를 저장하지 않는다”고 쓰지 않고 “가명처리해 24시간 보관”이라고 정확히 씀.
5. **자녀 요약은 문장 틀로만.** AI가 쓴 문장은 자녀에게 보내지 않음(원문 재전송 방지). 푸시 본문에는 요청 ID와 고정 문구만.
6. **가족 암호는 어디에도 저장하지 않음.** 입력창에 “가족 암호는 여기에 쓰지 마세요” 표시.
7. **캡처 이미지는 휴대폰 밖으로 보내지 않음.** 글자 인식은 기기 안에서 하고, 인식된 글도 마스킹을 거친 뒤에만 AI로 보냄.
8. **링크 평판 조회에는 도메인만.** 경로·쿼리에 개인 토큰이 있을 수 있으므로 전체 URL을 보내지 않고, 링크에 접속하지 않음.
9. **오판 신고 사례 저장은 별도 동의 후, 마스킹된 문장만.** 사람이 비식별 여부를 검토하고, 동의를 끄면 삭제.

### 4-2. 접근 권한 (Supabase RLS)

1. 모든 테이블 RLS 켬, **기본 거부**에서 시작해 필요한 정책만 추가.
2. 역할별 RLS 테스트를 자동화: 부모님 / 보호자 A / 다른 그룹 사용자 / 비로그인 각각이 볼 수 있는 행을 검사.
3. 보호자는 자기에게 온 확인 요청만, 판별 기록 전체는 부모님만.
4. 동의가 없으면 확인 요청 생성 불가: **Edge Function과 RLS 두 곳**에서 막음(F5-9).
5. 뷰(view)를 만들면 `security_invoker` 설정 확인. 스토리지 버킷은 쓰지 않거나 비공개.
6. Realtime은 권한 캐시 문제로 쓰지 않고 폴링(PRD 12-4 결정 유지).

### 4-3. 인증과 계정 탈취

1. **악성 앱이 인증 문자를 빼갈 수 있음**: 새 기기 로그인 시 가족 알림, 사용자당 세션 하나, 위험 작업(동의 변경·보호자 추가/삭제·번호 카드 수정·번호 변경)은 재인증 + 가족 알림.
2. 보호자 추가는 **만나서 일회용 코드/QR로만**. 코드는 해시 저장, 10분 만료, 시도 횟수 제한.
3. 동의는 부모님 휴대폰에서 본인이 직접. 대리 동의 경로가 코드에 없어야 함.
4. 감염 의심(앱 설치) 시 그 기기 세션 종료 안내.

### 4-4. 비용 남용과 서비스 악용

1. **인증 문자 남용(SMS pumping)**: CAPTCHA, 번호·IP별 발송 한도, 일일 총 발송 상한, 결제 한도 알림.
2. **판별 API 남용(LLM 비용)**: 로그인 사용자만, 사용자별 분당·일일 호출 한도, 입력 길이 상한.
3. **예비 문자 남용**: 그룹별 하루 발송 상한.
4. **가족방패 사칭**: “가족방패는 링크를 보내지 않아요”를 화면에 고정 표시, 초대에 링크 사용 금지, 예비 문자에도 링크 없음.
5. LLM·문자 제공사 계정에 **월 사용 한도와 알림** 설정.

### 4-5. AI 관련

1. **프롬프트 주입**: 문자 안의 지시를 따르지 않도록 시스템 프롬프트에 명시하되, 그것에 기대지 않음. 출력은 허용 목록·스키마로만 받고, 판정은 규칙 엔진이 함. 코드 신호와 합집합이라 AI가 신호를 지워도 판정이 내려가지 않음(DEV-E01).
2. 모델에 도구·웹 접근을 주지 않음. 출력은 화면 문구로만 쓰고 HTML로 렌더링하지 않음.
3. 설명 문장 검증: “안전/정상” 표현, URL, 숫자 4개 이상 연속 문장 제거.
4. 모델 ID 고정, `model_id`·`prompt_version` 기록.

### 4-6. 웹(PWA) 보안

1. 엄격한 CSP. 외부 스크립트·광고·분석 도구 넣지 않음(토큰 탈취 방지).
2. 사용자 입력·AI 출력을 HTML로 넣지 않음(`dangerouslySetInnerHTML` 금지).
3. 서비스 워커는 정적 파일과 공식 번호 카드만 캐시. **API 응답(판별 결과·요약)은 캐시하지 않음.**
4. CORS는 서비스 도메인만 허용. Edge Function은 JWT 검증 켬.
5. 웹 푸시 구독 정보는 사용자별로 저장하고 410 응답 시 폐기.

### 4-7. 개발 도구와 배포 과정

1. 비밀값은 `.env`와 각 서비스의 Secrets에만 두고, 커밋·채팅·이슈에 붙여 넣지 않음. 노출되면 즉시 교체.
2. Claude Code에는 dev 환경만. prod 키·DB 비밀번호를 주지 않음.
3. Figma Make·Vercel 프리뷰에 실제 데이터 금지.
4. 평가셋은 합성 데이터만(번호 `010-0000-XXXX`, 링크 `.invalid`). 실제 피해 문자를 받게 되면 저장소에 넣지 않음.
5. 의존성은 최소로, 설치 전 패키지 이름 확인(유사 이름 패키지 주의).

### 4-8. 법·운영 (멘토링에서 확인)

- HMAC 번호의 가명정보 여부와 보관 기간
