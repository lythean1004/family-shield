# Codex 요청서: 문자 모양 평가 세트 (놓침·오경보 재측정용)

작성일: 2026-11-27 · 작성: Claude Code · 요청자: 프로젝트 운영자
시작 커밋: `39eef6d` 이후 최신 `main`

## 왜 다시 만드나

`eval/holdout-2026-11*.jsonl`(60건)은 “상담 접수표에 … 적혔다”처럼 **제3자가 사건을 요약한 문장**이다. 부모님이 실제로 붙여 넣는 것은 받은 문자 그 자체라서, 이 세트로는 판별 성능을 잴 수 없다(위험 26건이 코드 신호 0개). 이 세트는 지우지 말고 보존만 한다. 수치는 보고에 쓰지 않는다.

이번에는 **부모님 휴대폰에 그대로 도착한 문자·카톡 본문 모양**으로 새로 만든다. 위험 문자와 정상 문자의 문체(길이·말투·형식)를 맞춰서 놓침과 오경보를 같은 조건에서 잰다.

## 0. 지킬 것 (`docs/codex-request-next-dev.md` 0절 그대로)

- 서버 접속·배포·재시작 금지. 로컬과 GitHub까지만.
- `.env`·`private/`·`data/` 원본은 읽거나 커밋하지 않는다.
- **모든 문장은 지어낸 것이다.** 실제 피싱 문자 원문을 복사하지 않는다. 실명·실제 번호·실제 계좌·실제 피싱 주소를 쓰지 않는다.
  - 전화: `010-0000-0000` 같은 0으로 채운 값, 또는 `02-000-0000`.
  - 계좌: `000-0000-0000-00`.
  - 링크: 사기 쪽은 `.invalid`·`.xyz`·`.top` 같은 지어낸 도메인(실제로 있는지 확인하지 말 것, 접속 금지). 정상 쪽은 근거 카드(`content/evidence/`)의 공식 호스트만.
- 사실(기관 이름·공식 번호·공식 주소)은 근거 카드에서만 가져온다.
- ‘안전’ 정답을 만들지 않는다. 정답은 위험 / 주의 / 확인필요뿐이다.
- 규칙·코드 표현은 이 작업에서 고치지 않는다.

## 1. 독립성 (가장 중요)

- **문장을 다 쓰고 커밋한 뒤에** 코드를 본다. 쓰는 동안 `packages/core/src/extract.js`, `rule-engine.js`, `eval/test.jsonl`, `eval/supplement.jsonl`, `eval/holdout-*`를 열지 않는다.
- 참고는 공개된 예방 자료의 **수법 설명**만 한다(근거 카드의 `basis_card`, 금융감독원·경찰청·KISA 안내의 수법 분류). 문장은 직접 지어 쓴다.
- 정답(`gold`)은 문장을 쓸 때 함께 적고 같은 커밋에 넣는다. 결과를 보고 정답을 바꾸면 안 된다. 바꿔야 하면 새 판본 파일(`-v2`)을 만들고 이유를 남긴다.

## 2. 만들 것: `eval/messages-2026-11.jsonl` (120건)

스키마는 `eval/test.jsonl`과 같다(PRD 15장). `node eval/validate.mjs`로 검사한다. `case_id`는 `MSG-<그룹><번호>`.

| 그룹 | 건수 | 내용 |
|---|---:|---|
| 위험 · 기관 사칭 | 18 | 검찰·경찰·법원 출석·금감원·국세청 환급·건강보험 환급. 앱 설치, 원격 지원, 개인정보, ‘안전 계좌’ 이체, 이 번호로 전화 |
| 위험 · 가족·지인 사칭 | 16 | “엄마 나 폰 고장”, 새 번호, 상품권, 대신 결제, 병원비·합의금, “전화는 안 돼” |
| 위험·주의 · 미끼 | 16 | 택배 주소 오류, 카드 결제 승인, 과태료·범칙금, 부고·청첩장 링크, 정부 지원금, 투자·고수익. 링크 포함 |
| 정상 · 기관·회사 | 20 | 진짜 국세청·건강보험·은행·카드·택배·통신사 안내. 공식 주소나 대표번호만 있음. 납부·결제·만기 같은 돈 이야기가 들어간 것도 섞는다 |
| 정상 · 가족·지인 | 20 | 진짜 자녀·손주의 부탁과 안부. 돈 부탁(“엄마 이번 달 월세 좀…”), 링크 공유(사진·지도), “나중에 전화할게”, 급한 말투 |
| 정상 · 생활 | 10 | 병원 예약, 약국, 동창 모임, 아파트 관리비, 쇼핑 배송 완료 |
| 경계 | 20 | 사람도 헷갈리는 문자. 공식 주소인데 재촉, 가족인데 새 번호지만 돈 요구 없음, 단축 링크가 있는 정상 안내 등 |

- 위험 50 · 정상 50 · 경계 20 정도가 되게 한다. 경계 그룹의 정답은 `notes`에 이유를 한 줄 쓴다.

**문장 모양**
- 실제 문자처럼 `[Web발신]`, `[국외발신]`, 기관 머리말, 줄바꿈, 이모티콘, 띄어쓰기 없음, 맞춤법 틀림, 사투리, 짧은 카톡 말투(“엄마 나야ㅠ”)를 섞는다.
- 위험과 정상의 길이 분포를 비슷하게 맞춘다(둘 다 짧은 것·긴 것이 고르게).
- 같은 수법이라도 표현을 바꾼다. 한 표현을 세 번 넘게 쓰지 않는다.
- 부모님이 함께 입력하는 정보(`parent_inputs`: 통화 중, 전에 통화함, 발신 번호 끝 4자리)는 20건 정도에만 넣는다.

**정답 두 가지**
- `level_human`: 부모님에게 어떤 단계가 맞는지 사람 기준.
- `level_rule`: 지금 규칙(`docs/prd.md` 규칙표, `18e64c0`에서 코드에 맞춤)대로라면 나올 단계. 규칙표만 보고 적는다(코드는 보지 않는다).
- 두 값이 다르면 `notes`에 이유를 쓴다. 이 차이가 **운영자가 규칙을 바꿀지 판단할 자료**다.

## 3. 측정 (로컬, AI 없이)

```powershell

```

## 4. 결과물

`docs/eval-messages-2026-11.md`에 다음을 쓴다.

1. 그룹별 건수, 길이 분포(위험·정상 각각 중앙값)
2. 규칙만 결과: 놓침(사람 기준 위험 중 위험 아님), 오경보(사람 기준 위험 아닌 것 중 위험), 정상 중 ‘주의’ 비율, 혼동표
3. 놓친 위험 사례의 원인 분류: 코드 표현 없음 / 규칙 조합 없음 / AI가 있어야 잡힘(기대) / 정답 애매. **표현 추가나 규칙 수정은 하지 않고 제안만** 쓴다.
4. `level_human`과 `level_rule`이 다른 사례 목록(운영자 결정용)
5. 서버 AI 평가 명령

커밋은 ① 문장+정답 ② 결과+보고서로 나눈다. `packages/core`·`skill`·`web`의 `npm test`, `node --test eval/test/*.test.js`가 통과하는지 확인한다.

## 5. 운영자 결정 반영 (2026-11-27)

- **정답 검토:** 운영자 대신 Claude Code가 120건을 먼저 모두 본다. 정답이 애매하거나 `level_human`·`level_rule`이 다른 건만 운영자에게 묻는다. 그러니 `notes`를 성실하게 쓴다.
- **지난 60건(`holdout-2026-11*.jsonl`):** 보관만 한다. 정답이 갈린 4건(HO-B-02·B-05·B-12·A-08)은 확인하지 않는다.
- **D50(Claude Code가 구현):** 수사기관 사칭 + ‘안전계좌’ 이체 요구는 코드만으로 위험이다. 이 규칙을 알고 문장을 쓰면 독립성이 깨지니, 2절 문장은 D50을 의식하지 말고 평소대로 쓴다.

지킬 것:
- 표에 적힌 대표 호스트 **하나만**, www까지 정확히 같은 것만 넣는다. 등록 도메인 전체나 하위 주소는 넣지 않는다.
- **iM뱅크·제주은행**은 이름이 바뀌었으니 지금 쓰는 대표 주소를 은행 공식 누리집 안의 자료로 다시 확인한다. 확인이 안 되면 넣지 말고 보고한다.
- 카드마다 출처 URL·확인일을 남기고 `terms_checked`는 그대로 false로 둔다. “검수 완료” 표시는 하지 않는다.
- 시험을 먼저 쓴다. 각 대표 주소만 있으면 확인 필요 + 공식 안내, 미등록 주소가 섞이면 공식 예외가 꺼지는지 본다.
- Tranco 100만 사칭 경고 수(4건)와 KISA 위험 호스트 일치(0건)가 그대로인지 확인한다.
- 이 작업은 2절 문장을 커밋한 **뒤에** 한다(정상 문장에 넣을 공식 주소는 이 표에서 골라도 된다).
